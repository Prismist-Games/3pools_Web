# 策略抽奖:AP + 位置系统设计

> 最后更新:2026-04-23
> 状态:待实现(原型阶段最小方案)
> 目标:替换当前"抽数 + 道具栏"机制,将抽取统一到 AP 经济中,并引入"位置"作为本店独立的紧迫度

---

## 1. 背景

### 问题

当前版本的核心抽取循环有两个结构性问题:

1. **抽数抽象化**:每家店固定 3 次抽数,没有叙事支撑。"为什么只抽 3 次"没有合理回答,玩家的"抢菜"体验和机制脱节
2. **道具独立于抽取**:5 个道具(透视 / 换位 / 驱散 / 炸墙 / 清库换抽)和抽取是平行系统,没有统一的成本经济,玩家决策维度单薄

### 目标

让**每个动作都有策略权衡**,并让游戏主题(抢菜)与机制闭环——玩家在摊位前是在"抢位置 + 抢货",被挤出是游戏的自然终结。

---

## 2. 核心机制

### 两个资源

| 资源 | 范围 | 回满时机 | 职责 |
|---|---|---|---|
| **AP(体力)** | 0-3 | 每回合开始重置为 3 | "这回合我还能做多少事" |
| **位置** | 1-5(小 = 深入摊位,大 = 靠近边缘) | 每进店重置为 5 | "在这家店还能待多久" |

### 位置规则

- **起始位置 = 5**(玩家刚到摊位的边缘,还没挤进人群)
- **位置 5 时再被推挤 → 强制离店**(本次抽奖结束,进入 between_turns)
- **位置下限 1**(最深入,无法再拉近)
- **推挤来源(仅 2 条):**
  1. 回合结束时:位置 +1
  2. 抽到抢菜人格时:位置 +1(**保留现有 HP 扣血逻辑**,叠加)

### 回合结构

没有新增仪式事件。每回合:
- 开始:AP 重置为 3
- 过程:玩家用 AP 做动作(顺序自由)
- 结束:玩家主动结束或 AP 用完后结束 → 位置 +1 → 若需要则触发离店 → 否则进下一回合

---

## 3. 动作菜单(固定 6 个)

这是玩家在摊位里的**全部**可选动作。**全部始终可用**(不从掉落获取、不从牌堆抽取、不需要解锁)。

| # | id | 中文名 | AP | 位置变化 | 效果 |
|---|---|---|---|---|---|
| 1 | `draw` | **抽取** | 1 | 0 | 选一行或一列,行/列内随机命中 1 格,获取该格内容 |
| 2 | `swap` | **换位** | 1 | 0 | 任选墙上 2 格,交换位置(不改内容) |
| 3 | `disperse` | **驱散** | 2 | 0 | 任选 1 格,变为空格(后续抽取命中 = 无事) |
| 4 | `bomb` | **炸墙** | 3 | 0 | 选 3×3 区域中心,区域内所有格子重新 roll 生成 |
| 5 | `push_in` | **冲进去** | 2 | **-2** | 位置减 2(下限 1) |
| 6 | `haggle` | **讨价还价** | 0 | **-1** | 丢 1 个菜篮食材 → 位置 -1(需菜篮有食材,下限 1) |

### 按钮禁用规则

- AP 不够 → 灰色不可点
- 讨价还价时菜篮为空 → 灰色不可点
- 冲进去在位置 1 → 灰色不可点(已最深入)
- 炸墙选择中心时,若 3×3 会越墙边界 → 中心候选自动钳制到不越界的位置

### 目标选择交互

- **抽取**:按下后进入"选行/列"模式,hover 行列高亮,点击确认
- **换位**:按下后进入"选 2 格"模式,连点 2 个格子
- **驱散**:按下后进入"选 1 格"模式,点击 1 个格子
- **炸墙**:按下后进入"选中心"模式,点击 1 个格子作为 3×3 中心
- **冲进去**:按下立即生效
- **讨价还价**:按下后进入"选菜篮食材"模式,点击菜篮 1 格确认
- 所有目标选择模式下可按 ESC 或再次点击该动作按钮取消

## 4. 设计原则(强约束)

### 不要做(重要)

- ❌ **不加透视类信息动作**(揭示品质、预告墙、预告订单、揭示人挤人光标落点等)
- ❌ **不加缩小抽取概率的动作**(必中某格、过滤到仅某品质、占位、权重倾斜等)
- ❌ **不保留现有道具掉落机制**(墙上的 tool 格、进店发道具、离店 +1 道具)
- ❌ **不加位置门禁**(所有 6 个动作在任何位置都可用)
- ❌ **不加按位置变效**(同动作在不同位置效果相同)

### 要做

- ✅ 动作只能做两件事:**改变墙面状态** 或 **操作资源(位置 / AP / 菜篮)**
- ✅ 抽取必须保持真正随机——玩家改变"池子里是什么",不改变"抽到什么"
- ✅ 6 动作菜单是固定菜单,所有玩家从第一秒就能看到全部选项

以上"不要做"的部分是**有意为之**——它们是未来潜在扩展方向,但**不是第一版原型范围**。第一版先跑通 6 个动作的基础经济,再谈扩展。

## 5. 实现路径

### 5.1 数据层 — 配置新增

在 `src/data/v2Config.js`(或 `runtimeConfig.js` 如果希望可调)添加:

```js
export const POSITION_CONFIG = {
    initial: 5,
    min: 1,
    max: 5,
    pushOnTurnEnd: 1,
    pushOnDoomHit: 1,
};

export const ACTION_CONFIG = {
    draw:     { id: 'draw',     ap: 1, posDelta: 0 },
    swap:     { id: 'swap',     ap: 1, posDelta: 0 },
    disperse: { id: 'disperse', ap: 2, posDelta: 0 },
    bomb:     { id: 'bomb',     ap: 3, posDelta: 0 },
    push_in:  { id: 'push_in',  ap: 2, posDelta: -2 },
    haggle:   { id: 'haggle',   ap: 0, posDelta: -1, requiresBasketItem: true },
};

// 修改现有的 TURN_CONFIG
export const TURN_CONFIG = {
    apPerTurn: 3,       // 取代 goldPerTurn
    // drawCost 移除
    // goldPerTurn 移除
};
```

### 5.2 状态层 — `useGameLogic.js`

**新增 state:**
- `position`(数字,每进店重置为 `POSITION_CONFIG.initial`)
- `ap`(数字,每回合重置为 `TURN_CONFIG.apPerTurn`)

**废除 state / 逻辑:**
- `gold` / `drawsRemaining`(被 `ap` 替代)
- `tools` / `toolInventory` / 道具掉落相关逻辑

**新增函数:**
- `handleAction(actionId, params)`:通用动作分发器
  - 检查 AP 是否足够
  - 检查前置条件(冲进去的位置、讨价还价的菜篮)
  - 扣 AP、改位置
  - 执行具体效果(抽取 / 换位 / 驱散 / 炸墙)
- `endTurn()`:
  - 位置 +1
  - 若位置越过 max(原本 = 5 时触发) → 调用 `triggerForcedExit('crowd')`
  - 否则 `ap` 重置为 3
- `onDoomHit()`(在现有 HP 扣血逻辑上):
  - 位置 +1
  - 若位置越过 max → 调用 `triggerForcedExit('crowd')`
- `triggerForcedExit(reason)`:统一的离店入口
  - reason ∈ `'crowd' | 'hp' | 'voluntary'`
  - 走现有的 between_turns 流程

**进店 / 离店:**
- 进店(`wall_reveal` → `drawing`):`position = 5`, `ap = 3`
- 离店:保持现有流程,不动

### 5.3 UI 层

**MarketPanel / 抽取面板 header 新增显示:**
- **位置条**:5 段可视(比如 5 个分段条或 5 个图标槽),当前位置高亮
  - 标注:"距被挤出 {5 - position + 1} 步"(位置 5 时显示"下一次推挤就被挤出")
- **AP 计数器**:3 段(3 颗体力图标)。已用的变灰或消失

**删除显示:**
- 抽数计数(被 AP 替代)
- 道具栏 / 道具槽位 / 道具 tooltip

**动作菜单(新)—— 替代现有道具栏位置:**
- 6 个按钮横排或 2×3 网格
- 每个按钮显示:
  - 图标 + 名称
  - AP 成本(红色 / 蓝色徽章)
  - 位置效果(-2 / -1 显示,0 不显示)
- Hover tooltip 显示完整 desc

**回合结束 UI:**
- 右下角"结束回合"按钮,随时可点
- AP = 0 时按钮高亮提示
- 点击后:位置 +1 动画 → 若触发离店则转场,否则 AP 重置动画

**离店动画:**
- 位置推到 5 之后再被推 → 触发"被人群挤出"动画
- 表现:屏幕轻微抖动 + 摊位视角淡出 + "被挤出摊位"文案

## 8. 典型玩家决策场景(验证用)

### 场景 A:位置 5 + 3 AP,回合开局

玩家**必须至少用一次拉近动作**,否则本回合结束即被挤出:

- **选项 1**:冲进去 (2 AP, 5→3) + 抽取 (1 AP, 1 draw) → 回合结束推挤至 4
- **选项 2**:讨价还价 (0 AP, 丢 1 食材, 5→4) + 抽取 ×3 (3 AP, 3 draws) → 回合结束推挤至 5 → 下回合开局即处于位置 5
- **选项 3**(放弃):抽取 ×3,主动接受回合结束被挤出。换得 3 次抽取

### 场景 B:位置 3 + 3 AP

相对舒适,多种路径:
- 纯抽:抽取 ×3(end turn → 4)
- 塑形 + 抽:换位 (1 AP) + 抽取 ×2 (2 AP)
- 清除威胁:驱散 1 格抢菜人 (2 AP) + 抽取 (1 AP)

### 场景 C:位置 5 + 1 AP,残局

- AP 不够冲进去(需 2 AP)
- 没菜篮食材时不能讨价还价
- 剩下选择:抽取 1 次接受即将被挤出 / 主动结束回合 / 等末日来临

## 9. 最小原型验证目标

跑起来后,观察以下 3 个指标:

1. **位置经济的节奏感**
   - 平均每店能抽几次?
   - "冲进去 → 抽取 × N → 被推挤"的循环是否成为自然节奏
   - 玩家是否会主动选择早退

2. **冲进去的性价比**
   - 2 AP 是否合适?
   - 玩家是否主动使用,还是绕开?
   - 出现在哪些位置最常用

3. **讨价还价的情境张力**
   - 菜篮有垃圾食材时是否产生"反正没用,换个位置"的顺手决策
   - 菜篮全是好货时的舍弃焦虑是否成立
   - 0 AP 成本是否让它被滥用

## 10. 开放问题(实现时可灵活处理)

1. **AP 是否完全每回合重置** — 当前方案:完全重置,不跨回合保留
2. **炸墙的中心越界钳制策略** — 当前方案:不允许选择会越界的中心
3. **位置条在 UI 中的具体形态** — 当前方案:交给实现者决定(5 段图标 / 数字 / 人群挤压视觉)

以上不影响核心机制,实现时可自由定型。
