# 运送系统设计文档

## 概述

在提交订单与获得积分之间新增"运送结算"环节。玩家提交的物品排成一列，在运输颠簸中按顺序碰撞结算。玩家通过排列物品顺序和投入超额品质来管理运送风险。

**设计目标：** 为核心循环增加新的设计空间，使订单运送条件反向传导至池子选择和品质投资决策。

**核心身份：** 游戏依然是"在抽奖前做出策略选择"。运送条件作为前置已知信息，影响玩家在抽取阶段的决策。

## 流程集成

```
原流程：选池→抽取→背包管理→匹配订单→提交→得分

新流程：选池→抽取→背包管理→匹配订单→【排列打包】→【运送结算】→评估→得分/失败
```

运送仅对常规积分订单生效。撤离订单不经过运送。

## 核心规则

### 物品运送属性

每种物品有两个固定属性：

- **耐久 (D)**：抗撞击能力。UI图标：`Umbrella`
- **尖锐 (S)**：对相邻物品的碰撞威胁。UI图标：`TriangleAlert`

**设计原则：** 大多数物品S≥1（有质量有棱角，碰撞时造成冲击），少数S=0物品（柔软/吸收冲击）成为有价值的缓冲品。

### 品质缩放

**仅耐久随品质提升，尖锐固定不变。**


| 品质  | 耐久加成 |
| --- | ---- |
| 普通  | +0   |
| 优秀  | +1   |
| 稀有  | +2   |
| 史诗  | +3   |
| 传说  | +4   |
| 神话  | +5   |


示例：普通手机 D=2，稀有手机 D=4，史诗手机 D=5。

设计意图：品质投资 = 生存力投资。尖锐是物品固有属性，普通菜刀和史诗菜刀一样锋利(S=3)，但史诗菜刀自身更耐撞(D=9)。

### 订单运送条件

每个常规积分订单生成时附带运送信息：

**距离（决定颠簸次数）：**


| 距离  | 颠簸次数 | 生成权重 |
| --- | ---- | ---- |
| 近途  | 1    | 15%  |
| 中途  | 2    | 50%  |
| 远途  | 3    | 35%  |


**颠簸方向：** 每次颠簸的方向（→或←）在订单生成时随机确定，生成后固定，对玩家完全可见。

示例：一个远途订单可能显示 `→ ← →`，另一个可能显示 `← ← →`。

### 颠簸结算算法

#### 单次颠簸流程

以→方向为例，从最左侧开始依次处理每对相邻物品：

```
攻击者 = items[i]（颠簸方向上游侧）
防御者 = items[i+1]（颠簸方向下游侧）

如果攻击者已损坏或防御者已损坏：跳过
如果攻击者.尖锐 == 0：跳过（无伤害）

伤害 = 攻击者.尖锐

如果 防御者.当前耐久 >= 伤害：
  防御者.当前耐久 -= 伤害          // 护盾吸收
否则如果 防御者.当前耐久 > 0：
  防御者.当前耐久 = 0              // 护盾击穿
  防御者品质降一级                  // 穿盾伤害
否则：                              // 耐久已为0
  防御者品质降一级                  // 直接品质伤害

品质降级规则：
  普通物品耐久为0时再受伤害 → 损坏（从运送中移除）
  其他品质 → 降一级（史诗→稀有，等等）
  每次碰撞最多降一级，无论伤害多高
```

←方向：从最右侧开始，攻击者在右，防御者在左。

#### 颠簸间处理

- 单次颠簸内物品不移动位置
- 损坏的物品立即标记，该颠簸内后续碰撞跳过该物品
- 一次颠簸全部结算后，移除已损坏物品，剩余物品合拢填补空隙
- 下一次颠簸使用更新后的队列

#### 边缘位置特性

自然涌现的位置策略：

- →颠簸时：最左物品只攻击不受攻击（安全位），最右物品只受攻击不攻击
- ←颠簸时：最右物品只攻击不受攻击（安全位），最左物品只受攻击不攻击
- 策略：尖锐物品放在防御端（使其尖锐不造成伤害），脆弱物品放在安全端

### 运送后评估

1. 运送结算完毕后，用运送后的物品状态核验订单要求
2. 所有需求仍满足 → 订单完成，积分按运送后品质计算
3. 任一物品不再满足品质要求（降级至要求以下或已损坏）→ 订单失败
4. 订单失败时：存活物品以降级后状态返回背包，已损坏物品永久丢失

## UI设计

### 打包排列阶段（玩家操作）

**目标：** 让玩家凭静态信息做出合理排列决策。

**信息呈现：**


| 信息       | 展示方式                          |
| -------- | ----------------------------- |
| 物品身份     | 图标 + 名称 + 品质边框颜色              |
| 耐久 (D)   | `Umbrella`图标 + 实际数值（基础+品质加成后） |
| 尖锐 (S)   | `TriangleAlert`图标 + 实际数值      |
| 颠簸序列     | 方向箭头序列（如 → ← →）               |
| 订单最低品质要求 | 显示在物品或订单信息上                   |


**交互方式：** 点击交换（与现有游戏操作一致，无拖拽）。

**无结算预览：** 不显示预测结果，玩家自行判断排列优劣。保留后期转向随机方向的可能性。

### 结算动画阶段（自动播放）

**播放粒度：** 按碰撞（每对物品的碰撞单独演出）。

**播放控制：** 自动播放 + 暂停 + 按颠簸为单位回退/前进。

#### 单次碰撞动画序列

**步骤0 - 聚焦：** 高亮当前碰撞对（攻击者+防御者），其余物品变暗/淡化。

**步骤1 - 撞击：** 攻击者向防御者方向短距位移，防御者抖动。表达物理碰撞。

**步骤2 - 结算：** 根据情况分支：


| 情况                | 动画表现                          |
| ----------------- | ----------------------------- |
| 耐久吸收（D>0且未归零）     | 耐久数字变化 + 伤害弹字（-N）             |
| 护盾击穿（D降至0 + 品质降级） | 耐久归零 + 碎盾效果 → 短暂停顿 → 品质边框变色降级 |
| 无盾受击（D已为0）        | 直接品质降级，边框变色                   |
| 损坏（Common无盾受击）    | 碎裂/消散效果 → 物品从队列移除             |


**步骤3 - 复位：** 攻击者回到原位。短暂间隔后进入下一对碰撞。

#### 颠簸间过渡

- 已损坏物品消失，剩余物品合拢动画
- 短暂停顿展示当前状态
- 显示下一次颠簸方向，进入下一轮

## 数值验证场景

### 场景1：全S=1订单，远途

[苹果(D=3), 柠檬(D=3), 芒果(D=2)]，全Common，→ ← →


| 颠簸  | 碰撞                | 结果                |
| --- | ----------------- | ----------------- |
| →   | 苹果(S=1)→柠檬: D 3→2 | 柠檬(S=1)→芒果: D 2→1 |
| ←   | 芒果(S=1)→柠檬: D 2→1 | 柠檬(S=1)→苹果: D 3→2 |
| →   | 苹果(S=1)→柠檬: D 1→0 | 柠檬(S=1)→芒果: D 1→0 |


结果：全部存活，护盾刚好耗尽。Common全水果远途极限安全，再多一次颠簸就会降级。

### 场景2：含S=3物品 + 缓冲策略

订单需要菜刀和手机。中途 → ←。

直接打包 [芒果(D=2), 菜刀(D=3,S=3), 手机(D=2)]，全Common：

- →：菜刀(S=3)→手机 穿盾→手机损坏
- ←：菜刀(S=3)→芒果 穿盾→芒果损坏
- 结果：灾难，只剩菜刀。

加缓冲 [菜刀, 笔记本(D=6,S=0), 芒果, 手机]：

- →：菜刀(S=3)→笔记本 D:6→3，其余无伤
- ←：手机(S=1)→芒果 D:2→1，芒果(S=1)→笔记本 D:3→2，笔记本(S=0)→菜刀 无伤
- 结果：全部存活。笔记本隔离了菜刀的威胁。

## 远期扩展候选

以下为脑暴阶段的想法记录，待核心验证后考虑：

- **运输词缀：** 稳固（不会滑动）、棱角（被撞击时反伤）、连接（与相邻物品视作一体）
- **容器墙壁耐久：** 边缘位置的额外风险
- **上下方向颠簸：** 从1D排列扩展到2D网格
- **随机颠簸方向：** 从确定性转为随机性，增加风险管理深度
- **包装类物品池：** 已排除（选择路径A：多用途物品兼任缓冲）
