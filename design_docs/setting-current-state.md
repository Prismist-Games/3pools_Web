## 已确定

以下是确认的决定，可作为前提使用。不在这里的东西都是开放的。

**主题**
- **人如何与不确定性共处**——这是游戏主要讨论的话题
- 是一种"我有想要的结果/东西,但是想要的不一定能得到,得到了/更有把握得到的不一定很想要,但我还得继续"的情况,和这种情况应该怎么办.
- 包含两部分:

  **心态层**：关于你如何对待这个处境——在一个有 tension 的情景下依然保持冷静和思考,不因为随机性和不确定性决策瘫痪,调整心态:
  - 你能不能保持冷静？
  - 你能不能接受"这就是随机的"？
  - 你是焦虑、愤怒、麻木，还是平静地面对？
  - 你有没有把随机性的影响**纳入你的考量**——不是试图消除它，而是承认它的存在并带着它做决定？

  **策略层**：在不确定的情况下如何更有效地做出策略选择:
  - 概率评估、风险管理、资源分配、博弈思维

  **两层的关系**：策略层在核心机制里天然存在。**心态层一直缺失**——目前玩家没有理由对抽取结果产生真正的情感反应。设定的主要工作是让心态层落地。策略部分让人"思考"，心态部分让人"感受"。两者结合才是完整的"与不确定性共处"。

**设定**
- 主角的餐厅即将倒闭
- 主角每天凌晨去菜市场抢食材——好食材稀缺、人多手快，"抢"不是比喻
- 回到餐厅做菜、挽救人气、撑过每一天
- 餐厅对角色为什么重要的具体理由待定（传承、自我认同、信念等）——决定游戏的情感底色

**游戏结构**
- 每天 = 一次菜市场早市（一次搜打撤）+ 一道菜
- 天数为设计变量，由局外系统需求决定

**局内（菜市场早市）**
- 玩家在菜市场里抢食材，完成订单
- 当前实现：5 种摊位类型（海鲜市场、肉铺、粮食店、蔬菜店、乳品店），各摊位供应对应大类的食材
- 80 种食材，5 级品质，订单按品类 + 品质要求匹配
- 核心体验：订单和抽取互相影响，玩家灵活调整优先级
- 抢菜人（NPC）在场上制造干扰——食材有限、竞争者众，是"抢菜"设定的具象载体

**局外（做菜系统）**
- 局外的核心定位：**情境设置器**——给局内提供目标和意义，不是第二个游戏
- 玩家出门前看到今天的菜品要求 → 带着目标去菜市场 → 回来用抢到的食材做菜 → 结算
- 做菜系统尽可能简单，本质是一个结算过程

**人气值系统**
- 人气值 = 玩家的"血量" + 经济引擎
- 每天做菜的评价影响人气值涨跌（不是 0/1，是梯度——取决于做得多好）
- 人气值高 → 收入高 → 能升级（厨房设备等）→ 做菜能力更强（正循环）
- 人气值低 → 收入低 → 升级慢 → 做菜更难（负循环）
- 人气值归零 = 游戏失败

**终局**
- 活到最后，面对最终评审（"Boss战"）
- 可能是三道菜或一个 set 的综合评分
- 通过 = 餐厅得救
- 具体机制待定

**做菜机制——槽位制**
- 每天一道菜，菜有若干槽位（数量因菜而异）
- 每个槽位指定接受的食材分类，不同食材匹配度不同（S/A/B/C/D 等级）
- 菜品要求包含：菜名（指定命题）+ 槽位结构 + 五维目标（健康/香气/口感/味道/外观）
- 食材填入槽位 → 汇总五维属性 → 与目标比较（dispatch 五边形重叠）→ 得分
- 通配食材（淀粉、面粉等）：能进多种槽位但效力低，是"妥协"的载体

**食材分类**
- 蛋白质：肉类、水产、蛋类、奶制品、豆制品
- 蔬果：叶菜、根茎、果实类蔬菜、菌菇、水果
- 主食：米、面/面条/意面、面包、薯类
- 调味：基础调味、香料、香草、酱料
- 油脂乳品：植物油、动物油脂、黄油、奶油、芝士
- 通配原料：淀粉、面粉、蛋（作为辅料时）、高汤等——可跨类别使用

**评价双维度**
- **合题**（菜做对了没有）：槽位匹配度，菜品是否符合命题要求。主要影响当日人气值。
- **水准**（菜做好了没有）：食材品质和五维属性总和。主要影响最终评审。
- 两个维度之间存在张力：保人气的安全菜 ≠ 冲评审的野心菜

## 每日循环

```
1. 看到今天的菜品要求（菜名 + 槽位 + 需要什么食材）
2. 进入菜市场（局内）→ 在摊位抽取食材、完成订单、躲避抢菜人
3. 回家做菜 → 食材填入槽位 → 结算评分
4. 人气值涨跌 → 收入结算 → 可选升级
5. 下一天 → 新菜品要求
重复 N 天 → 最终评审（Boss）
```

## 死胡同

**关于"需要"作为唯一动机**：
- "需要"一旦被满足就不再重要——天花板问题
- 纯经济生存压力容易让做菜变成手段而非体验本身

**旧设定方向**：
- 公司员工/工位/机器设定——已废弃
- 电视烹饪节目设定——已废弃（2026-04-22），理由见 `setting-evolution-log.md` 2026-04-22 条目

**AI做菜**：
- 测试后未发现AI带来的独特体验
- AI方便测试但不构成核心玩法
- 做菜系统应为简单的机制结算，不依赖AI

## 设计原则

1. **主题是种子，不是装饰。** 所有设定元素必须服务于"人如何与不确定性共处"
2. **视觉和机制表现，不靠文字。** 需要大量文字解释的元素要么重新设计要么砍掉
3. **心态层通过设定落地，不通过机制强加。** 游戏机制服务策略层；设定让玩家的注意力转向心态层
4. **重要性必须通过系统持续传递。** 玩家在乎的东西需要在游戏中持续可见、会变化、被操作影响
5. **"抢"必须是真实的紧张感，不是购物。** 食材稀缺、时间紧迫、竞争者在场——设定要让早市像生存战而不像周末采购
6. **局外是情境设置器，不是第二个游戏。** 局外提供目标和意义，核心玩法在局内
