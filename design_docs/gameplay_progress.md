# 玩法设计进度

本文档为 AI agent 和团队成员提供整个项目的全局视角：每个系统的设计意图、当前状态，以及关键的演变决策。

> 阅读本文档后，AI 应能判断：每个系统为什么是现在这样，哪些经过了深入思考，哪些是临时的，哪些方向已经被排除过。

---
## 核心理念

围绕"在一个随机抽奖的行动之前,让玩家做一个"选择抽哪个池子"的策略选择"这个想法,制作一个轻中度的策略游戏.
## 核心决策

玩家面对 3 个池子，综合订单需求、背包状态、金币余量、词缀差异，选择一个池子进行抽取。这是整个游戏围绕的中心——所有系统最终服务于让这个决策有趣、有深度、有张力。

## 系统地图

| 系统      | 设计意图                                                    | 备注                                                                                                                                                                                           |
| ------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 奖池系统    | 策略选择的核心载体——玩家面对 3 个池子做出抽奖选择.                            | 目前池子有两个属性,物品类型和随机附着的词缀. 同一个类型的物品集中在同一个池子内随机产出(e.g., 苹果,西瓜,芒果都属于水果).这是一个决定,不是默认.                                                                                                              |
| 奖池词缀    | 增加抽奖选择时的策略维度,而且这一层维度直接指向"抽奖的方式"                         | 1.目前的策略空间中非常核心的构成部分,在目前的游玩体验中我们对词缀感觉良好. <br>2.设计上非常依赖于奖池和物品的属性特征.我们目前感觉扩展空间非常小, 因为物品只有品质和名称两个属性, 奖池只有名称的类别一个属性.所以归根结底奖池只能在现有基础上影响检索名字的能力和检索品质的能力. <br>3. 改动词缀意味着从比较底层修改核心玩法, 仅在对核心决策动刀时考虑修改. |
| 金币经济    | 策略选择的核心代价,局内经济系统                                        | 1.我们有一种对"金币"这个词指向的经济货币系统的倾向,可能因为背后天然带着一种更强的资源分配的感受.所以我们设想未来让玩家从局外带入金币的设计,也有未来让玩家有更多在局内使用金币的方式的倾向. <br>2.但是目前金币在游戏内只是机会成本,本质上和"步数","能量"没有区别,我们知道这一点,但我们还不急着修改. <br>3.完成撤离任务时重置是为了保持每一小轮的张力    |
| 物品      | 物品的独特名字是订单匹配的核心属性                                       |                                                                                                                                                                                              |
| 物品品质    | 增加决策立体感——不只是"要不要抽"，还有品质维度                               | 6 个等级；加成系数数值未深究                                                                                                                                                                              |
| 背包      | 背包空间构成资源压力                                              | 10 格固定大小                                                                                                                                                                                     |
| 合成机制    | 同名同品质合并升级，提供背包管理的策略维度                                   | 直觉性添加。`[待填充：是核心体验的一部分，还是可被替换？]`                                                                                                                                                              |
| 回收机制    | 局内唯一的金币回收途径（除撤离重置）；用物品换金币是有代价的取舍                        | 不同品质回收价值不同                                                                                                                                                                                   |
| 普通订单    | 要求特定物品组合，构成玩家抽取的目标和方向                                   | 3 个常规订单                                                                                                                                                                                      |
| 普通订单奖励  | 暂用分数作奖励，未来可能变成带到局外的物品/道具                                | **明确临时**；最高分目标也是临时的                                                                                                                                                                          |

## 关键演变

### 脉络

扑克牌原型 → 物品+订单系统 → 加入品质/金币/词缀 → 撤离订单+双资源系统 → 当前版本

### 关键决策

| 决策 | 原因 |
|------|------|
| 放弃扑克牌系统 | 查表体验差；数字感太抽象不利叙事；调性不符；扩展性差 |
| 放弃 tag+set collection | bookkeeping 过多，缺乏乐趣 |
| 订单不再奖励金币 | 钱滚钱体验差；数值无法配平；选择时"可能亏"的模糊感 |
| 引入撤离订单 | 受搜打撤/Risk of Rain 启发；需要整体张力和目标 |
| 每池物品 5→4 | 减少复杂度，让 flow 更流畅 |
| 暂时移除技能和阶段 | 独立模块，先验证核心+撤离 |
| 主题从"物欲"改为"人如何与不确定性共处" | 物欲不适合当前游戏 |

### 被否决的方向

| 方向 | 为什么否决 |
|------|-----------|
| 订单奖金币 + 定期上缴 + 难度递增 | 钱滚钱体验差 |
| 订单奖票 → 抽特殊池 → 过关道具 | `[待填充：具体为什么？]` |
| 层层递进的特殊池门票 | `[待填充]` |
| 集齐特殊道具 | `[待填充]` |
| Incremental 式逐渐展开机制 | `[待填充]` |
| 四时代 + modifier（Godot 版本） | modifier 可支撑体验变化，但钱滚钱问题未解决；整体循环感觉不好 |

## 当前设计重点

1. **bookkeeping 问题** — 必要但体验不佳的簿记劳动掩盖了有乐趣的策略思考
2. **策略空间的可见性** — 核心乐趣对很多玩家不够清晰、不够 accessible；与第 1 点相关但不完全相同
3. **内容扩展性** — 游戏感觉像"小游戏"；缺乏丰富内容和扩展空间；现有玩法做内容扩展不容易
4. **局内体验变化** — 单局内体验缺乏变化,尤其是玩家在单局中的决策并不太影响同一局内后续的体验
5. **叙事与机制的统一** — 设定需要跟着玩法一起推进
6. **局外系统缺失** — 优先级低于核心玩法迭代，但会影响局内设计
