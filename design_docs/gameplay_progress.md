# 玩法设计进度

本文档为 AI agent 和团队成员同步整个项目的全局视角：每个系统的设计意图，团队对游戏中各部分的当前想法.

---
## 核心理念

围绕"在随机抽奖前,让玩家做出"选择抽哪个池子"的策略决策"这一想法,制作一个轻中度的策略游戏.
## 核心决策

玩家面对 3 个池子，综合里程碑网格需求、背包状态、金币余量、词缀差异，选择一个池子进行抽取。这是整个游戏核心——所有系统最终服务于让这个决策有趣、有深度、有张力。

---

## 系统地图

| 系统       | 设计意图                                      | 备注                                                                                                                                                                                                                                                          |
| -------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **奖池（空间奖池）** | 策略选择的核心载体——玩家面对3×4物品地图+3个形状框做出抽奖选择 | 1. 已从旧的"类别+词缀"系统迭代为"物品地图+框选工具"系统。<br>2. 每抽从20个物品中随机选12个排在3×4网格上，3个框（形状+品质效果）供选择。<br>3. 形状决定覆盖哪些物品（名字索引），品质效果决定抽取品质分布。<br>4. 费用=形状精度费+品质效果费。小形状精确但贵，大形状便宜但噪音大。<br>5. 旧系统的扩展瓶颈（只能操纵名字和品质两个维度）被形状的空间维度缓解。<br>6. 物品类别概念已移除，"有的放矢"词缀已移除（被小形状取代）。                                                     |
| ├ 品质效果  | 继承旧词缀的品质操纵功能，附着在框上                       | 1. 6种效果（波动/稀碎/以旧换新/硬化/精准/提纯），和旧词缀一一对应（减去有的放矢）。<br>2. 效果本身没有改变——改变的是它们附着的载体（从池子变成框）。                                                                                                                                                                          |
| **金币**   | 策略选择的核心代价,局内经济系统                          | 1. 我们倾向于将"金币"视为经济货币系统，可能因为它天然带有更强的资源分配感受。我们设想未来让玩家从局外带入金币，也倾向于增加更多局内使用金币的方式。<br>2. 但目前金币在游戏内只是机会成本，本质上和"步数""能量"没有区别。我们知道这一点，但还不急着修改。<br>3. 完成撤离任务时重置金币是为了保持每一小轮的张力。<br><br>                                                                                 |
| **物品**   | 物品的独特名字是构成抽奖的核心                           | 1. 当前物品的名称、种类完全是临时的，会跟随设定修改。<br>2. 出于玩法考虑，物品应清晰易读，便于分辨和记忆。<br>3. 我们认为目前的局内物品过于符号化，但完全契合玩法，所以暂时不知道如何修改。<br>4. 除了名字和品质，我们倾向于赋予物品更多属性和特征，但同时对复杂度非常敏感。                                                                                                          |
| ├ 品质     | 强化抽奖乐趣，提供中奖的感觉。名字匹配只是功能性差别，品质提供了奖品稀有程度的差别 | 1. 品质这个属性本身和订单对物品品质提出要求之间不是必然关系，事实上它们不是同时添加的。<br>2. 目前的游玩体验中，我们对品质这个概念感觉良好，之后大概率会保留。<br>3. 但对于品质对玩家的实际意义，我们保留修改空间。现在的设计在当前版本运转良好，但随着核心玩法迭代可能会发生变化。<br>4. 例如，现在订单奖励券，所以品质可以在数值上给订单提供加成；但未来如果奖励物品，可能就要重新设计品质的效果。<br>5. 局内物品的品质应该和订单奖励之间有紧密关系。<br><br><br><br> |
| ├ 工具物品   | 测试"让玩家在背包里对物品进行操作，增加一个交互环节"这种设计的体验        | 1.非常临时的设计,未来机制方向的初步尝试.<br>2.目前玩起来的感觉还不错,我们认为能在物品抽出之后稍微鼓捣鼓捣是符合玩家直觉的一种好玩与满足感.<br>3.但同时我们认为它与核心玩法关系不够紧密，没有提升核心决策的体验，只是一个不错的独立系统，对现在的设计重要性一般。<br>4.未来可能会把这些道具的功能放置在系统中其他模块                                                                                      |
| ├ 合成     | 给玩家提供更多agency,提供合成升级的乐趣,减少获得低品质物品的挫败感.    | 1. 几乎是随着品质直觉性地添加的。<br>2. 感觉良好，暂时不打算更改。<br>3. 曾尝试提高合成的重要性和频率，发现与核心决策相性一般，没有深度参与到核心决策中，所以目前只作为一个不错的机制保留在游戏里。                                                                                                                                                  |
| ├ 回收     | 最初的意图是减少随机抽奖带来的负面体验                       | 1. 回收被设计成止损手段而非赚钱手段，除非在某些特定技能配置下。<br>2. 在游玩过程中，我们发现回收会在绝境下创造出"砸锅卖铁"续命的情况，在那个阶段带来很多"先扔什么"的策略选择，是有趣的游戏体验。<br>                                                                                                                                                 |
| **背包**   | 对玩家进行策略限制，施加压力迫使玩家进行取舍                    | 1.有对于在背包进行一些操作,发生一些交互的想象<br>2.有对于丰富背包格设计的想象                                                                                                                                                                                                                 |
| **里程碑网格** | 构成玩家抽取的目标和方向,核心玩法中的价值终点。取代了旧的"3普通订单+2撤离订单"系统 | 1. 原型阶段。用不规则连通网格（8–12单元格，3–5任务）取代了平面订单列表。<br>2. 核心变化：任务间通过共享单元格实现结构性互联（取代关节技）；逐格填充取代批量提交；撤离标记嵌入网格而非独立系统。<br>3. 移除了订单刷新、候选选择、品质加成乘数。<br>4. 叙事框架：网格=项目，里程碑=项目阶段，任务=交付物，单元格=工作项。<br>5. 任务限定为连续直线（水平或垂直），不允许完全重叠的任务。奖励稀疏化（30%概率/格，每任务保底1个）。<br>6. 正在验证这种结构能否解决旧系统的 bookkeeping 问题，同时保留策略深度。 |
| ├ 奖励     | 作为玩家在局内的最终目标——获得更多积分                      | 1. 积分 = 完成任务时收集有奖励单元格的积分值之和；金币 = 固定3/任务（临时数值）。<br>2. 奖励稀疏化：仅30%的单元格有积分奖励，但每个任务保证至少1个。<br>3. 共享的有奖励单元格在每个覆盖任务完成时各计一次。<br>4. 品质加成乘数已移除，未来可能重新引入。<br>5. 分数奖励仍是临时的，之后可能换成带到局外的物品。                                                                                                                  |
| ├ 品质要求   | 丰富抽奖时的策略考量维度                              | 1. 每个单元格仍有最低品质要求，但不再有品质加成乘数。<br>2. 网格系统的视觉化布局让品质要求更直观可见，可能缓解旧系统的簿记问题。<br>3. 未来迭代中仍可能调整品质在系统中的角色。                                                                                                                                                          |
| ├ 任务互联   | 取代关节技——通过网格结构让玩家同时考虑多个任务                  | 1. 任务共享单元格，填充一个单元格可能同时推进多个任务。这是旧"关节技"的结构化替代。<br>2. 关节技的耦合感现在来自网格拓扑而非提交时的物品匹配逻辑，更直观也更可控。                                                                                                                                                                   |
| **撤离**   | 提供局内风险/收益张力                               | 1. 不再是独立的订单系统。撤离现在是里程碑网格中一个单元格的属性（撤离标记🚀）。<br>2. 完成覆盖撤离格的任务后撤离变为**可用状态**（显示撤离按钮），玩家自行选择何时触发。<br>3. 核心体验框架保留：在压力下搜刮资源、权衡何时触发撤离。<br>4. 撤离时机的策略性增强——满足条件后可以继续抽取和完成其他任务再撤离。                                                                                           |
| **技能系统** | 提供局内体验变化和progression                      | 1.对构建核心玩法的影响不大,至少目前,我们有别于传统肉鸽游戏,不是强调engine building和synergy的游戏.所以这个系统更像是调料,是带来体验变化的添头,和其他系统关联不大,几乎可以独立考虑.因此,目前迭代核心玩法的测试过程中暂时移除了.<br>2.游玩体验良好.                                                                                                               |
| **时代系统** | 提供局内体验变化                                  | 1.和技能系统类似,属于添头.更像是不同的关卡特征.出于同样原因也暂时移除了.<br>2. 未来类似效果可能会用于关卡选择.                                                                                                                                                                                              |

## 当前设计重点

1. **bookkeeping 问题** — 必要但体验不佳的簿记劳动掩盖了有乐趣的策略思考
2. **策略空间的可见性** — 核心乐趣对很多玩家不够清晰、不够 accessible；与第 1 点相关但不完全相同
3. **内容扩展性** — 游戏感觉像"小游戏"；缺乏丰富内容和扩展空间；现有玩法不易进行内容扩展
4. **局内体验变化** — 单局内体验缺乏变化,尤其是玩家在单局中的决策对同一局内后续的体验影响不大
5. **叙事与机制的统一** — 设定需要跟着玩法一起推进
6. **局外系统缺失** — 优先级低于核心玩法迭代，但会影响局内设计

## 当前阶段

空间奖池系统原型已实现并正在测试中。里程碑网格（左）与物品地图+框选工具（右）并列显示。正在验证空间化的抽奖选择是否比旧的类别+词缀系统更有趣、更直观、更有扩展性。
