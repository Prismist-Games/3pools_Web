# 玩法设计进度

本文档为 AI agent 和团队成员同步整个项目的全局视角：每个系统的设计意图，团队对游戏中各部分的当前想法.

---
## 核心理念

围绕"在随机抽奖前,让玩家做出"选择抽哪个池子"的策略决策"这一想法,制作一个轻中度的策略游戏.
## 核心决策

玩家面对 3 个池子，综合订单需求、背包状态、金币余量、词缀差异，选择一个池子进行抽取。这是整个游戏核心——所有系统最终服务于让这个决策有趣、有深度、有张力。

---

## 系统地图

| 系统       | 设计意图                                      | 备注                                                                                                                                                                                                                                                          |
| -------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **奖池**   | 策略选择的核心载体——玩家面对 3 个池子做出抽奖选择.              | 目前池子有两个属性,物品类型和随机附着的词缀. 同一个类型的物品集中在同一个池子内随机产出(e.g., 苹果,西瓜,芒果都属于水果).这是有意的设计决定,不是默认.但正在等待迭代.                                                                                                                                                                  |
| ├ 词缀     | 增加抽奖选择时的策略维度，三轴策略空间                    | 1. 12个词缀，分三个轴：名字选择（以旧换新/精准/有的放矢）、品质操控（硬化/提纯/波动/稀碎）、运送相关（棱角/单向/保护/套装/易爆）。<br>2. 物品现在有品质、名称和尖锐度(▲)三个属性，词缀空间比之前更大。<br>3. 运送词缀给物品贴tag，影响delivery碰撞行为，创造了品质词缀之外的全新策略维度。 |
| **金币**   | 策略选择的核心代价,局内经济系统                          | 1. 我们倾向于将"金币"视为经济货币系统，可能因为它天然带有更强的资源分配感受。我们设想未来让玩家从局外带入金币，也倾向于增加更多局内使用金币的方式。<br>2. 但目前金币在游戏内只是机会成本，本质上和"步数""能量"没有区别。我们知道这一点，但还不急着修改。<br>3. 完成撤离任务时重置金币是为了保持每一小轮的张力。<br><br>                                                                                 |
| **物品**   | 物品的独特名字是构成抽奖的核心                           | 1. 当前物品的名称、种类完全是临时的，会跟随设定修改。<br>2. 出于玩法考虑，物品应清晰易读，便于分辨和记忆。<br>3. 我们认为目前的局内物品过于符号化，但完全契合玩法，所以暂时不知道如何修改。<br>4. 除了名字和品质，我们倾向于赋予物品更多属性和特征，但同时对复杂度非常敏感。                                                                                                          |
| ├ 品质     | 品质 = 耐久度(♥)的唯一来源和视觉标识 | 1. 品质已从"抽象的好坏"简化为"具体的生存能力"——普通1♥到神话6♥。<br>2. 品质不再影响订单通过条件或积分乘数。唯一的机械作用是决定物品在运送中能扛多少伤害。<br>3. 品质颜色成为D值的快速可读层——紫色=硬，灰色=脆。<br>4. 合成的意义变得清晰：+1♥在1-6的尺度下是生死差别。<br>5. 抽奖的"开箱"兴奋感保留（高品质 = 更多心 = 更安全的运送）。 |
| ├ 工具物品   | 测试"让玩家在背包里对物品进行操作，增加一个交互环节"这种设计的体验        | 1.非常临时的设计,未来机制方向的初步尝试.<br>2.目前玩起来的感觉还不错,我们认为能在物品抽出之后稍微鼓捣鼓捣是符合玩家直觉的一种好玩与满足感.<br>3.但同时我们认为它与核心玩法关系不够紧密，没有提升核心决策的体验，只是一个不错的独立系统，对现在的设计重要性一般。<br>4.未来可能会把这些道具的功能放置在系统中其他模块                                                                                      |
| ├ 合成     | +1♥耐久，在1-6♥的尺度下是生死差别                     | 1. 合成动机在新系统中变强：每+1♥直接决定物品能否扛住运送碰撞。<br>2. 但合成消耗一个同名物品（失去名字匹配机会），与背包空间形成真实取舍。 |
| ├ 回收     | 最初的意图是减少随机抽奖带来的负面体验                       | 1. 回收被设计成止损手段而非赚钱手段，除非在某些特定技能配置下。<br>2. 在游玩过程中，我们发现回收会在绝境下创造出"砸锅卖铁"续命的情况，在那个阶段带来很多"先扔什么"的策略选择，是有趣的游戏体验。<br>                                                                                                                                                 |
| **背包**   | 对玩家进行策略限制，施加压力迫使玩家进行取舍                    | 1.有对于在背包进行一些操作,发生一些交互的想象<br>2.有对于丰富背包格设计的想象                                                                                                                                                                                                                 |
| **普通订单** | 构成玩家抽取的目标和方向,核心玩法中的价值终点                   | 1. 目前"订单"="名字 + 最低品质"的组合。我们认为现在的核心玩法既是由这样的订单定义的，也受这一点的限制而难以扩展。<br>2. 当对核心玩法进行改动时，我们随时准备修改订单的运作方式。                                                                                                                                                           |
| ├ 奖励     | 作为玩家在局内的最终目标——获得更多订单奖励                    | 1. 目前的分数奖励完全是临时的。因为没有局外系统，出于让游戏能完整运行的目的，我们先定了获取高分的游戏目标。<br>2. 之后可能会换成带到局外的物品作为奖励，但还没有确定。                                                                                                                                                                    |
| ├ 品质要求   | **已移除**                                        | 订单不再要求特定品质。品质的策略复杂度已转移到运送系统：品质决定♥（生存能力），运送中物品的▲值决定互相伤害。bookkeeping问题因此大幅改善。 |
| ├ 关节技    | 鼓励玩家在展开策略时同时考虑多个普通订单                      | 1. 曾尝试移除，因为关节技导致的订单间耦合会促使玩家进入"凑满所有订单所需，然后一波交"的循环，在完成订单的抉择上似乎有些单薄。但实测移除关节技后，整体舒适度大幅下降，所以保留了这个设计。                                                                                                                                                             |
| ├ 刷新与候选  | 通过赋予玩家选择权降低订单随机性带来的负面体验                   | 1. 在一次性完成多个订单时，第一个和第二个订单的选择有点缺乏依据，但不是大问题。<br>2. 是一个和核心决策关系不大，但很好用的机制。<br>                                                                                                                                                                                   |
| **运送系统** | 在订单提交和结算之间加入空间排列谜题层                      | 1. 所有订单（普通+撤离）都走运送结算。物品在运送途中碰撞，♥(品质)决定生存，▲(物品固有)决定威胁。<br>2. 撤离难度通过物品▲值总和控制——高难度订单需要高▲物品，它们在运送中互相撕碎。<br>3. 装箱排列是玩家的核心操控：哪个物品放中间（受双重伤害），哪个放边缘。<br>4. UI用♥和▲替代数字，视觉计数替代心算。 |
| **撤离订单** | 提供局内风险/收益张力                               | 1. 撤离订单现在也走运送结算流程。难度由物品▲值决定而非品质要求。<br>2. 保留核心框架：在前功尽弃的压力下进行物品搜刮。 |
| **技能系统** | 提供局内体验变化和progression                      | 1.对构建核心玩法的影响不大,至少目前,我们有别于传统肉鸽游戏,不是强调engine building和synergy的游戏.所以这个系统更像是调料,是带来体验变化的添头,和其他系统关联不大,几乎可以独立考虑.因此,目前迭代核心玩法的测试过程中暂时移除了.<br>2.游玩体验良好.                                                                                                               |
| **时代系统** | 提供局内体验变化                                  | 1.和技能系统类似,属于添头.更像是不同的关卡特征.出于同样原因也暂时移除了.<br>2. 未来类似效果可能会用于关卡选择.                                                                                                                                                                                              |

## 当前设计重点

1. **bookkeeping 问题** — 必要但体验不佳的簿记劳动掩盖了有乐趣的策略思考
2. **策略空间的可见性** — 核心乐趣对很多玩家不够清晰、不够 accessible；与第 1 点相关但不完全相同
3. **内容扩展性** — 游戏感觉像"小游戏"；缺乏丰富内容和扩展空间；现有玩法不易进行内容扩展
4. **局内体验变化** — 单局内体验缺乏变化,尤其是玩家在单局中的决策对同一局内后续的体验影响不大
5. **叙事与机制的统一** — 设定需要跟着玩法一起推进
6. **局外系统缺失** — 优先级低于核心玩法迭代，但会影响局内设计
