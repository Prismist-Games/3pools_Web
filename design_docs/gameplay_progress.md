# 玩法设计进度

本文档为 AI agent 和团队成员同步整个项目的全局视角：每个系统的设计意图，团队对游戏中各部分的当前想法.

---
## 核心理念

围绕"在随机抽奖前,让玩家做出"选择抽哪个池子"的策略决策"这一想法,制作一个轻中度的策略游戏.
## 核心决策

玩家面对 3 个池子，综合订单需求、背包状态、金币余量、词缀差异，选择一个池子进行抽取。这是整个游戏核心——所有系统最终服务于让这个决策有趣、有深度、有张力。

---

## 系统地图

| 系统       | 设计意图                                            | 备注                                                                                                                                                                                                                                                         |
| -------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **奖池**   | 策略选择的核心载体——玩家面对 3 个池子做出抽奖选择.                    | 目前池子有两个属性,物品类型和随机附着的词缀. 同一个类型的物品集中在同一个池子内随机产出(e.g., 苹果,西瓜,芒果都属于水果).这是有意的设计决定,不是默认.但正在等待迭代.                                                                                                                                                                 |
| ├ 词缀     | 增加抽奖选择时的策略维度,而且这一层维度直接指向"抽奖的方式"                 | 1.目前的策略空间中非常核心的构成部分,在目前的游玩体验中我们对词缀感觉良好. <br>2.设计上非常依赖于奖池和物品的属性特征.我们目前感觉扩展空间非常小, 因为物品只有品质和名称两个属性, 奖池只有名称的类别一个属性.所以归根结底奖池只能在现有基础上影响检索名字的能力和检索品质的能力. <br>3. 改动词缀意味着从比较底层修改核心玩法, 仅在对核心决策动刀时考虑修改.                                                               |
| **金币**   | 策略选择的核心代价,局内经济系统                                | 1.我们有一种对"金币"这个词指向的经济货币系统的倾向,可能因为背后天然带着一种更强的资源分配的感受.所以我们设想未来让玩家从局外带入金币的设计,也有未来让玩家有更多在局内使用金币的方式的倾向. <br>2.但是目前金币在游戏内只是机会成本,本质上和"步数","能量"没有区别,我们知道这一点,但我们还不急着修改. <br>3.完成撤离任务时重置是为了保持每一小轮的张力                                                                  |
| **物品**   | 物品的独特名字是构成抽奖的核心                                 | 1. 当前物品的名称,种类完全是临时的,会跟随设定修改.<br>2. 出于玩法考虑,物品应该清晰易读,能够轻松分辨,记忆.<br>3. 我们觉得目前的局内物品过于符号化,但是完全契合玩法,所以暂时不知道怎么修改.<br>4. 在名字和品质之外,我们有赋予物品更多属性,特征的倾向,同时对复杂度非常敏感.                                                                                                    |
| ├ 品质     | 强化抽奖的乐趣,提供中奖的感觉,名字是否匹配只是功能上的差别,品质提供了抽出奖品的稀有程度差别 | 1. 品质这个属性本身和订单对物品品质提出要求之间不是必然的关系,事实上他们也不是同一时间添加的.<br>2. 目前的游玩体验中我们对品质这个概念本身的感觉良好,之后大概率会保留.<br>3. 但是对于品质对玩家而言的实际意义我们保留修改的空间,现在的在当前版本运转没问题,但随着核心玩法的迭代,可能会发生变化.<br>4. e.g.,,现在订单奖励券,所以品质可以在数值上给订单提供加成,但是未来如果奖励物品了,可能就要重新设计品质的效果.<br>5. 局内物品的品质应该和订单奖励之间关系非常紧密 |
| ├ 工具物品   | 测试"让玩家在背包里可以有一些对物品的操作,多一个交互环节"这种设计的体验           | 1.非常临时的设计,未来机制方向的初步尝试.<br>2.目前玩起来的感觉还不错,我们认为能在物品抽出之后稍微鼓捣鼓捣是符合玩家直觉的好玩,有满足感的乐趣.<br>3.但同时我们认为他与核心玩法的关系并不紧密,没有提升核心决策的体验,只是一个不错的独立系统. 所以对于现在的设计重要性一般.<br>4.未来可能会把这些道具的功能放置在系统中其他模块                                                                              |
| ├ 合成     | 给玩家提供更多agency,提供合成升级的乐趣,减少获得低品质物品的挫败感.          | 1. 几乎是随着品质直觉性地添加了.<br>2. 感觉良好,没有必要暂时不打算更改.<br>3. 曾经有过把合成的重要性和频率提高的尝试,发现与核心决策相性一般,也并不是非常深度地参与到了核心决策中.所以目前只是作为一个还不错的机制保留在了游戏里.                                                                                                                               |
| ├ 回收     | 最初的意图只是减少随机抽奖带来的负面体验                            | 1.回收被设计成止损手段,而非赚钱手段.除非在某些特定技能配置下.<br>2.在游玩过程中,我们发现回收会打造出绝境下"砸锅卖铁"去续命的情况,在那个阶段带来了很多先扔什么的策略选择,是非常有趣的游戏体验.                                                                                                                                                    |
| **背包**   | 对玩家进行策略上的限制,给到压力逼迫玩家进行取舍                        | 1.有对于在背包进行一些操作,发生一些交互的想象<br>2.有对于丰富背包格设计的想象                                                                                                                                                                                                                |
| **普通订单** | 构成玩家抽取的目标和方向,核心玩法中的价值终点                         | 1. 目前"订单"="名字+最低品质"的组合,我们认为现在的核心玩法既是由这样的订单定义的,也在受这一点的限制导致很难扩展.<br>2. 当要对核心玩法进行改动时,我们随时准备修改订单的运作方式.<br>                                                                                                                                                     |
| ├ 奖励     | 作为玩家在局内的最终目标 - 获得更多订单奖励                         | 1.目前的分数奖励完全是临时的,因为没有局外系统,出于让游戏能完整运行的目的,我们先定了获取高分的游戏目标<br>2. 之后可能会换成带到局外的物品作为奖励,但还没有确定.                                                                                                                                                                     |
| ├ 品质要求   | 丰富抽奖时的策略考量维度                                    | 1.目前核心决策的策略空间中非常重要的构成部分,目前的感觉比较复杂. 大量关于订单的簿记工作来源于此,同时也确实创造出了许多思考空间.<br>2.当核心玩法进行迭代时,极有可能会被优化掉,把复杂度释放给另一些玩法要素,回到更纯粹的品质加成/展示物品稀有度的身份上.                                                                                                                       |
| ├ 关节技    | 鼓励玩家在展开策略时同时考虑多个普通订单                            | 1.曾经尝试过移除,因为关节技导致的订单之间耦合的情况会促使玩家进入 凑满所有订单所需,然后一波交了的循环. 在完成订单的抉择上仿佛有些单薄.但是实测移除关节技后,整体舒适度大幅下降,所以保留了关节技的设计.                                                                                                                                                   |
| ├ 刷新与候选  | 通过赋予玩家选择权降低订单随机性带来的负面体验                         | 1. 在一次性完成多个订单时,第一个和第二个订单的选择有点缺乏依据,但不是大问题.<br>2. 是一个和核心决策关系不大,但是挺好用的一个机制.                                                                                                                                                                                   |
| **撤离订单** | 提供局内风险/收益张力                                     | 1. 在某一次对游戏流程的大幅度改动中加入,最让我们惊喜的收获,我们非常希望保留这个框架:在无法成功结算,前功尽弃的压力之下,进行"物品搜刮(虽然目前是分数)"的局内游戏流程.                                                                                                                                                                   |
| **技能系统** | 提供局内体验变化和progression                            | 1.对构建核心玩法的影响不大,至少目前,我们有别于传统肉鸽游戏,不是强调engine building和synergy的游戏.所以这个系统更像是调料,是带来体验变化的添头,和其他系统关联不大,几乎可以独立考虑.因此,目前迭代核心玩法的测试过程中暂时移除了.<br>2.游玩体验是好的.                                                                                                             |
| **时代系统** | 提供局内体验变化                                        | 1.和技能系统类似,属于添头.更像是不同的关卡特征.出于同样原因也暂时移除了.<br>2. 未来类似效果可能会用于关卡选择.                                                                                                                                                                                             |

## 当前设计重点

1. **bookkeeping 问题** — 必要但体验不佳的簿记劳动掩盖了有乐趣的策略思考
2. **策略空间的可见性** — 核心乐趣对很多玩家不够清晰、不够 accessible；与第 1 点相关但不完全相同
3. **内容扩展性** — 游戏感觉像"小游戏"；缺乏丰富内容和扩展空间；现有玩法做内容扩展不容易
4. **局内体验变化** — 单局内体验缺乏变化,尤其是玩家在单局中的决策并不太影响同一局内后续的体验
5. **叙事与机制的统一** — 设定需要跟着玩法一起推进
6. **局外系统缺失** — 优先级低于核心玩法迭代，但会影响局内设计
