# 玩法设计进度

本文档为 AI agent 和团队成员同步项目全局视角：每个系统的设计意图、当前实现状态、是核心还是脚手架、是精心设计还是占位符。

具体规则数值见 `game_rules.md`，设定背景见 `setting-current-state.md`，代码参考见 `codebase_technical_reference.md`。

---

## 核心理念

制作一款轻中度策略游戏，核心体验是"在随机性面前做出有意义的策略选择"。

主题：**人如何与不确定性共处**——心态层 + 策略层。叙事层是"厨师参加电视节目抢菜 → 回家做菜救餐厅"。

## 系统设计意图

### 市场（替代旧墙类型）

把"这面墙有啥"变成玩家可理解的空间概念——"去哪家店就能买到哪类食材"。减少认知负荷，同时保留跨墙策略（订单跨大类 → 需要多家店轮访）。

### 品质 5 档 + MIN_QUALITY 底

- 5 档让墙上物品有"稀有性"可读，紫/橙的出现对玩家是小事件
- MIN_QUALITY 底是**给每墙加局部价值**——抽到被标记的品类有"保底品质"，意味着同一面墙不同品类抽取价值差异巨大，引导玩家**优先消耗被标记的品类**

### 订单从概率表到 qualityDist

- easy/medium 仍用 reqBudget（±25% 方差），保留"轻随机"的探索感
- hard/extreme 用 qualityDist 固定配比，因为高难订单的"难度形状"应该稳定可读（例：hard 恒定 = "1 紫 + 1 绿 + 1 白"），玩家一眼知道要做什么

### 人群 / 抢菜人（主题换壳）

原本"厄运"是抽象惩罚系统。换成"人群"/"抢菜人"后：
- 语义更贴"抢菜"情景
- 抢菜人用人像 emoji 池呈现，把"风险"可视化为"有人挡住你拿到东西"
- HP → "耐久度"（菜篮的韧性）

### 交换区（旧"货架"）

叙事改口强调"交换"这个动作——订单本身是**我用 A 换 B**（交食材拿奖励）。容量从 5 降到 4，减少玩家的"我还要追哪些订单"的认知负担。

### 配置面板

从"每次问 agent 概率是多少"的痛点直接对应的方案。设计意图是：
- 所有经常调的数值都进 `LIVE_CONFIG`
- 玩家 / 设计师能**在游戏里直接改**，不用碰代码 + 重启 dev server
- 导入导出 JSON 方便把"好的组合"贴回代码

## 当前设计重点

1. **主题文案统一最终通稿** —— 已经统一一轮（抢菜人 / 人挤人 / 交换区 / 菜篮 / 耐久度 / 接下来去哪儿？），但零星地方（translations.js 的老条目、GameGuide、编辑器）还有历史痕迹，零碎清理中
2. **MIN_QUALITY 实战手感** —— 2-4 个标记品类的出现率和品质分布对每墙策略深度的影响
3. **订单需求 vs 奖励平衡** —— extreme 现在是 reqBudget 等价提交拿橙色奖励，已经从"白嫖"收紧到"零利润 + 跨 4 大类的难度溢价"
4. **人气值曲线** —— 当前 ±2/±1/0，但**起始人气 / 下限 / 归零失败**的参数是否合理需要实战
5. **Kitchen 提交时对玩家的"目标可见性"** —— 槽位要求 tag 能让玩家规划，但复杂度（3 层 tag + default 0）对新手是否过高
6. **ConfigPanel 覆盖率** —— 词缀系统（目前未启用）、合成规则、人气值公式这些更深的参数还没进面板

## 已知问题与设计债务

- **useGameLogic 巨型化**：~2200 行，尚未拆子 hook
- **`fridge` 字段冗余**：代码里有 `fridge` state，但实际几乎不用，当前"跨店持有"基本靠 inventory。留着有点困惑，没清
- **i18n 覆盖不全**：新主题（抢菜人/人挤人/交换区/耐久度/菜篮/接下来去哪儿？）英文翻译已补，但 translations.js 里大量 v1 残留条目（奖池/技能/词缀/传说/神话...）还在占位
- **派遣判定与厨房未接线**：`DispatchJudgment.jsx` 五维判定是独立工具，未与 Kitchen 做菜流程整合
- **LevelEditor 路由未清**：`/editor` / `/levels` 路由在 `App.jsx` 仍注册，但当前玩法不消费 level 数据
- **populate-dependent 翻译**：320 个食材名的英文仍靠 `nameEn` 字段直读，没走 `t()` —— 所以 hot-swap 翻译时不一致
- **constants.js 冷冻 v1 数据**：600+ 行 v1 系统（阶段/技能/词缀/工具/6 级品质/池）还在，可以考虑清掉
