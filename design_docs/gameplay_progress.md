# 玩法设计进度

本文档为 AI agent 和团队成员同步整个项目的全局视角：每个系统的设计意图，团队对游戏中各部分的当前想法.

---
## 核心理念

制作一个轻中度的策略游戏,核心体验是"在随机性面前做出有意义的策略选择".

## 核心决策

玩家面对 4×4 奖品墙，综合订单需求、背包状态、墙面布局（含贴纸成簇情况）、modifier 效果、厄运风险，选择一行或一列进行抽取（随机获取其中 1 个格子；若是贴纸格则按簇消除、按公式产出）。

回合间的两层决策：
- **奖品墙 3 选 1**（modifier 隐藏，仅看贴纸/厄运/特殊格组成）→ 押宝 + 揭晓戏剧性
- **继续 vs 撤离** → push-your-luck

每场开局的"今日菜单 + 5 次二选一组建初始订单"让玩家在第一回合之前就已经做出风格性的策略表态。

## 系统地图

| 系统       | 设计意图                                      | 备注                                                                                                                                                                                                                                                          |
| -------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **行列选取** | 策略选择的核心载体——玩家面对 4×4 矩阵，选择一行或一列抽取 | v2.5 起加入"簇"概念：相邻同 id 贴纸自动连片，整片消除但仅产出 1 张（modifier/膨化加成可叠加）。这让"行/列里的贴纸成簇情况"成为新的决策维度——抽散单格保数量 vs 抽大簇换 modifier windfall。 |
| **簇（Cluster）** | 让墙面的"几何结构"参与决策，不只是"哪些格子"，还有"它们怎么挨着" | 新加。当前是惩罚性机制（密集成片基础产出仍是 1）。配合传送带/转盘的横向移动机制，玩家可以重排簇结构。视觉上通过桥接矩形让簇渲染成一片连贯形状。设计预期：经过测试调整 yield 公式与 modifier 加成的曲线。 |
| **奖品墙 3 选 1** | 在抽墙之前增加一层选择，提供风险偏好的表达 | 候选卡只展示基本信息（贴纸/厄运/特殊格），modifier **隐藏** 直到选定后揭晓。Commit-on-click，无 peek-back。设计意图：让选墙变成"押宝格子组成"+"揭晓戏剧性"，而不是"提前读规则后选最舒服的"。 |
| **金币**   | 局内经济系统                          | 每回合 5 金币，每抽 1 金币消耗，回合内不累积。当前简化设计，未来可能赋予更多战术维度（modifier 覆盖、技能联动）。 |
| **贴纸**   | 局内材料                          | 20 种全集，每面墙随机出 3-4 种。每场撤离时丢失。完成订单消耗。是簇系统的载体。 |
| **食材** | 局外得分物 + 厨房菜品 slot 的填充材料 | INGREDIENTS：4 大类（肉类/海鲜/蔬菜/主食）× 4 小类 × 4 rarity ≈ 64 种，带 hierarchical tag。撤离时进入厨房按今日菜品的 slot 匹配规则结算（prefer ×2 / accept ×1 / none ×0.5）。3 种食材每局获得 +1/+2/+3 大局加分。 |
| **厨房与菜品** | 给食材一个"组合性"的目标，让收集时有"配菜"的方向感 | 当前 2 道菜（海洋线条/炉火慢歌），每道菜 4 个 slot + 可能的 trigger 槽位 + crossBonus。结算评级 5 档（翻车 ~ 惊艳），人气 Δ -2~+2。**结算自动化未做**——目前是手动模态框，玩家自己摆 slot。 |
| ├ 合成     | 给玩家提供更多 agency，减少低品质食材的挫败感    | 选 2 个相同食材合成 → 升 1 级 rarity。目前是 nice-to-have，与核心决策耦合度不高。 |
| ├ 回收     | 减少抽奖负面体验                       | 多选丢弃，无补偿。HP 紧张时的"砸锅卖铁"续命选项。 |
| **背包**   | 对玩家施加压力迫使取舍                    | 15 格（基础），抽中 🎒 +1 持续到本场结束。贴纸和食材共用。背包满时进入待处理队列逐个处理。 |
| **订单系统** | 构成玩家抽取的目标和方向                   | 货架始终满 5 单，无"接受/未接受"区分。三种刷新渠道：开局 setup（5 次二选一）/ 完成订单自动补单（二选一）/ 主动 🔄 刷新（消耗刷新次数 -1）。多个二选一事件共享 FIFO 队列，永不互相覆盖（v2.5 修复了之前的"事件吞掉"bug）。 |
| ├ 模板与权重 | 4 档难度的奖励-成本曲线                   | easy(★, 2 sticker, 1 type, w40) / medium(★★, 3, 2, w30) / hard(★★★, 4, 3, w20) / extreme(★★★★, 6, 4, w10)。 |
| ├ Setup 二选一 | 让开局成为有意识的"今天打哪些订单"决策 | 揭晓菜品 + 5 次二选一构建初始货架，不能跳过。意图：菜品的 slot 偏好 + 玩家选订单 = 第一回合前的策略基调。也修了首墙生成时尚无订单可参考的 bug。 |
| ├ 刷新次数 | 让玩家主动管理订单组合                       | 每场初始 0（旧版 3，v2.5 改 0），上限 5。订单格 +1，主动按钮 -1。"是否要花刷新换订单组合"成为局内的小型资源管理决策。 |
| **撤离** | 提供局内风险/收益张力                               | 主动撤离：食材进厨房结算；贴纸丢失。HP 归零强制撤离 + 全部丢失。撤离机制本身想保留这个框架，未来可能增加更多过程/条件/代价。 |
| **厄运系统** | 核心压力来源 | 厄运网格（10 格，1 起手危险）+ 每回合自动 +1 危险。墙上💀 / ⬆️ 格触发结算/升级。v2.5 重新让两种厄运格出现在随机墙上（5%/5% 每格概率）。屏幕抖动 + CRT 视觉强化 💀 命中。 |
| **Modifier 系统** | 让每面墙提供独特的局内体验变化                      | 当前 9 种（v2.5 移除了阴阳轮转）：神秘面纱、双倍惊喜、交叉问答、转盘中心、传送带、野蛮生长、爆裂愈合、镜花水月、祝福愈合。Modifier 选取使用 shuffle bag（跨回合/跨场保留），保证 9 个 modifier 在轮完前不重复。 |
| **关卡系统（手作）** | 提供半手作的特殊地形作为 modifier 之外的选项                                  | 关卡 JSON 在 `src/data/levels/`，调度配置在 `src/data/levelSchedule.json`。主关卡进入 3 选 1（与 modifier 互斥），子关卡通过 🚪 入口进入。当前关卡内容偏少，是后续扩展点。 |
| **技能系统** | 提供局内体验变化和 progression                      | 暂未启用。当前迭代核心玩法的测试中暂时移除。 |

## 当前设计重点

1. **簇系统的平衡感** — yield 公式（基础 1 + modifier 加成）的曲线是否让玩家感到"惩罚但可博弈"，需要实战调整
2. **厨房结算的体验** — 撤离时手动放食材 vs 自动求最优解；菜品 slot 的反馈循环是否清晰
3. **bookkeeping 问题** — 必要但体验不佳的簿记劳动掩盖了有乐趣的策略思考
4. **策略空间的可见性** — 核心乐趣对很多玩家不够清晰、不够 accessible
5. **内容扩展性** — 关卡内容偏少；菜品只有 2 道
6. **叙事与机制的统一** — 厨房主题已落地，但与"奖品墙/电视节目"的原本意象需要进一步统合
7. **局外系统缺失** — 优先级低于核心玩法迭代，但会影响局内设计

## 当前阶段

**v2.5 — 簇系统 + 开局组建 + 三选一隐藏 modifier**

正在迭代簇系统的玩家体验：视觉表达（已加桥接矩形）、产出公式（加性叠加确认）、modifier 交互（mirror 同簇去重、blast/blessing/growth 只作用于抽中格）。下一步：实战测试簇 yield 曲线、厄运密度（当前 5%/5%）、5 次 setup 二选一的节奏感。

并行可推进项：
- 厨房结算自动化
- 菜品扩展（当前 2 道）
- 关卡扩展
- 修订 codebase 技术参考文档（当前最后更新于 2026-04-07，与现状脱节较大）
