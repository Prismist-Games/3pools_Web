## 模块地图

每个模块标注两个维度：
- **定位**：核心玩法 / 局内外围 / 局外外围
- **状态**：精心设计 / 临时填充 / 已移除或搁置

### 核心玩法的定义

给定一个游戏画面（订单状态、背包内物品、池子选项），面对三个池子，玩家在思考什么，从而做出选择一个池子进行抽取的决策。从"抽取"到"完成订单"的过程，就是核心玩法。

### 核心玩法模块

| 模块 | 状态 | 设计意图 | 备注 |
|------|------|----------|------|
| 奖池系统 | 精心设计 | 策略选择的载体——玩家面对 3 个池子做出选择 | 每池 4 个物品（从 5 改为 4，减少复杂度） |
| 物品与背包 | 精心设计 | 物品的独特名字是订单匹配的核心属性；背包空间构成资源压力 | 10 格固定大小 |
| 订单系统 | 精心设计 | 要求特定物品组合，构成玩家抽取的目标和方向 | 3 个常规订单 |
| 金币经济 | 精心设计 | 让选择有代价；切断了"完成订单→获得金币→抽取→完成订单"的循环 | 重要决策：双资源系统。金币可通过回收物品少量回收，或撤离重置恢复初始量，但不从订单获得 |

## 关键演变

### 脉络

扑克牌原型 → 物品+订单系统 → 加入品质/金币/词缀 → 撤离订单+双资源系统 → 当前版本

### 关键决策

| 决策 | 原因 |
|------|------|
| 放弃扑克牌系统 | 查表体验差；数字感太抽象不利叙事；调性不符；扩展性差 |
| 放弃 tag+set collection | bookkeeping 过多，缺乏乐趣 |
| 订单不再奖励金币 | 钱滚钱体验差；数值无法配平；选择时"可能亏"的模糊感 |
| 引入撤离订单 | 受搜打撤/Risk of Rain 启发；需要整体张力和目标 |
| 每池物品 5→4 | 减少复杂度，让 flow 更流畅 |
| 暂时移除技能和阶段 | 独立模块，先验证核心+撤离 |
| 主题从"物欲"改为"人如何与不确定性共处" | 物欲不适合当前游戏 |

### 被否决的外围系统方向

| 方向 | 为什么否决 |
|------|-----------|
| 订单奖金币 + 定期上缴 + 难度递增 | 钱滚钱体验差 |
| 订单奖票 → 抽特殊池 → 过关道具 | `[待填充：具体为什么？]` |
| 层层递进的特殊池门票 | `[待填充]` |

## 当前设计重点

1. **核心玩法的 bookkeeping 问题** — 必要但体验不佳的簿记劳动掩盖了有乐趣的策略思考
2. **策略空间的可见性** — 核心乐趣对很多玩家不够清晰、不够 accessible；与第 1 点相关但不完全相同
3. **内容扩展性** — 游戏感觉像"小游戏"；缺乏丰富内容和扩展空间；现有玩法做内容扩展不容易
4. **叙事与机制的统一** — 设定需要跟着玩法一起推进
5. **局外系统** — 优先级低于核心玩法迭代，但会影响局内设计
