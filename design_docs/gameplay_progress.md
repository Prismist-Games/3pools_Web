# 玩法设计进度

本文档为 AI agent 和团队成员同步整个项目的全局视角：每个系统的设计意图，团队对游戏中各部分的当前想法.

---
## 核心理念

制作一个轻中度的策略游戏,核心体验是"在随机性面前做出有意义的策略选择".

## 核心决策

玩家面对 4×4 物品矩阵,综合订单需求、背包状态、矩阵布局,选择一行或一列进行抽取（随机获取其中1个物品）。每次选择同时影响当下收益和未来布局。

---

## 系统地图

| 系统       | 设计意图                                      | 备注                                                                                                                                                                                                                                                          |
| -------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **行列选取** | 策略选择的核心载体——玩家面对 4×4 物品矩阵,选择一行或一列抽取 | v3 + 5×5 测试后回到 4×4,进入结构性简化周期(详见「v3 测试后的方向性调整」)。5×5 曾探索的重力掉落+即时补充机制已放弃。行列二重性(同一物品可通过所在行或列接近)是独特的策略维度。 |
| **金币**   | 局内经济系统,代价机制待确定                          | 1. 当前无回合概念,金币消耗方式需要重新设计。<br>2. 我们倾向于将"金币"视为经济货币系统，可能因为它天然带有更强的资源分配感受。我们设想未来让玩家从局外带入金币，也倾向于增加更多局内使用金币的方式。<br>3. 完成撤离任务时重置金币是为了保持每一小轮的张力。<br><br>                                                                                 |
| **物品**   | 物品的独特名字是构成抽奖的核心                           | 1. 当前物品的名称、种类完全是临时的，会跟随设定修改。<br>2. 出于玩法考虑，物品应清晰易读，便于分辨和记忆。<br>3. 我们认为目前的局内物品过于符号化，但完全契合玩法，所以暂时不知道如何修改。<br>4. 除了名字和品质，我们倾向于赋予物品更多属性和特征，但同时对复杂度非常敏感。                                                                                                          |
| ├ 品质     | 强化抽奖乐趣，提供中奖的感觉。名字匹配只是功能性差别，品质提供了奖品稀有程度的差别 | 1. 品质这个属性本身和订单对物品品质提出要求之间不是必然关系，事实上它们不是同时添加的。<br>2. 目前的游玩体验中，我们对品质这个概念感觉良好，之后大概率会保留。<br>3. 但对于品质对玩家的实际意义，我们保留修改空间。现在的设计在当前版本运转良好，但随着核心玩法迭代可能会发生变化。<br>4. 例如，现在订单奖励券，所以品质可以在数值上给订单提供加成；但未来如果奖励物品，可能就要重新设计品质的效果。<br>5. 局内物品的品质应该和订单奖励之间有紧密关系。<br><br><br><br> |
| ├ 工具物品   | 测试"让玩家在背包里对物品进行操作，增加一个交互环节"这种设计的体验        | 1.非常临时的设计,未来机制方向的初步尝试.<br>2.目前玩起来的感觉还不错,我们认为能在物品抽出之后稍微鼓捣鼓捣是符合玩家直觉的一种好玩与满足感.<br>3.但同时我们认为它与核心玩法关系不够紧密，没有提升核心决策的体验，只是一个不错的独立系统，对现在的设计重要性一般。<br>4.未来可能会把这些道具的功能放置在系统中其他模块                                                                                      |
| ├ 合成     | 给玩家提供更多agency,提供合成升级的乐趣,减少获得低品质物品的挫败感.    | 1. 几乎是随着品质直觉性地添加的。<br>2. 感觉良好，暂时不打算更改。<br>3. 曾尝试提高合成的重要性和频率，发现与核心决策相性一般，没有深度参与到核心决策中，所以目前只作为一个不错的机制保留在游戏里。                                                                                                                                                  |
| ├ 回收     | 最初的意图是减少随机抽奖带来的负面体验                       | 1. 回收被设计成止损手段而非赚钱手段，除非在某些特定技能配置下。<br>2. 在游玩过程中，我们发现回收会在绝境下创造出"砸锅卖铁"续命的情况，在那个阶段带来很多"先扔什么"的策略选择，是有趣的游戏体验。<br>                                                                                                                                                 |
| **背包**   | 对玩家进行策略限制，施加压力迫使玩家进行取舍                    | 1.有对于在背包进行一些操作,发生一些交互的想象<br>2.有对于丰富背包格设计的想象                                                                                                                                                                                                                 |
| **普通订单** | 构成玩家抽取的目标和方向,核心玩法中的价值终点                   | 1. 目前"订单"="名字 + 最低品质"的组合。我们认为现在的核心玩法既是由这样的订单定义的，也受这一点的限制而难以扩展。<br>2. 当对核心玩法进行改动时，我们随时准备修改订单的运作方式。                                                                                                                                                           |
| ├ 奖励     | 作为玩家在局内的最终目标——获得更多订单奖励                    | 1. 目前的分数奖励完全是临时的。因为没有局外系统，出于让游戏能完整运行的目的，我们先定了获取高分的游戏目标。<br>2. 之后可能会换成带到局外的物品作为奖励，但还没有确定。                                                                                                                                                                    |
| ├ 品质要求   | 丰富抽奖时的策略考量维度                              | 1. 目前核心决策策略空间的重要构成部分，目前的感觉比较复杂。大量关于订单的簿记工作来源于此，但同时也确实创造出了许多思考空间。<br>2. 当核心玩法迭代时，极有可能会被优化掉，把复杂度释放给其他玩法要素，回到更纯粹的品质加成 / 展示物品稀有度的身份上。                                                                                                                           |
| ├ 关节技    | 鼓励玩家在展开策略时同时考虑多个普通订单                      | 1. 曾尝试移除，因为关节技导致的订单间耦合会促使玩家进入"凑满所有订单所需，然后一波交"的循环，在完成订单的抉择上似乎有些单薄。但实测移除关节技后，整体舒适度大幅下降，所以保留了这个设计。                                                                                                                                                             |
| ├ 刷新与候选  | 通过赋予玩家选择权降低订单随机性带来的负面体验                   | 1. 在一次性完成多个订单时，第一个和第二个订单的选择有点缺乏依据，但不是大问题。<br>2. 是一个和核心决策关系不大，但很好用的机制。<br>                                                                                                                                                                                   |
| **撤离订单** | 提供局内风险/收益张力                               | 1. 在某一次对游戏流程的大幅改动中加入，是最让我们惊喜的收获。我们希望保留这个框架：在无法成功结算、前功尽弃的压力下，进行"物品搜刮（虽然目前是分数）"的局内游戏流程。                                                                                                                                                                       |
| **技能系统** | 提供局内体验变化和progression                      | 1.对构建核心玩法的影响不大,至少目前,我们有别于传统肉鸽游戏,不是强调engine building和synergy的游戏.所以这个系统更像是调料,是带来体验变化的添头,和其他系统关联不大,几乎可以独立考虑.因此,目前迭代核心玩法的测试过程中暂时移除了.<br>2.游玩体验良好.                                                                                                               |
| **时代系统** | 提供局内体验变化                                  | 1.和技能系统类似,属于添头.更像是不同的关卡特征.出于同样原因也暂时移除了.<br>2. 未来类似效果可能会用于关卡选择.                                                                                                                                                                                              |

## 当前设计重点

1. **bookkeeping 问题** — 必要但体验不佳的簿记劳动掩盖了有乐趣的策略思考
2. **策略空间的可见性** — 核心乐趣对很多玩家不够清晰、不够 accessible；与第 1 点相关但不完全相同
3. **内容扩展性** — 游戏感觉像"小游戏"；缺乏丰富内容和扩展空间；现有玩法不易进行内容扩展,也较难带来局内体验变化
4. **局内体验变化** — 单局内体验缺乏变化,尤其是玩家在单局中的决策对同一局内后续的体验影响不大
5. **叙事与机制的统一** — 设定需要跟着玩法一起推进
6. **局外系统缺失** — 优先级低于核心玩法迭代，但会影响局内设计

## v3 测试后的方向性调整(更新至 2026-04-11)

> 本节记录 v3 测试后的设计方向及当前原型实现状态。**很多细节仍在讨论中**,本节只反映已有明确方向/已实施的内容。未决问题单独列出。本节替换了早期版本(2026-04-10)的内容,把多个 session 的讨论整合到一起。

### 整体基调:结构性简化 + 经济层作为宏观策略

游戏的宏观策略定位为**经济运营**(TFT 思路启发,非复刻)。玩家在整场做的主要决策是"**资源怎么分配、什么时候花、攒多少**",这是一个连续的、有时间维度的经济决策链。

矩阵规模从 5×5 探索回到 **4×4**,5×5 的 重力掉落+即时补充 机制已放弃。

---

### 已在原型中实施的(Step 1 + 2 + 3)

**Step 1:剥离预定/赎买,改成直接抽取**
- v1 原型里"抽到局外物品 → 预定 → 攒贴纸 → 赎回"的机制被**彻底推翻**
- 现在抽到局外物品格子 → **直接加入背包**(和抽到贴纸/普通物品走同一条路径)
- 局外物品仍然以普通格子形式出现在墙上(继承 v1 的生成逻辑,30% 墙概率 1-2 个)

**Step 2:抽取需要花金币**
- 每次抽取固定消耗 `DRAW_GOLD_COST = 2` 金币
- 金币不足时抽取被阻止,UI 提示"金币不足",行/列按钮禁用

**Step 3:回合自动发金币 + 起始金币调整**
- 每个新回合开始时自动 `TURN_GOLD_INCOME = 3` 金币
- 起始金币从 v3 的 10 调整到 **15**
- 金币显示升级为琥珀色胶囊 + 变化时 +N/-N 浮现 + 不足时红色脉动

---

### 已明确的设计方向(尚未全部实施)

**墙**
- **纯正向墙:去掉所有负面格子**,包括 v3 中仍存在的**炸弹**
- 抽奖感为核心,避免赌博感
- 玩家处于**建构心态**("这一抽让我之后怎么样"),不是**防御心态**("这一抽会不会害我")

**风险模型**
- **侵蚀型主观风险**替代 v3 的升级型客观风险 ——"世界不变,玩家的抗风险能力随经历下降"
- 风险**不附着在行/列抽取上**,而是在**整体流程的结构性节点**上兑现
- 抽取不直接产生风险,而是通过经济运营**间接影响**玩家在节点上的抗风险能力
- 节点倾向固定位置,具体数量/形态/触发方式待定

**经济层**
- **金币是主要经济资源**(但不排除还有其他)
- **抽取花金币** + **回合自动发钱**(已实施)
- 经济机制采用类别 **1、2、3、4**(类别 5 条件触发 combo 已排除):
  - **类别 1:利息型**——时间维度积累,**不是 TFT 的线性利息**,倾向用主动投资/放弃即收益替代
  - **类别 2:背包触发式物品**——背景被动积累(例"进红色墙时 +1 回收值")
  - **类别 3:兑换/投资**——时间价值转化
  - **类别 4:push/econ 节奏**——金币和抽取次数之间的互换
- **被动收入 + 主动决策**比例平衡
- 抽取花金币让"经济和游戏的核心动作"直接绑定,经济和玩法融为一体

**订单系统重定位**
- 订单不再是"贴纸 → 局外物品"的转化通道
- 分成两类(概念确定,具体机制待定):
  - **成长订单** — 完成后向三选一候选池**添加一面新墙**("一面新墙承载一个成长效果")
  - **撤离订单** — 完成后影响撤离的安全度/可行性
- 成长订单**不互斥**,玩家可以自由选择顺序、放弃任意订单
- 成长订单每场**随机出 4-5 个**,贴纸需求每场随机但**类别对应**

**成长的根本原则**
- **目的:帮玩家接近想要的局外物品**
- **硬约束:不改变行/列选完后的抽取概率**(1/N 神圣不可触碰)
- **允许:改变墙的生成内容、三选一候选墙的构成**
- **不允许:固定生产**(绕过抽取发物品)

**成长墙和 v3 现有墙的关系(未定,暂时"能用就用")**
- 成长墙的具体效果库候选:集群/精品/珍宝/新潮/侦察/丰收/定点/交易/猎手 等(约 14 种候选)
- 和 v3 现有的**即时效果墙**(小金库/金库/大金库/特约订单/优选订单/护盾/逃生口/通行证/刷新/快速通道)**可能存在重叠**
- 当前立场:"**能用就用,存在重叠是 OK 的,之后再具体讨论**"
- 这是一个**待详细讨论的核心问题**,会影响 Step 4 及之后的 scope

**简化基调**
- 这是一次**结构性简化周期**,不是"加机制",是让**机制之间的关系更清晰**

### 已经明确排除的方向

- **预定/赎买机制**(原型 v1 的核心,Step 1 已推翻)
- **TFT 利息的完整复刻**(会产生 robotic 算账行为)
- **凑套 → 升级**(太被动,等 RNG)
- **开拓区域作为成长**(过于显而易见,没思考乐趣)
- **固定生产**(绕过抽取直接发物品)
- **条件触发 combo 经济**(类别 5,想要连续性不是零散爆发)
- **隐藏赎金 → 揭示**(原型 v1 的核心机制,Step 1 淘汰)
- **强制压缩贴纸类型到品类**(新方向下不是必需)

## 揭晓框架(2026-04-12)

本节是 2026-04-12 session 的迭代,在「v3 测试后的方向性调整」基础上**进一步重构玩家行为主线**。核心改动:把玩家的主要行为从"抽取墙格子"扩展为**揭晓 → 评估 → 参与**的三步循环。

### 核心命名(本 session 确定)

为与"电视游戏节目"的叙事主题统一:

| 机制 | 名字 |
|---|---|
| 玩家主要行动 | **揭晓**(reveal)— 花行动点,游戏随机产生一个环节作为可参与选项 |
| 揭晓的产物 | **环节**(segment) |
| 抽奖环节(原抽池) | **奖品墙** — 回归游戏标题《幸运之墙》的核心意象 |
| 危险环节 | **突发状况** |
| 未来扩展 | **特别环节** |
| 威胁累积器 | **风险**(risk)— 替代"威胁" |
| 承受力 | **生命**(lives)— 替代 HP |
| 回合资源 | **行动点**(AP)— 保留 |
| 跨回合战略资源 | **金币** — 保留,用于某些环节的入场费 |
| 类型化收集物 | **印花**(stamps)— 替代"贴纸"(玩家反馈"贴纸"不清楚) |

**注意:** 这些命名尚未落到代码 / UI,代码里依然是旧词(flip/pool/doom/HP/sticker)。需要一次 agent 做统一文本替换。

### 揭晓-参与循环

玩家每回合的典型流程:

1. **揭晓**(花行动点):游戏从所有可能的环节里随机产生一个
2. **评估**:看看揭晓出的是什么(奖品墙 / 突发状况 / 特别环节)
3. **参与 or 跳过**:
   - 奖品墙 → 可选择进入(花行动点 + 入场费),进入后行/列抽取
   - 突发状况 → 立即结算(扣生命或其他资源),无选择
   - 特别环节 → 按类型处理
4. **继续揭晓** 或 **结束回合**(行动点耗尽自动结束)

**关键特征:** 揭晓产生的是"可参与的选项",不是"立刻发生的事"。多个已揭晓的环节可以同时存在(上限 5),玩家决定何时去参与。

### 风险系统结构(设计阶段,未实现)

**核心想法:**

- **风险是一个全局数值**(不是每个池子独立,也不是累积器)
- **风险 = 基线 + 临时修饰**
  - **基线**:主要通过揭晓行为缓慢不可逆地上涨 — 代表"节目越演越戏剧化"
  - **临时修饰**:进入特定环境(某些奖品墙)时加上,离开时消失
- **风险效果**:**风险影响揭晓时产物的类型分布**
  - 风险越高,揭晓出"突发状况"的概率越大
  - 风险**不直接扣生命**,只决定"遇到危险的可能性"
- **生命**是被突发状况消耗的资源

**设计目标(三条):**
1. **环节内退出理由**:在奖品墙里有理由想离开(除了行动点耗尽)— 临时风险让长留在池子里变得更可能揭晓出突发
2. **整局撤离理由**:基线缓慢上升 → 越到后期越危险 → 必须撤离
3. **持续生命威胁(起伏)**:临时修饰的进出产生起伏,不是单调压力上升

**未定的具体细节:**
- 基线每次揭晓的涨幅
- 临时风险的数量和消退方式
- 风险到类型分布的具体曲线
- 玩家间接降低基线的手段
- 突发状况的具体效果

**和之前 agent 提议的"每抽 roll danger check"有本质差别:**
- 旧方案:抽取即 roll,风险概率直接对应 HP loss(每次抽都可能扣血)
- 新方案:抽取本身永远正面,"遇到危险"是通过**揭晓出突发状况**发生,与每次抽取无关
