# 双层结构原型规格

## 整体结构

```
资源层（池子系统）→ 物品 → 消费层（项目系统 + 需求系统）
```

- **资源层**：定义资源如何获取。3池选择 + 货币消耗 + 不确定性。
- **项目系统**（拉力）：提交物品组合建造项目，获得奖励和成长。玩家主动规划。
- **需求系统**（推力）：周期性出现限时需求，不满足有负面后果。被动应对。
- 两个消费系统竞争同一批物品，创造动态权衡。

## 资源层：池子系统

沿用当前核心机制，简化部分规则。

### 池子

- 每回合展示 **3个池子**，各自随机分配一个物品类别和一个词缀
- **5个物品类别**（沿用现有定义）：

| ID | 名称 | 物品 |
|----|------|------|
| fruit | 水果 | 西瓜、柠檬、芒果、苹果 |
| medicine | 药物 | 冲剂、滴眼液、注射器、胶囊 |
| stationery | 文具 | 铅笔、橡皮、订书机、笔记本 |
| kitchenware | 厨具 | 平底锅、菜刀、砧板、汤勺 |
| electronics | 电器 | 手机、耳机、空调、电脑 |

- 每个类别包含 **4种物品**（名字不同，机制上等价）

### 词缀

沿用现有7种词缀，不做修改：

| 词缀 | 费用 | 效果 |
|------|------|------|
| 以旧换新的 | 1 | 用背包内1个物品随机置换1个同品质物品 |
| 硬化的 | 2 | 品质更高，但物品带【绝育】无法合成 |
| 提纯的 | 3 | 保底稀有、史诗或传说 |
| 波动的 | 1 | 只产出普通(90%)或传说(10%) |
| 稀碎的 | 1 | 获得3个物品，但必定普通品质 |
| 精准的 | 2 | 从2个候选物品中选1个 |
| 有的放矢的 | 4 | 指定想要的物品类型 |

### 抽取

- 花费货币从池子中抽取物品
- 每回合可多次抽取（只要有货币和库存空间）
- 抽取结果受词缀影响（品质概率、数量等）
- 硬化词缀产出的物品带【绝育】标记，无法用于合成（但可以直接提交给项目/需求）

### 物品属性

- **名字**：具体物品名（西瓜、铅笔等）
- **类别**：所属池子类别（水果、药物、文具、厨具、电器）
- **品质**：普通 → 优秀 → 稀有 → 史诗 → 传说 → 神话（6级，沿用现有）
- **绝育标记**：部分物品无法合成（来自硬化词缀）

### 库存

- **10格**固定库存
- 同名 + 同品质物品可合成 → 品质+1
- 物品可回收 → 获得少量货币（保底经济手段）

## 消费层 A：项目系统

### 概述

项目是游戏的**成长轴**。完成项目获得奖励、解锁新项目、推进胜利条件。玩家自主决定做什么项目、什么顺序。

### 项目结构

每个项目定义：

```
{
  id: "basic_farm",
  name: "基础农场",
  requires: [
    { category: "fruit", minRarity: "common", count: 2 }
  ],
  rewards: {
    currency: 0,
    currencyPerRound: 2,        // 每回合被动收入
    prosperity: 3,               // 繁荣点（胜利条件）
    unlock: ["greenhouse", "orchard"]  // 解锁新项目
  },
  prerequisite: []               // 前置项目
}
```

### 提交方式

- 玩家从库存选择符合需求的物品，一次性提交
- 提交后物品消失，项目完成，奖励立即生效
- 已完成的项目永久存在，持续产出效果

### 项目树（原型内容）

项目主题为"社区商业街建设" — 用日常物品搭建各种店铺和设施。

| 项目 | 需求 | 奖励 | 解锁 |
|------|------|------|------|
| 水果摊 | 普通水果×2 | +2货币/回合, 3繁荣 | 果汁店, 果品仓库 |
| 诊所 | 普通药物×2 | 需求惩罚减半, 3繁荣 | 药房, 急救站 |
| 文印店 | 普通文具×2 | +2货币/回合, 3繁荣 | 书店, 设计工作室 |
| 小厨房 | 普通厨具×2 | 抽取费用-1, 3繁荣 | 餐厅, 烘焙坊 |
| 维修铺 | 普通电器×2 | 需求奖励+30%, 3繁荣 | 电器城, 回收站 |

### 项目效果精确定义

**经济类效果**：
- `+N货币/回合`：每回合开始时自动获得N货币。多个项目的被动收入叠加。
- `需求奖励+X%`：满足需求时获得的货币乘以(1+X%)。多个此类效果乘法叠加（+30%和+50% = ×1.3×1.5 = ×1.95）。
- `需求惩罚减半`：未满足需求的货币/繁荣惩罚数值减半（向下取整）。

**抽取类效果**：
- `抽取费用-N`：所有池子的抽取费用降低N。最低费用为1（不能免费抽）。多个项目叠加。
- `所有抽取费用减半`：在其他减费效果之后生效，向上取整。最低费用仍为1。
- `XX池品质+1级`：从该类别池子抽取时，所有获得的物品品质提升1级（普通→优秀，优秀→稀有，以此类推）。已达最高品质则不变。
- `XX池额外出1个物品`：从该类别池子抽取时，额外获得1个物品（不额外花费）。受库存空间限制。
- `所有池子品质+1级`：同上，适用于所有类别。与单类别品质提升叠加（即水果池可能+2级）。

**繁荣类效果**：
- `每回合+N繁荣`：每回合开始时自动获得N繁荣点。

### 合成在策略中的角色

合成是获取高品质物品的核心手段：
- 第二层项目需要**优秀**物品 → 合成2个同名普通物品
- 第三层项目需要**稀有**物品 → 合成2个同名优秀物品（即4个同名普通物品的累积）
- 这意味着：专注从同一个池子反复抽取 → 更容易凑齐同名物品 → 更快合成出高品质
- 合成策略和项目路线选择直接相关：走水果路线就需要反复抽水果池来合成优秀/稀有水果

### 项目树策略路线分析

**经济路线**（水果摊/文印店系）：
- 优先建设产出货币的项目（水果摊+2/回合、文印店+2/回合）→ 前期收入高 → 可以频繁抽取 → 后期资源充裕
- 二层走果汁店（+3/回合）或书店（+3/回合）继续叠加收入
- 风险：繁荣增长慢，可能被需求升级压迫

**效率路线**（小厨房系）：
- 优先降低抽取费用（小厨房-1 → 餐厅-2 → 厨艺学校减半）→ 同样货币抽更多次
- 风险：前期无额外收入，依赖需求奖励维持经济

**商业路线**（维修铺系）：
- 优先提升需求奖励（维修铺+30% → 电器城+50% → 科技园翻倍）→ 需求从负担变成主要收入
- 风险：依赖需求生成频率，二层需要跨类别物品（电器+药物）

**防御路线**（诊所系）：
- 优先降低需求惩罚（诊所惩罚减半 → 药房时限+1 → 社区医院惩罚归零）→ 放心忽略部分需求，专注建设
- 风险：不产出额外货币或效率，纯防御性收益

**混合路线**：
- 根据前几回合池子类别的随机性，灵活选择 1-2 条路线
- 通常最可行的策略：这是设计意图——池子随机性引导不同的路线选择

## 消费层 B：需求系统

### 概述

需求是游戏的**生存轴**。周期性出现限时任务，要求提交特定物品。满足得奖励，不满足受惩罚。需求也是**主要的货币来源之一**，不能完全忽视。

### 需求结构

```
{
  type: "food_shortage",
  name: "粮食短缺",
  requires: [
    { category: "fruit", minRarity: "common", count: 2 }
  ],
  timeLimit: 3,                  // 3回合内完成
  reward: { currency: 8 },       // 满足奖励
  penalty: { currency: -5 }      // 未满足惩罚
}
```

### 需求生成

- 第1回合：无需求（给玩家1回合纯建设时间）
- 第2-5回合：每2回合生成1个需求
- 第6-10回合：每2回合生成1个需求，偶尔同时生成2个
- 第11回合起：每回合生成1个需求
- 同时最多存在 **3个活跃需求**（达上限时不生成新的）
- 需求从需求池中随机抽取，物品要求随游戏进程升级

### 需求与池子的关系

需求生成时**不保证**对应类别的池子存在。这是有意设计：
- 3回合时限内，特定类别不出现的概率约6%——足够低，不会经常发生
- 偶尔碰不到 = 可接受的"坏运气"，用惩罚货币抵消，不致命
- 这创造了"库存缓冲"的策略价值：手头囤一些各类别物品，应对未来需求
- 如果测试中发现错配导致体验太差，调节手段：延长时限到4回合，或让需求倾向于近期出现过的池子类别

### 需求池（原型内容）

**基础需求**（前10回合出现）：

| 需求 | 要求 | 时限 | 奖励 | 惩罚 |
|------|------|------|------|------|
| 水果采购 | 普通水果×2 | 3回合 | +8货币 | -5货币 |
| 药品补货 | 普通药物×2 | 3回合 | +8货币 | -5货币 |
| 文具订购 | 普通文具×2 | 3回合 | +8货币 | -5货币 |
| 厨具需求 | 普通厨具×1 | 2回合 | +6货币 | -4货币 |
| 电器维修 | 普通电器×1 | 2回合 | +6货币 | -4货币 |

**进阶需求**（第6回合起混入）：

| 需求 | 要求 | 时限 | 奖励 | 惩罚 |
|------|------|------|------|------|
| 社区聚餐 | 优秀水果×1 + 普通厨具×1 | 3回合 | +12货币 | -8货币 |
| 健康检查 | 优秀药物×1 + 普通电器×1 | 3回合 | +12货币 | -8货币 |
| 办公升级 | 优秀文具×1 + 普通电器×1 | 3回合 | +12货币 | -8货币 |
| 紧急补给 | 任意类别×3 | 2回合 | +10货币 | -8货币 |

**高级需求**（第11回合起混入）：

| 需求 | 要求 | 时限 | 奖励 | 惩罚 |
|------|------|------|------|------|
| 社区晚会 | 优秀水果×1 + 优秀厨具×1 + 普通电器×1 | 3回合 | +18货币, 繁荣+2 | -12货币 |
| 急诊抢救 | 稀有药物×1 + 优秀电器×1 | 3回合 | +18货币, 繁荣+2 | -12货币, 繁荣-3 |
| 批量订单 | 优秀×3（任意类别） | 2回合 | +15货币, 繁荣+1 | -10货币 |

## 经济系统

### 货币来源

| 来源 | 数量 | 说明 |
|------|------|------|
| 满足需求 | 6-18/次 | 主要货币来源 |
| 项目被动收入 | 2-5/回合 | 随建设积累增长 |
| 回收物品 | 1-3/个 | 保底手段（普通1, 优秀2, 稀有3） |

### 货币消耗

| 消耗 | 数量 | 说明 |
|------|------|------|
| 抽取物品 | 1-4/次 | 取决于池子词缀 |
| 需求惩罚 | 4-12/次 | 未满足需求时扣除 |

### 初始状态

- 起始货币：**15**
- 起始库存：空
- 起始项目：第一层5个项目全部可用
- 起始需求：第2回合开始生成

## 游戏流程

### 回合结构

```
1. 回合开始
   - 生成新池子（3个，随机类别+词缀）
   - 检查是否生成新需求
   - 项目被动收入结算

2. 抽取阶段
   - 玩家查看3个池子，决定是否抽取、从哪个池子抽
   - 可多次抽取（货币和库存允许的情况下）

3. 管理阶段
   - 查看库存、可用项目、活跃需求
   - 合成物品（同名同品质 → 品质+1）
   - 回收物品（换少量货币）
   - 提交物品到项目（完成建造）
   - 提交物品到需求（满足需求）

4. 回合结束
   - 需求倒计时-1
   - 到期未满足的需求执行惩罚
   - 检查胜利/失败条件
```

### 胜利条件

繁荣点达到 **40** 即胜利。

繁荣来源：
- 完成项目获得繁荣（3/5/10点不等）
- 部分高级项目每回合产出繁荣
- 部分高级需求满足后给少量繁荣

### 失败条件

货币降到 **0以下** 且库存为空（无法继续游戏）。

## 核心体验目标

### 每局游戏应该感觉不同

- 池子类别随机 → 前几回合能接触到的物品类别不同 → 自然走向不同的项目路线
- 需求随机 → 不同的经济压力节奏
- 项目分支选择 → 不同的成长策略

### 不同时刻应该有不同的决策类型

- **建设窗口**（需求少、货币充裕）：从容规划项目路线，策略性思考
- **应急时刻**（多个需求同时活跃）：用手头物品即兴应对，取舍判断
- **关键抉择**（项目需求和紧急需求竞争同一批物品）：长期投资 vs 短期生存
- **收获期**（多个项目建成，被动收入高）：经济宽裕，可以追求高级项目

### 池子选择应该有多种理由

- "这个池子的物品能完成我的项目" → 建设驱动
- "这个池子的物品能满足紧急需求" → 生存驱动
- "这个池子便宜，我先囤点物品" → 经济驱动
- "这个池子品质好，我去赌一个稀有" → 投机驱动

## 典型游戏弧线（供AI理解节奏）

### 第1回合（探索）
- 15货币，3个随机池子
- 玩家抽3-5次（花5-10货币），获得3-5个普通物品
- 可能已经能完成1个第一层项目（需要2个同类别普通物品）
- 无需求压力，纯粹探索和建设

### 第2-5回合（起步）
- 第一个需求出现，需要应对
- 完成1-2个第一层项目，开始有被动收入（+2-4/回合）
- 开始攒同名物品准备合成优秀品质
- 经济紧张但可控：需求奖励 + 被动收入刚好维持抽取
- 繁荣：6-12/40

### 第6-10回合（发展）
- 需求频率提升，开始出现进阶需求（要优秀物品）
- 第二层项目逐渐可建（需要优秀物品）
- 项目效果开始叠加，经济或效率明显改善
- 核心张力：优秀物品是交给需求还是投入项目？
- 繁荣：15-25/40

### 第11-15回合（冲刺）
- 高级需求出现，压力最大
- 第三层项目需要稀有物品（需要大量合成积累）
- 前期建设的效果此时回报：被动收入高、抽取便宜/品质好
- 繁荣接近目标，每个决策都在"再投资"和"拿繁荣"之间权衡

### 第15-20回合（决胜）
- 完成最后几个高级项目，冲过40繁荣
- 或：如果前期投资不足，此时经济崩溃，需求惩罚不断，艰难求生

### 预计游戏时长
- 15-20回合，每回合1-2分钟 = 约20-35分钟/局

## 平衡参数（可调）

| 参数 | 初始值 | 调节方向 |
|------|--------|---------|
| 起始货币 | 15 | 太难↑ 太易↓ |
| 库存格数 | 10 | 太紧↑ 太松↓ |
| 需求频率 | 每3/2/1回合 | 压力太大→降频 |
| 需求时限 | 2-3回合 | 太紧→延长 |
| 需求惩罚 | 4-12货币 | 太狠→降低 |
| 需求奖励 | 6-18货币 | 经济太紧→提高 |
| 项目被动收入 | 2-5/回合 | 经济太紧→提高 |
| 繁荣目标 | 40 | 太长↓ 太短↑ |
| 回收收益 | 1-3/个 | 经济太紧→提高 |

## 已知风险与待验证项

### 需要通过原型测试验证的

1. **经济平衡**：起始15货币是否足够？被动收入增长曲线是否匹配需求升级曲线？
2. **库存压力**：10格是否足够同时服务项目囤货、需求应对、合成积累？可能是最紧张的资源。
3. **合成节奏**：凑齐4个同名普通物品合成1个稀有需要多少回合？如果太慢，第三层项目会感觉遥不可及。
4. **需求压力感**：需求惩罚是否足够让玩家在意，但不至于感觉被惩罚？轻中度定位需要"有压力但不焦虑"。
5. **项目路线分化**：池子随机性是否真的引导不同路线，还是玩家总能走到同一条最优路线？
6. **游戏长度**：15-20回合是否合适？太短来不及展开策略，太长会拖沓。

### 设计层面的已知局限

1. **项目树是静态的**：每局可用的项目都一样，只是解锁顺序不同。后续可以引入随机项目池（每局只出现部分项目）来增加重玩性。
2. **需求缺乏叙事性**：当前需求是纯机制性的（交物品换货币）。可以通过叙事包装让需求感觉更有意义。
3. **物品名字仍然无差别**：同类别的4种物品机制上等价。如果后续想增加深度，可以让特定项目要求特定名字的物品（不只是类别）。
4. **没有玩家间差异化**：当前是单人体验。如果后续需要，可以通过不同的起始条件或随机项目池来创造"每局不同的角色/身份"。
