# 核心循环的扩展性与体验多样性

## 原始问题

核心玩法感觉封闭，缺乏内容扩展性。加新内容（物品、词缀、订单）很难产生有意义的新玩法变化。

## 分析路径

### 第一层：内容元素缺乏组合性交互

初始判断：物品是纯匹配 token（只有名字+品质），内容元素之间缺乏组合交互。加新元素 = 线性增长，不是指数增长。

尝试的方向及失败原因：
- **物品加属性**（词缀烙印、物品特质）→ 认知负担太高。每个物品多一个维度要追踪，在轻中度策略游戏中不可接受。
- **技能作为修饰层**（类比 Balatro 的 Joker）→ 感觉是外围系统，不属于核心玩法。核心循环本身没有变化。
- **库存组合操作**（结构性合成规则）→ 规则本身增加了池子选择前的认知负担，且扩展性带来的认知增长不可控。

**关键发现**：尝试通过"增加内容元素间的交互"来获得扩展性，在轻中度策略游戏的复杂度预算内可能走不通。交互意味着玩家要理解、记忆、评估——内容越多，负担越重。

### 第二层：单一优化轴

重新审视后发现，问题不在内容数量或交互，而在于所有决策共享同一个优化轴（金币→分数效率）。无论输入变量（池子、词缀、订单）怎么变，玩家的评估方式不变——"怎么把金币最高效地变成分数？"

局面变化感低，不是因为变量少，而是因为无论变量怎么变，解决问题的方式不变。

### 第三层：经济循环是单向管道

追问为什么优化轴单一，发现根源在经济结构：

```
金币 → 物品 → 金币 + 分数（单向流动，一条路径）
```

物品只有一个去处（订单），只有一种转化路径（匹配→得分）。管道结构天然只产生"优化流通效率"一种决策。

在管道内部调整任何节点（丰富物品、改善库存、增加订单类型）都不改变这一本质——只要结构是单向管道，决策类型就不会变。

### 团队的关键输入

- "获得物品→提交物品"这个核心动作不变，可以有并行的提交轴
- 分数作为唯一目标需要替换（或至少需要多条达成路径）
- 抽取物品需要花费货币——经济循环的约束
- 多次拒绝"在管道内部调整"的方案，推动分析跳出管道结构本身
- 指出"扩展性和玩法复杂度无法兼容"的模式——这直接导致了从"内容交互"到"经济结构"的分析转向

## 结构洞察

### 根因链
1. 所有决策共享同一个优化轴（金币→分数效率）
2. 因为物品只有一个去处（订单），只有一种转化路径（匹配→得分）
3. 因为经济循环是单向管道：金币→物品→分数
4. 所以无论内容怎么变，玩家的思考方式不变

### 结构方向
将经济循环从单路径管道改为多路径网络。需要三个结构性质同时成立：

1. **物品有多个去处，回报不可互相折算** — 不同去处给玩家的东西是质性不同的，不能折算成同一标准来比较
2. **至少一条反馈回路** — 某个去处的回报改变了池子/抽取端的体验，创造路径依赖
3. **多条质性不同的转化路径，且不同状态下不同路径占优** — 不需要多个目标，但需要多种达成方式，游戏状态决定哪条路径当前最有价值

关于第3点的重要修正：最初认为需要"多维目标"，但通过反例分析（Balatro、杀戮尖塔、Splendor）发现单维目标完全可以产生丰富体验——关键不是目标维度，而是到达目标的路径多样性。

### 骨架（不变的）
货币 → 从池子抽取 → 获得物品 → 提交物品。

### 扩展性来源
"去处"本身是可扩展的内容层。每个去处由"接受什么物品 + 返回什么"定义，基于物品的结构属性（池子类别、品质、名字）运作。新去处自动和所有已有物品产生交互，新物品自动参与所有已有去处的规则。

## 分析方法回顾

### 使用的分析透镜
- **抽象**：将核心循环抽象为"资源转化管道"，暴露结构本质
- **经验追溯**：从"体验单一"反推到"决策类型单一"再到"优化轴单一"再到"经济结构单向"
- **重构**：从"内容交互不足"重构为"经济结构限制"——问题不在内容层面，在结构层面
- **比较分析**：Balatro、杀戮尖塔、Splendor、围棋——区分"内容多样性"和"局面多样性"，以及"多维目标"和"多路径达成"
- **约束与张力**：识别出"扩展性 vs 认知负担"的根本张力，这直接推动了分析方向的转变

### 关键转折点
1. **从"内容交互"到"经济结构"**：多次方案被否后，识别出认知负担与扩展性的根本张力，意识到问题不在内容层面
2. **从"管道调整"到"跳出管道"**：团队反复指出分析没有跳出当前结构，推动分析从"改善管道"转向"替换管道"
3. **从"多维目标"到"多路径达成"**：通过反例分析修正了对目标结构的认识

### 死胡同
- 给物品加功能性属性（任何形式）→ 认知负担与游戏重量级冲突
- 在管道外加修饰层（技能系统等）→ 不改变核心循环的体验
- 在管道内改善节点（丰富库存操作、增加订单类型）→ 管道结构本身限制了决策类型
- 引擎建造/双重用途→ 方向正确但未跳出管道思维——仍是"给管道加分支"

## 后续步骤

结构方向已确定。下一步设计工作：
- 具体的"去处"有哪些，各自接受什么、返回什么
- 目标的具体形态（替代当前的纯分数累积）
- 反馈回路如何影响池子/抽取端
- 货币系统如何适配多路径网络
