# 批量完成订单后的选择退化

## 原始问题

玩家反馈：订单刷新二选一，单个刷新时还好（有另外两个普通订单作为参考），但一次提交完成多个订单后，面对连续的新订单二选一，感觉不好选。主要是决策负担（连续多个不太有意义的选择），也有信息不足和候选难以区分的成分。问题主要出现在前几个候选选择。

## 关键上下文

- 3个普通订单 + 2个撤离订单同时在场
- 完成订单后，每个空槽生成2个候选订单供选择1个
- 多个订单同时完成时，候选选择按队列依次进行
- 撤离订单持续存在，不会被清空

## 分析路径

### 1. 参考框架的结构

首先确认了二选一的策略性依赖"组合式参考"——其他普通订单构成的需求网络。你的思考方式是"我在攒水果/我需要Rare"，新候选在这个方向上的契合度是判断标准。

### 2. 撤离订单作为参考的局限

初始分析遗漏了撤离订单的参考作用（原因见下方"过程反思"）。纳入后发现：
- 撤离订单提供的是**排除性硬约束**（"和撤离需求撞车的不要"）——简单、直觉、低认知成本
- 更精细的参考（"普通订单要的东西和撤离订单同池不同物"实现资源协同）——玩家反馈认知成本太高、收益不确定，实践中不会用
- 结论：撤离订单能帮排除明显差的候选，但不能在"两个都行"的候选之间建立偏好

### 3. 参考框架的单点依赖

发现核心结构问题：**玩家所有的"方向感"都集中存储在活跃的普通订单组合里。** 批量完成后不仅订单被清空，背包物品也因提交而变稀疏。所有主要参考来源同时被削弱。

### 4. "补充信息"方向的可行性探讨

初始判断"补充信息走不通"（缺的参考正是你正在重建的东西，自引用问题）。

团队追问：如果是新增一种现在不存在的信息呢？分析后发现：如果存在一种**独立于当前订单组合、能持久存在的战略方向源**，就能打破单点依赖。这类信息需要满足：独立于订单更替、能制造候选偏好差异、认知成本低。

### 5. 候选比例作为设计杠杆

分析方向5（候选互为参考/批量展示）时，初始因缩放问题（6选3认知爆炸）和候选相似度问题判定不稳健。

团队追问"比例不一定要2:1"，打开了关键洞察：
- **"选出最好的"需要丰富参考，"淘汰最差的"只需要基本排除标准**
- 撤离订单提供的恰好是排除标准，认知成本低
- 设计为"总是多1个候选来淘汰"：完成1个→2选1（不变），完成2个→3选2（淘汰1），完成3个→4选3（淘汰1）
- 认知任务不随批量大小膨胀
- 候选相似度问题也缓解："都差不多，随便去掉一个"在淘汰任务下是轻松的

### 6. 排除的方向

**时间解耦（推迟选择等参考恢复）**：表面合理，但实际上把问题从"一个无意义的选择时刻"扩散为"好几轮无意义的游戏"。空订单槽意味着抽卡失去方向，核心循环被打断。且恢复的参考（库存）是不同种类的参考，实质上反转了"先有目标再行动"的游戏流程。代价与问题不成比例。

## 最终方向

1. **避免批量清空** — 结构上减少同时完成多个订单的情况
2. **减轻选择负担** — 匹配选择的仪式感与实际策略含量
3. **引入持久方向源** — 让战略方向不完全绑定在当前订单组合上
4. **可变比例的批量淘汰** — 批量完成时多给1个候选，任务从"挑选最好"变为"淘汰最差"，匹配低参考下玩家能做的判断类型

## 过程反思

### 系统边界陷阱

分析初期遗漏了撤离订单作为参考的作用。原因：游戏规则文档按系统边界组织（普通订单和撤离订单分属不同章节），分析时继承了文档的系统划分，没有从玩家视角重建"决策时刻的完整感知场"。

教训：文档按系统组织，玩家按时刻体验。分析玩家决策时，必须跨越系统边界，重建玩家在该时刻能看到、能参考、会想到的一切。这一教训已反馈为对 analyzing-game-mechanic skill 的修改建议（在 Player Perspective 透镜中增加显式警告）。

### 过早排除方向

对"补充信息"方向的初始判断过于绝对——只考虑了现有信息源，没有考虑引入新信息源的可能性。团队追问后才打开了"持久方向源"这个思路。

教训：排除一个方向时，要区分"现有条件下走不通"和"结构上不可能"。前者留有空间，后者才能真正排除。

### 隐含假设限制了方向探索

对方向5的评估受限于"2:1比例"的隐含假设。团队指出比例可变后，方向5从"不稳健"变为了可能最有潜力的方向之一。

教训：评估一个方向时，检查是否有未被质疑的参数假设。方向的核心idea和其具体参数是不同层面的东西——idea可能是好的，只是默认参数有问题。
