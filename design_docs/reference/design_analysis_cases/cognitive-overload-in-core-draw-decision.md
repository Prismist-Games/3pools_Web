# Case: 核心抽奖决策的认知过载

**日期**: 2026-02-27
**类型**: 现有设计问题诊断 (Scenario A)

---

## 原始问题

核心玩法"对照着当前订单，选择一扇门抽东西"需要比对和查看的信息太多，玩起来感觉"过载"、累。希望改善这一点的同时保留核心乐趣。

## 锁定的意图

- **问题本质**：每次抽奖决策之前，信息比对的过程既有"体力活"（扫描、查找），也有"脑力活"（交叉匹配），这些劳动让玩家感到疲惫。
- **核心乐趣**：在随机性中做出策略选择，以及随之而来的抽奖体验本身。
- **关键区分**：乐趣在"做决定的那一刻"和"开门的瞬间"。问题在于"走到那个决定之前的路太长、太累"。

## 分析路径

### 1. 拆解玩家的心理过程

玩家在点击池子之前，需要完成五个步骤：

| 步骤 | 内容 | 性质 |
|------|------|------|
| ① 盘点需求 | 扫描3普通订单+2急单，识别未满足的需求 | 簿记劳动 |
| ② 物品→品类映射 | 回忆20种物品分别属于哪个品类 | 簿记劳动 |
| ③ 供需交叉匹配 | 检查当前3个池子是否包含所需品类 | 簿记劳动 |
| ④ 词缀评估 | 评估每个相关池子的词缀/费用/品质概率 | 策略劳动 |
| ⑤ 多目标权衡 | 综合金币、背包空间、合成、订单优先级做决定 | 策略劳动 |

### 2. 核心发现：两种劳动混在一起

- **信息检索劳动**（①②③）：纯粹的簿记工作，没有乐趣，是"必须做的功课"
- **策略评估劳动**（④⑤）：权衡取舍、在不确定性中做判断——核心乐趣所在

玩家必须穿越三层簿记劳动，才能到达真正有趣的策略区域。每次池子刷新后都要重新做一遍。

### 3. 抽象层级的错位

- 订单用的是**具体物品**："西瓜🍉 稀有品质"
- 池子用的是**品类**："水果池🍎"

玩家必须在两个抽象层级之间反复跳跃（物品→品类→池子），这本质上是查表操作，不是策略思考。

### 4. 词缀的叠加效应

词缀本身有策略深度，但必须建立在"已知道池子和需求是否相关"的基础上。当簿记步骤已经让玩家疲惫时，词缀从"有趣的策略维度"变成了"又一层要处理的信息"。

## 结论

**根因**：游戏把"簿记劳动"和"策略劳动"绑定在一起，作为同一个不可分割的心智任务交给了玩家。信息检索的负担淹没了策略选择的乐趣。

## 方向

四个结构性杠杆（可组合使用）：

1. **让游戏来做匹配**（杠杆1）：改变信息呈现方式，把供需匹配结果直接展示给玩家。保留所有机制，风险是可能让决策变得"无脑"。
2. **减少比对数量**（杠杆2）：更少的订单/池子/需求项。直接但可能让游戏"变薄"。
3. **拆分复合决策**（杠杆3）：将"为哪个订单努力"和"哪个池子最优"拆成两个显式的先后决策。可能更根本地解决问题，但限制了"一石二鸟"的灵活性。
4. **对齐抽象层级**（杠杆4）：让池子展示具体物品，或让订单以品类为单位。

核心取舍：保持机制不变优化信息呈现（杠杆1、4，较安全）vs 调整决策结构本身（杠杆2、3，更深入）。

## 未解决的问题

- 当匹配关系透明后，词缀选择和资源管理是否仍能提供足够策略深度？
- 5个订单中有多少真正参与了玩家决策？削减是否有实际损失？
- "一石二鸟"的操作感是否是核心体验的一部分？
