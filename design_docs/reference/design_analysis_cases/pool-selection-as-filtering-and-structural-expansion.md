# Case: 池子选择的本质是筛选，以及量变与质变的区分

**日期**: 2026-03-17
**类型**: 核心玩法本质理解 / 设计框架

---

## 原始问题

在讨论如何为物品添加新属性（词条效果）以及如何让这些属性与词缀互动时，团队对游戏核心玩法的根本结构产生了更深层的理解：池子选择到底是什么？词缀和类型到底在做什么？新增的任何设计，本质上在改变什么？

## 分析路径

### 第一层：池子选择的本质是筛选

游戏存在一个"大表"——所有可能出现的物品的全集。当前是 20个名字 × 6种品质 = 120种可能的物品。

每个池子是这个大表的一个**筛选后的子集**，附带特定的概率分布。玩家面对3个池子做选择，本质上是在3个不同的筛选结果之间做选择。

池子的**类型**是一种筛选器——"水果池"意味着"只出水果类名字的物品"，把20个名字筛到4-5个。

池子的**词缀**是另一种筛选器——影响品质分布、改变概率权重、可能移除某些品质档位。

**关键认识：类型和词缀在结构上是同一种东西。** 它们都是对大表施加的筛选条件（filter），定义了"池子里有什么"和"各自的概率是多少"。类型筛选名字维度，词缀筛选品质维度（以及可能的其他维度）。如果把类型也视为一种词缀，它的效果就是"只出某个名字子集"。

### 第二层：玩家思考的不可约简核心

不管表面机制如何复杂——多少种词缀、多少种类型、多少种额外属性——玩家在池子选择时的心智活动归根结底是：

1. **我需要什么？**（由订单和当前状态决定）
2. **这个池子里有什么？概率怎样？**（由池子上的所有筛选条件共同决定）
3. **花这些钱划不划算？**（经济评估）

这三个问题是核心抽奖策略的不可约简形式。所有关于"怎么抽比较合适"的策略思考，最终都在回答这三个问题。

### 第三层：新属性 = 大表的新列

当我们给物品添加新属性（比如词条效果），本质上是在大表里加了新的列。如果有5种词条效果，可能性空间从 20×6=120 变成 20×6×5=600。

然后我们需要新的筛选器来帮助玩家在这个扩大的空间中定向——这就是"面向新属性的词缀"的需求来源。一个"只出火焰词条"的词缀，本质上和"只出水果"的类型词缀做的是同一件事：在某个维度上缩小子集。

**这意味着：给物品加属性 + 加对应的筛选器 = 在现有结构内做量变扩展。** 策略空间更大了，但玩家在做的事情（评估筛选后的子集 vs 需求 vs 成本）没有改变。

### 第四层：量变与质变的区分

- **量变**：在大表中增加新列（新属性），增加新的筛选器（新词缀），增加"我需要什么"的考量维度（新的需求来源）。池子选择的决策更丰富，但结构不变。

- **质变**：增加一个在"抽取"和"提交"之间的新游戏阶段（如加工过程）。这不是大表的新列或新筛选器——它是一种全新的玩家活动，用抽取的输出作为输入，产生新的输出。

两者不互斥，而且自然互相喂养：
- 加工过程需要物品有特定属性 → 这些属性成为大表的新列（量变）
- 新列需要新的筛选器 → 池子选择变丰富（量变）
- 但加工过程本身是新的决策类型（质变）

### 第五层：词缀的设计定位

在理解了"一切都是筛选器"之后，词缀的设计定位变得清晰：

**词缀更靠近核心玩法的前端。** 当前的策略深度主要来自词缀对品质检索能力的差异，以及这些差异与订单需求的联动。词缀直接影响"这一抽的策略思考"——它们是策略抽奖中"策略"部分的主要载体。

**类型池更靠近名字匹配。** 类型池的选择已经被"订单对名字的需求"所驱动。玩家看类型时，想的是"里面有没有我要的名字"。

这两者现在是分工的：
- 类型 → 名字维度的筛选 → 服务于订单的名字匹配
- 词缀 → 品质/概率维度的筛选 → 服务于策略效率评估

当引入新属性时，新的筛选器放在哪里（类型侧 vs 词缀侧），决定了玩家的注意力被引导到哪里。

## 结构洞察

### 核心框架

```
大表 = 所有可能物品的全集（每个属性是一列）
池子 = 大表的一个筛选子集 + 概率分布
类型/词缀 = 筛选器（本质等价，只是筛选不同的列）
池子选择 = 玩家在3个筛选子集之间，基于需求和成本做选择
```

### 设计启示

1. **加新属性+新筛选器 = 量变**：不改变玩家活动的本质，但扩大策略空间。有边际递减的风险——每多一个维度，玩家需要同时考虑的因素增加，可能重回认知过载问题。

2. **加新游戏阶段 = 质变**：改变玩家活动的种类。但新阶段和池子选择之间需要有信息回流——加工需求影响抽取需求，形成正交的拉力。

3. **筛选器的位置决定注意力引导**：一个新筛选器被设计成"类型"还是"词缀"，影响玩家在做选择时的认知路径。词缀位置更显著，更靠近"我在策略地选择这一抽"的体验。

4. **量变不是贬义**：当前游戏只有两列（名字、品质）和两种筛选器（类型、词缀），策略空间确实有限。适度的量变是必要的。关键是知道自己在做量变还是质变，不要误以为量变是质变。

### 与此前分析的关系

- **核心循环扩展性案例**指出经济结构是单向管道，需要多路径网络。本案例进一步揭示：在管道内部，池子选择本身也有结构性限制——所有改动最终都是"筛选器的变体"。
- **认知过载案例**指出簿记劳动和策略劳动的混合。本案例暗示：每增加一个筛选维度，都在增加簿记劳动（又多一个维度要比对）。量变扩展必须谨慎控制维度数量。

## 方向

在推进具体设计时，遵循以下顺序：

1. **先设计加工过程**（质变）——确定玩家抽到物品后"做什么"
2. **再反推物品属性**（量变）——加工过程需要物品携带什么信息
3. **再设计筛选器**（量变）——这些新属性如何被筛选器覆盖
4. **最后决定筛选器的位置**——放在类型侧还是词缀侧，取决于想引导玩家注意什么

## 未解决的问题

- 当前两个维度（名字×品质）配两种筛选器（类型×词缀）已经产生了认知过载。增加到三个维度时，如何控制认知负担？
- 量变扩展的上限在哪里？三个筛选维度是否已经是轻中度策略游戏的天花板？
- 加工过程（质变）和池子选择（量变）之间的信息回流应该是什么强度？太弱则正交性不足，太强则又回到认知过载。
