# 桌游调研：多人独立随机输入 + 争夺式 Set Collection

最后更新：2026-05-08

## 研究问题

我们要找的不是“有抽奖”或“有收集”的桌游，而是结构上接近当前《幸运之墙》LAN 多人原型的游戏：

- 玩家彼此竞争。
- 每名玩家有自己的随机输入或抽取结果。
- 玩家用获得的资源/物品完成集合、订单、合约或目标。
- 目标存在争夺关系：别人先完成会改变我的计划。
- 决策重点不是单纯碰运气，而是在随机性前后做资源配置、目标选择、风险判断。

结论先说：我没有找到一个完全同构的桌游。最接近的结构是几个游戏的交叉：

- 《The Quacks of Quedlinburg》和《Cubitos》提供“每人独立随机输入、同时/近同时开奖”的参考。
- 《Augustus / Via Magica》提供“公共目标、随机叫号、多人同时推进并抢完成时机”的参考。
- 《Potion Explosion》《Project L》《Century: Spice Road》《Ticket to Ride》《Splendor》提供“收集资源完成共享市场目标”的参考。

我们当前原型的独特点在于：所有人面对同一组公开订单，但订单不是被提前拿走成为私人任务，而是保持在公共区，直到某人用自己的背包物品完成它。这一点在桌游里并不常见。

## 1. 筛选维度

我用下面几个维度判断相似度：

| 维度 | 对当前游戏的重要性 | 说明 |
| --- | --- | --- |
| 随机输入是否个人化 | 高 | 我抽到什么不影响你抽到什么，但我们会比较结果 |
| 目标是否共享并可被抢 | 高 | 一个订单被完成后，其他人的计划被改变 |
| 资源是否进入私人库存 | 高 | 背包是中间状态，不是抽到即得分 |
| 玩家是否能读别人进度 | 高 | 公开背包让竞争可判断 |
| 决策是否发生在随机前 | 高 | 选择哪个池子，是随机前的战略判断 |
| 决策是否发生在随机后 | 中 | 合成、回收、提交订单是随机后的整理判断 |
| 是否同时行动 | 中 | 影响节奏与信息泄露 |
| 是否有自然终局资源 | 中 | 当前游戏用金币耗尽作为结束结构 |

## 3. 深入案例

### 3.1 The Quacks of Quedlinburg

规则摘要：

《Quacks》是 2-4 人袋构筑 + push-your-luck 游戏。每名玩家有自己的袋子和锅。回合中，玩家从自己的袋子里一片一片抽成分放入锅中；抽出的白色爆炸成分总值超过 7 时锅会爆炸并停止。玩家可以随时选择停手。结算时根据锅推进距离获得分数和购买力，爆炸玩家要在分数与购买新成分之间二选一。游戏共 9 回合。

玩家决策情景：

中盘时，我的袋子里已经有几个高价值成分，也有不少白色爆炸片。当前锅已经走到一个不错的位置，继续抽可能让我多拿 4-5 个购买币，但也可能爆炸，导致我这回合只能拿分或买料之一。我会看领先玩家本回合推进到哪里，判断是否需要冒险追赶；也会考虑自己的袋子构成，比如我刚抽出了哪些白片，袋里还剩多少危险。

与当前游戏的相似点：

- 每个人的随机输入是个人化的。
- 玩家同时或近同时操作，开奖/抽出结果公开。
- 结果既带来即时收益，也影响后续构筑。
- 推运气产生强烈观战性：别人继续抽时，全桌都知道他在冒险。

关键差异：

- 《Quacks》没有共享订单，也没有“别人先完成导致我的目标消失”。
- 主要决策是“继续抽还是停”，不是“从三个公共池中选择哪一个”。
- 购买阶段是公开供应，但不是当前回合的主要争夺目标。

对我们的启发：

《Quacks》证明“个人随机输入 + 公开结果 + 同时推进”可以很有桌面感。它的 catch-up 机制、爆炸惩罚和 9 回合固定长度也说明，高随机游戏需要清晰的节奏护栏。我们的多人版目前用金币耗尽做终局，若局长不稳定，可以考虑固定轮数或更明确的行动寿命。

https://www.schmidtspiele.de/files/Retail/72dpi_PNG/88220_Quack_rules_english_2024.pdf

### 3.2 Cubitos

规则摘要：

《Cubitos》是骰池构筑 + 竞速游戏。每轮所有玩家先同时进行 Roll Phase：从自己的 Draw Zone 抽骰到 Roll Zone，掷骰，命中结果进入 Active Zone，然后选择继续 push 还是 pass。若在有爆掉风险时全是 miss，就会 bust。之后进入 Run Phase，玩家使用骰子能力、获得资源、购买新骰、在赛道上移动。

玩家决策情景：

我这轮已经有 4 个骰进入 Active Zone，其中有足够的钱买一个强骰，但移动力不够。如果继续掷，可能多拿到移动符号抢一个赛道奖励，也可能 bust 导致本轮收入大幅缩水。我还会看对手是否快到终点，判断是买骰提升长期能力，还是牺牲构筑去冲刺。

与当前游戏的相似点：

- 每名玩家拥有自己的随机生成器。
- Roll Phase 同时进行，节奏适合多人。
- push/pass 选择会让别人观看我的风险承担。
- 公开结果会形成比较：“你这轮开得太好了”。

关键差异：

- 《Cubitos》的竞争主要在赛道和市场骰构筑，不是共享订单。
- 玩家随机前的选择是骰池构筑和是否 push，不是三选一奖池。
- 没有背包式物品集合与订单提交。

对我们的启发：

《Cubitos》把“同时随机 + 之后处理结果”拆成明确阶段，避免玩家一直等别人。我们的“待处理物品不阻塞其他玩家”是同一类节奏判断。未来如果多人版出现等待感，应优先保持个人处理与全局回合解耦。

来源：Cubitos Rulebook PDF  
https://cdn.1j1ju.com/medias/3c/ae/87-cubitos-rulebook.pdf

### 3.3 Augustus / Via Magica

规则摘要：

《Augustus》是类似 Bingo 的目标竞速游戏。桌面有 5 个可选目标，玩家面前持有若干目标卡。每次从袋中抽出一个 mobilization token，所有玩家都可以在自己目标上放置或移动对应类型的标记。目标被填满时，玩家喊出完成，执行目标奖励，把目标移入得分区，并从公共展示中选择一个新目标补到自己面前。如果多人同时完成，按目标编号从低到高处理。

《Via Magica》是同一核心系统的再主题版本，整体更家庭向。

玩家决策情景：

我面前有三个目标：一个容易完成但分低，一个需要稀有符号但奖励强，一个和对手争同类奖励。每次符号被叫出时，我要决定把标记放在哪张目标上。若我快完成低分目标，我可以抢先拿新目标；但如果把资源投入高分目标，可能被别人先拿走公共展示中最适合我的下一张目标。

与当前游戏的相似点：

- 公共目标展示会被完成者刷新。
- 玩家可以通过别人目标上的标记读出进度。
- 多人可能同时接近目标，形成抢完成时机。
- 完成目标后立即补新目标，市场持续流动。

关键差异：

- 随机源是全局共享叫号，所有人响应同一个符号。
- 目标通常先被玩家拿到自己面前，再成为私人目标；我们当前订单留在公共区，任何人可直接完成。
- 没有背包容量、回收、合成等中间库存操作。

对我们的启发：

这是最接近“共享目标争夺”的参考。它特别提醒我们：当多人可能同时完成目标时，规则必须有清楚仲裁。当前多人版用服务器先到先得处理订单提交，这在技术上简单，但体验上可能不如《Augustus》的编号顺序或显式同时结算稳定。

https://www.goblins.net/files/downloads/Augustus%20Eng.pdf  
Via Magica 资料页  
https://www.thebigbanggames.com/producto/via-magica/

### 3.4 Potion Explosion

规则摘要：

《Potion Explosion》中，玩家从共享弹珠轨道拿一个成分弹珠。如果移除后同色弹珠相撞，会发生爆炸，玩家获得整组同色弹珠，并可能连锁爆炸。玩家把获得的弹珠放到自己的药水配方上。药水配方填满后完成得分，并可作为一次性能力使用。完成同类或不同类药水组合会获得 Skill token；达到指定数量后触发终局。

玩家决策情景：

轮到我时，轨道上有一个蓝色弹珠可以触发两段爆炸，给我大量蓝色和红色；但我当前配方最缺的是黑色。如果我拿高爆炸收益，可以填一些未来配方，但可能让下家拿到他正缺的黑色连锁。我还要考虑是否使用已完成药水能力改变轨道，抢在别人前完成一组同类药水拿 Skill token。

与当前游戏的相似点：

- 玩家收集具体资源来填订单/配方。
- 配方市场和 Skill token 形成争夺。
- 完成配方后进入个人得分区，市场继续推进。
- 资源和目标都非常可视化。

关键差异：

- 随机性集中在共享弹珠轨道的空间状态，不是个人独立抽奖。
- 玩家拿资源是轮流行动，不是同时开奖。
- 获得的弹珠通常直接进入配方孔位，背包式中间管理较弱。

对我们的启发：

《Potion Explosion》的强项是“我拿什么”与“我给下家留下什么”合在同一个动作里。我们的游戏目前抽奖互不影响，互动主要通过共享订单发生。如果实测觉得玩家之间还是太各玩各的，可以考虑未来让奖池选择轻微影响公共订单、公共池状态，或给下家留下机会成本。

https://horribleguild.com/us/product/potion-explosion/

### 3.5 Project L

规则摘要：

《Project L》是公开拼图市场 + 私人拼块库存游戏。玩家每回合执行 3 个动作：拿拼图、刷新一行拼图、升级拼块、放置拼块、或执行一次 Master 动作。完成拼图后，玩家收回放在上面的拼块，获得新拼块奖励，并把拼图收为分数。

玩家决策情景：

我有 3 个未完成拼图，其中一个只差一块就能完成并给我一个关键高级拼块。公共市场上出现了一个非常适合我当前拼块结构的黑色高分拼图，但拿它会占用我的未完成拼图上限。此时我要决定：先完成低分拼图滚动引擎，还是抢高分拼图防止别人拿走。

与当前游戏的相似点：

- 私人库存是核心中间状态。
- 公共目标市场可被别人拿走。
- 完成目标后获得奖励并腾出空间。
- “我当前库存适合哪个公共目标”是主要判断。

关键差异：

- 几乎没有随机抽取；市场随机翻出，但行动本身确定。
- 目标被拿走后成为个人拼图，不是一直公共可提交。
- 决策偏动作经济和空间拼合，不是抽奖概率。

对我们的启发：

《Project L》说明，公开目标市场要配合“个人容量限制”才会产生取舍。我们当前背包是容量限制，但订单没有持有上限，因为订单完全共享。若未来共享订单过于混乱，可以研究“玩家可临时锁定/认领少量订单”的中间形态，但这会削弱抢单张力。

https://cdn.1j1ju.com/medias/82/ee/c6-project-l-rulebook.pdf

### 3.6 Century: Spice Road

规则摘要：

《Century: Spice Road》中，玩家用手牌生产、升级、交换香料方块，然后用香料兑换公开的分数卡。分数卡从一排公开市场中获取，先拿的人可能获得金币/银币奖励。玩家还可以购买新的商人牌来改善自己的资源转换引擎。

玩家决策情景：

我当前可以通过两张牌把黄色香料换成绿色，下一轮就能拿到一张 14 分订单。但市场最左边的 11 分订单带金币奖励，另一个玩家已经明显拥有足够资源。我要决定是否先拿较低分但有奖励的订单，还是继续优化资源等更高分；同时也要考虑买一张新转换牌是不是比立刻拿分更划算。

与当前游戏的相似点：

- 私人资源用于完成公开订单。
- 公开订单被别人先拿会改变我的计划。
- 资源转换效率决定能否抢到目标。

关键差异：

- 随机性很弱，更像开放信息经济优化。
- 没有个人抽奖、开奖惊喜和背包满处理。
- 订单通常是“资源颜色数量”，不是具体物品名称 + 品质。

对我们的启发：

《Century》证明共享订单争夺可以靠纯经济节奏成立。但它也提示一个风险：当信息完全公开且随机性低，游戏会变成算步数。我们的随机奖池能降低纯计算压力，但 UI 必须把关键匹配关系显示清楚，否则玩家会只感到乱。

### 3.7 Ticket to Ride

规则摘要：

《Ticket to Ride》中，玩家抽取火车牌形成颜色集合，用同色牌一次性声明地图路线。玩家还持有目的地票，若自己的路线网络连接票上的两个城市，游戏结束时得分；未完成则扣分。地图路线是共享且会被占用，别人先占路线会迫使我绕路或放弃某些票。

玩家决策情景：

我需要完成洛杉矶到芝加哥的票，手里已经有 5 张橙色牌，可以下回合占关键路线。但如果我现在继续抽牌凑更长路线，别人可能先堵住中部枢纽。另一方面，如果我过早暴露路线方向，对手可能判断我的票。我的核心选择是在“收集更多资源”和“先占不可替代的公共空间”之间权衡。

与当前游戏的相似点：

- 抽牌形成集合，再用集合完成目标。
- 共享空间被别人先拿会改变计划。
- 玩家会通过公开行为推断别人目标。

关键差异：

- 目标票多为隐藏，不是共享公开订单。
- 争夺发生在地图路线，不是订单卡。
- 抽牌是轮流从公开/隐藏牌池拿，不是每人独立奖池开奖。

对我们的启发：

《Ticket to Ride》的互动不靠抢同一张订单，而靠“公共执行空间”。这指出一个可能的未来方向：如果共享订单的抢夺过于直接，可以把竞争转移到“完成订单所需的中间公共资源/位置”，让玩家不是抢最后一击，而是在过程中互相挤压。

### 3.8 Splendor

规则摘要：

《Splendor》中，玩家拿宝石筹码购买公开的发展卡。买到的发展卡既提供分数，也提供永久折扣，让之后购买同色卡更容易。桌面还有贵族目标，只要玩家发展卡颜色数量满足条件，就可在回合末拿取贵族。任意玩家达到 15 分触发终局。

玩家决策情景：

公共市场上有一张便宜蓝卡正好能让我达成贵族条件，但它本身没分。另一张高分卡需要我多拿两轮资源。对手已经有足够折扣，也可能下一轮买走蓝卡。我要决定是先抢关键折扣/贵族路径，还是追求更高即时分。

与当前游戏的相似点：

- 公开市场目标会被买走。
- 玩家资源公开，别人能判断我是否快达成目标。
- 贵族目标类似公共条件奖励。

关键差异：

- 抽象经济为主，随机性只来自市场翻牌。
- 没有个人抽奖和背包空间压力。
- 玩家购买卡后形成永久引擎，而不是消耗物品完成订单。

对我们的启发：

《Splendor》的可读性非常强：资源颜色、卡牌成本、贵族条件都摆在桌面上。我们的订单如果要承载多人竞争，也必须达到类似可读性：玩家一眼知道谁差什么、哪个池子能补什么、品质是否够。

来源：Space Cowboys 产品页与规则 PDF  
https://www.spacecowboys.fr/splendor/files/splendor_rules.pdf  
https://www.spacecowboys.fr/_files/ugd/59baa2_19b4a6d45b1c403caa7b2b2bfe41370f.pdf

### 3.9 Dice Forge

规则摘要：

《Dice Forge》中，玩家每轮掷自己的两颗可改造骰子获得金币、太阳碎片、月亮碎片和荣耀点。玩家可以花金币购买新骰面，把旧骰面替换掉；也可以花资源执行英勇壮举，拿取共享卡牌。所有玩家在主动玩家回合开始时都会获得一次掷骰收益。

玩家决策情景：

我可以花金币改造骰子，让之后每次祝福更稳定产出太阳碎片；也可以马上花资源拿一张高分英勇壮举卡。若别人也在攒同一种资源，某个卡堆可能会被拿空。我需要在长期随机生成器质量和短期抢卡之间取舍。

与当前游戏的相似点：

- 玩家拥有自己的随机生成器。
- 结果公开，并转化为私人资源。
- 共享市场卡会被拿走。

关键差异：

- 随机前选择主要是改造骰子，不是选择本轮抽哪个池。
- 资源抽象为货币，不是具体物品集合。
- 没有订单需求的“名称 + 品质”匹配。

对我们的启发：

《Dice Forge》的关键价值是“玩家能改造自己的随机分布”。我们当前词缀只影响单次抽奖，不形成长期生成器。若未来希望增加局内成长，可以考虑让玩家改变自己偏好的池子、奖池权重或品质倾向，但这会把游戏推向 engine-building，需要谨慎。

来源：Dice Forge Rulebook PDF  
https://cdn.1j1ju.com/medias/9a/b4/2f-dice-forge-rulebook.pdf

### 3.10 Spots

规则摘要：

《Spots》中，玩家通过执行 trick tile 掷骰，把骰子放到自己狗卡上对应点数的位置。无法或不想放置的骰子会埋到 yard 中；埋下的骰子点数总和过高会 bust，导致狗卡上和 yard 中的骰子被清空。玩家也可以选择 score dogs，把已填满的狗卡翻面计分。完成 6 张狗卡触发胜利。

玩家决策情景：

我有两张狗卡快完成，但 yard 里已经埋了高点数骰子。如果继续做高收益 trick，可能填上最后几个点数，也可能 bust 前功尽弃。我有一枚 treat 可以重掷，但用掉后下轮更危险。我的选择是在“抢完成速度”和“保住已有进度”之间摇摆。

与当前游戏的相似点：

- 随机骰子结果用于填具体目标槽位。
- 玩家有随机后的放置/止损选择。
- 公开进度让别人能看到谁快完成。

关键差异：

- 目标主要是个人持有，不是公共订单。
- 没有共享池三选一。
- 竞争更偏竞速，较少直接抢同一目标。

对我们的启发：

《Spots》说明“随机结果不能用时必须处理废料/风险”可以很好玩。我们的背包满处理和回收承担类似功能：抽到不合适的东西不能直接消失，而是制造一次取舍。多人版保留回收和替换是正确的。

## 4. 综合判断

### 最接近我们的不是某一个游戏，而是一个组合

当前《幸运之墙》多人版可以拆成三个结构层：

1. 随机输入层：像《Quacks》《Cubitos》，每个玩家有自己的运气展开。
2. 目标争夺层：像《Augustus》《Potion Explosion》《Project L》《Century》，公共目标被完成/拿走后刷新。
3. 库存管理层：像《Project L》《Potion Explosion》《Spots》，随机结果进入个人中间区，需要整理、取舍、转化。

市面桌游通常只强其中两层。我们的原型试图把三层叠在一起，这是它有独特性的地方，也是复杂度风险所在。

### 当前设计最有价值的差异点

公开共享订单不被提前认领，直到最后提交都对所有人开放。这会产生一种很直接的“我看见你快完成了，所以我要不要抢/阻止/改目标”的张力。桌游里更常见的是先 draft 目标变成私人任务，或者争夺地图空间；我们这个公共订单模型更像实时共享悬赏板。

### 当前最大风险

如果订单提交是“任何时候点按钮”，共享订单争夺可能滑向手速和界面操作，而不是前几轮抽奖规划。这个风险在桌游中通常通过回合顺序、同时完成仲裁、目标编号、或明确行动阶段来解决。第一版可以继续用服务器先到先得，但测试时要专门观察玩家是否觉得被 UI 抢走，而不是被策略击败。

### 另一个风险：信息量

4 人局时，玩家需要读：

- 3 个共享订单；
- 3 个共享奖池；
- 自己 10 格背包；
- 另外最多 30 格他人背包；
- 每个人金币和是否快淘汰。

这比很多家庭/轻中度桌游的信息面更重。因此订单匹配角标、hover 高亮、胶囊需求展示不是可选润色，而是多人版成立的前提。

## 5. 对当前原型的设计建议

这些不是立即要做的功能，而是基于桌游调研得到的观察点。

### 建议 1：继续保护同时开奖的纯度

《Quacks》和《Cubitos》都说明，个人随机结果在多人中好看，前提是开奖阶段干净、公开、有仪式感。我们已经把交互词缀选择隐藏，并把金币扣除延后到开奖，这是对的。

### 建议 2：测试“订单提交窗口”是否必要

如果测试中出现明显抢按钮体验，可以尝试三种轻量方案：

- 只有在自己未 ready 时能提交订单，已经选择奖池等待开奖时不能提交；当前已是这样。
- 在每轮开始时提供短暂“订单提交阶段”，同时提交后按规则仲裁。
- 给订单加“锁定/预约”动作，但这会改变共享订单的开放性，需谨慎。

### 建议 3：保持他人背包可读，但控制视觉密度

桌游里公开信息通常依赖实体摆放自然分区。网页没有这种天然空间感，所以自己的背包应该永远是主操作区，他人背包保持较小但信息完整。当前布局方向是对的。

### 建议 4：不要急着引入技能/引擎构筑

《Dice Forge》《Cubitos》《Splendor》都显示，引擎构筑会迅速成为主体验。我们的核心还在“抽哪个池 + 抢哪个订单”，如果太早加入长期构筑，可能会把设计带偏。

### 建议 5：关注落后玩家的观看体验

《Quacks》用 rat tails 做追赶，《Ticket to Ride》用隐藏票让落后不完全透明，《Cubitos》用赛道奖励和爆发骰保持悬念。我们的玩家一旦停止抽奖，目前只能看别人继续。如果淘汰时间差过大，需要加入低成本的旁观参与、结算加速、或更紧的金币/轮数结构。
