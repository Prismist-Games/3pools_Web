## 游戏概述

这是一款资源管理策略游戏。玩家面对一个 4×4 的物品矩阵，通过选择一行或一列来随机获取其中的一个格子。矩阵中除了普通物品外，还有厄运相关的特殊物品。被取走的格子从矩阵中移除，上方物品因重力下落，空缺位置由随机新格子补充。玩家将获得的物品放入背包，最终带着背包中的物品撤离。厄运系统持续制造升级的威胁，玩家随时可以选择撤离——核心张力在于"再抽一次拿更多东西"还是"现在就跑"。

## 核心资源

### 生命值 (HP)

- **初始生命值**: 3
- **用途**: 生命值是存活指标。厄运系统的"危险"效果会扣除生命值。
- **生命值归零**: 游戏结束 → 随机失去背包中一半物品，带着剩余物品撤离

## 物品系统

> **当前状态：大幅简化中。** 物品池（奖池）和品质（稀有度）系统已从当前原型中移除。物品的种类、属性和局内用途待重新设计。

### 物品

物品是玩家从网格中抽取的核心资源。每个物品有一个**名称**和**图标**。

> **待定**: 物品的具体种类、数量、分类方式尚未确定。旧的5池×4物品（共20种）结构和6级品质系统已移除，不再作为设计基础。

### 物品属性

每个物品实例具有以下属性：

- **name**: 物品名称
- **icon**: 物品图标
- **uid**: 唯一标识符

> **已移除**: 物品池（poolId）、品质等级（rarity）、合成系统（merge）、绝育标记（sterile）均已从当前原型中移除。

### 物品的局内用途（设计方向）

物品在局内不只是被动的收藏品，还应作为**活跃的局内资源**：

- **带出局外**: 撤离时带走，供 meta-game 使用（主要价值）
- **回收/消耗**: 在局内消耗物品以获取某种收益（如金币、能力等）——具体机制待设计
- **应对挑战**: 使用物品解决局内出现的问题/挑战——具体机制待设计

> **设计原则**: 每个物品都应有价值——想要的物品有带走价值，不想要的物品有局内消耗价值。不存在"无用物品"。

## 行列选取系统

> **当前状态：原型验证中。** 此系统替代矩阵框选系统 v2。

### 基本结构

- **矩阵大小**: 4×4（16个格子）
- 所有格子占 1 格
- 玩家选择一**行**或一**列**
- 从选中的行/列中**随机获取 1 个格子**
- 被取走的格子从矩阵中移除
- 上方格子因重力下落
- 顶部空位由随机新格子补充（三消式即时补充）
- **抽取本身无直接消耗**，但可能抽到厄运物品或触发厄运结算

### 格子类型

矩阵中的格子分为**普通物品**和**炸弹**两种。网格上不存在任何厄运标记或特殊格子——玩家看到的始终是干净的物品网格（厄运事件是隐形的）。

- **普通物品**: 获得该物品，放入背包
- **炸弹 💣**: 消除周围 8 格（不获得任何物品），所有受影响列执行重力补充。初始 1-3 个，补充时 8% 概率生成

> **已移除**: 金币陷阱、独立厄运格子、物品上的厄运标记均已移除。炸弹保留。

### 刷新阶段的厄运事件

每次网格补充新格子时（抽取后的重力补充、手动刷新等），**每个新生成的格子**都可能触发以下厄运事件。这些事件在物品出现的瞬间自动触发，物品本身留在网格上，不受影响。

| 厄运事件 | 触发概率 | 效果 | 保护规则 |
|----------|----------|------|----------|
| **厄运标记（装弹）** | 5%（每个新格子） | 一个"危险"标记**立刻加入厄运网格** | 初始网格和手动刷新后的新网格不会触发 |
| **厄运触发（开枪）** | 10%（每次刷新） | 立刻触发一次**厄运结算** | 初始网格不会触发；触发后进入冷却，不会立刻再次触发 |

**关键设计**: 厄运标记在物品出现时就自动进入厄运网格，而非等待玩家抽到。玩家看到的网格永远是干净的——没有需要回避的"雷"。所有厄运来自**抽取行为导致的网格刷新**，而非抽取结果。

### 网格刷新（Grid Refresh）

玩家可以消耗背包中 **1个物品** 来完全刷新物品网格。（具体消耗条件待品质系统重新设计后确定）

- 当前网格上所有格子被移除，生成全新的 4×4 网格
- 新网格不会触发厄运标记事件（保护规则）
- 刷新视为一次补充事件，可能触发厄运触发（10%概率）

### 核心决策

玩家看到矩阵上所有格子的信息，选择一行或一列作为抽取范围。选择的依据包括：

- **目标物品**: 哪一行/列包含需要的物品
- **概率评估**: 行/列中有多少个想要的物品
- **行列二重性**: 同一个目标物品可以通过它所在的行或列来接近，但附带的其他格子不同
- **重力预判**: 取走格子后的掉落会改变未来的行列组成；更多重力掉落 = 更多格子补充 = 更多厄运事件机会
- **撤离时机**: 厄运网格越来越危险，每次抽取都在"更多收获"与"更多风险"之间权衡
- **刷新决策**: 当前网格是否值得继续抽取，还是应该消耗物品换取全新机会？

## 背包系统

### 背包容量

- **默认容量**: 10格

### 操作模式

1. **整理模式**: 无待定物品时
   - 点击有物品的格子 → 选中该物品
   - 再次点击同一格子 → 取消选中
   - 点击另一个格子：
     - 空格 → 移动物品
     - 有物品且可合成 → 合成
     - 有物品但不可合成 → 交换位置

2. **放置模式**: 有待定物品时
   - 点击空格 → 放入物品
   - 点击有物品的格子：
     - 可合成 → 合成
     - 不可合成 → 回收原物品，放入新物品

### 待定队列

获得的物品会进入待定队列：
- 如果背包有空位且满足种类限制 → 自动飞入背包
- 如果背包满或违反种类限制 → 等待玩家手动选择替换

### 回收

> **待重新设计**: 回收系统原与金币经济绑定。金币系统已移除，回收机制需要重新设计。

### 订单槽位分配

玩家可以将背包中的物品预分配到订单的特定需求槽位：
- 选中背包物品后，点击订单需求槽位进行分配
- 已分配的物品会显示标记
- 幻影标记 (Phantom Marks) 会显示其他订单是否也需要同名物品

## 订单系统

> **设计方向调整**: 订单系统计划全部移至局外（meta-game 层）。抽取的物品需要被带出局内给局外使用。局内不再有订单。具体设计待定。以下内容为当前代码中的实现，仅供参考。

### 订单数量（当前实现）

- **普通订单**: 3个

### 普通订单生成

#### 需求数量

订单包含的物品需求数量：

| 需求数量 | 权重 | 近似概率 |
|----------|------|----------|
| 2物品 | 20 | 20% |
| 3物品 | 65 | 65% |
| 4物品 | 15 | 15% |

#### 需求品质

每个需求的品质通过 `orderRarityWeights` 随机决定：

| 品质 | 概率 |
|------|------|
| Common | 40% |
| Uncommon | 35% |
| Rare | 20% |
| Epic | 5% |
| Legendary | 0% |
| Mythic | 0% |

#### 订单奖励计算

**积分奖励**:
- `baseScoreReward` = 每个需求物品的品质积分权重之和 + progressOffset（默认为0）
- 积分品质权重:

| 品质 | 积分权重 |
|------|----------|
| Common | 2 |
| Uncommon | 2.5 |
| Rare | 4 |
| Epic | 8 |
| Legendary | 16 |
| Mythic | 32 |

- 例如：3物品订单要求 [Common, Uncommon, Rare]
  - baseScoreReward = floor(2 + 2.5 + 4 + 0) = 8，取 max(1, 8) = 8

**最终积分奖励** = ceil(baseScoreReward × multiplier)
- `multiplier` = 1 + 提交物品品质加成之和
- 如果技能"强迫症"触发（所有提交物品属于同一池子）：multiplier × 2

例如：提交 [Uncommon(+0.1), Rare(+0.25), Epic(+0.5)]
- multiplier = 1 + 0.1 + 0.25 + 0.5 = 1.85
- 最终积分 = ceil(3 × 1.85) = 6

### 订单刷新

- **初始刷新次数**: 3（JSON `global.initialRefreshCount` 值）
- **最大刷新次数**: 3（JSON `global.maxRefreshCount` 值）
- **刷新机制**: 消耗1次刷新机会，生成新订单替换被刷新的订单
- **完成订单恢复**: 每完成1个订单，刷新次数 +1

### 订单提交

1. 进入提交模式
2. 选择背包中的物品
3. 系统自动匹配所有可满足的订单
4. 提交成功 → 消耗物品，获得积分
5. 为每个完成的订单生成2个候选订单供选择
6. 触发相关技能效果

#### 关节技（物品共享规则）

同一次提交中，**普通订单之间**可以共享物品：一个物品如果同时满足多个普通订单的需求，则该物品会被计入所有这些订单的完成判定中。物品在提交结束后统一消耗，不会因被某个订单"占用"而对其他普通订单不可见。

### 订单候选选择

当订单完成后：
1. 系统为每个完成的订单槽位生成 **2个候选订单**
2. 玩家从2个候选中选择1个作为新订单
3. 多个订单同时完成时，候选选择按队列顺序依次进行

## 技能系统

> **当前状态：未启用。** 技能系统已在代码中完整实现，但当前版本尚未激活技能获取流程。部分技能效果与旧奖池/词缀系统绑定，需要重新设计。以下内容为设计规格参考。

### 技能获取

- 最多 **3个技能槽位**
- 技能通过积分进度触发选择事件获取
- 每次获取时从候选池中 **3选1**
- 技能一旦获得，持续整局游戏

### 技能列表

共有 **13个技能**：

---

#### 1. 贫困救济 (Poverty Relief)

**效果**: 金币 < 20 时，完成订单额外获得 **+5 金币**

**触发条件**: 订单完成时

---

#### 2. 幸运 7 (Lucky 7)

**效果**: 当前金币的尾数为 **7** ，或为 **7** 的倍数时，抽取传说物品的概率 **×2**

**示例**:
- 7 金币 → 触发
- 17 金币 → 触发（尾数7）
- 27 金币 → 触发（尾数7）
- 14 金币 → 触发

---

#### 3. 炼金术 (Alchemy)

**效果**: 回收 Rare 及以上品质物品时，**25%** 概率额外获得 **5 金币**

**触发条件**: 物品回收事件

---

#### 4. 贵宾折扣 (VIP Discount)

> **需重新设计**: 原效果与旧词缀系统绑定。

**原效果**: "精准"和"有的放矢"词缀的奖池金币消耗减少 **1**

---

#### 5. 谈判专家 (Negotiator)

**效果**: 抽到 **Epic** 或以上品质物品时，所有订单获得 **1次** 刷新次数

**触发条件**: 获得 Epic+ 物品

---

#### 6. 安慰奖 (Consolation Prize)

**效果**: 连续 **5次** 抽到 Common 品质物品后，下次必定 **Rare** 以上

**机制**:
1. 每抽到 Common → 计数+1
2. 抽到非 Common → 计数清零
3. 计数达到5 → 激活状态，下次保底 Rare+（从 Rare、Epic、Legendary、Mythic 中随机选择一个）

---

#### 7. 偷工减料 (Cut Corners)

**效果**: 刷新出新订单时，**20%** 概率使订单需求物品数量 **-1**（最低为1）

**触发条件**: 生成新普通订单时（不影响撤离订单）

---

#### 8. 时间冻结 (Time Freeze)

**效果**: 刷新单个订单时，**20%** 概率不消耗该订单的剩余刷新次数

**触发条件**: 单个订单刷新时

---

#### 9. 强迫症 (OCD)

**效果**: 提交的订单若所有物品属于 **同一种类（同一池子）**，积分奖励的乘数 **×2**

**示例**:
- 提交 [西瓜, 柠檬, 苹果]（均为水果池） → 触发 ×2
- 提交 [西瓜, 铅笔] → 不触发

---

#### 10. 自动补货 (Auto Restock)

**效果**: 完成任意订单后，下次抽取获得的物品会多获得 **1个**（复制第一个抽到的物品）

**机制**:
1. 完成订单 → 激活状态
2. 下次抽取时 → 额外获得1个物品
3. 获得物品后 → 消耗状态

---

#### 11. 时来运转 (Turn Fortune)

**效果**: 完成任意订单后，下次抽取获得的物品必定是 **Rare** 以上品质

**机制**:
1. 完成订单 → 激活状态
2. 下次抽取时 → 品质保底 Rare+（从允许的 Rare+ 品质中随机选择）
3. 获得物品后 → 消耗状态

---

#### 12. 大订单专家 (Big Order Expert)

**效果**: 完成需求物品数为 **4个** 的订单时，额外获得 **5 金币**

**触发条件**: 订单完成时，该订单有4个需求

---

#### 13. 困难订单专家 (Hard Order Expert)

**效果**: 完成需要 **Epic** 或以上品质物品的订单时，额外获得 **10 金币**

**触发条件**: 订单完成时，订单的需求中包含 Epic 或 Legendary 品质要求

## 工具物品系统

- 工具物品带有 `sterile` 标记（无法合成）

| 品质        | 概率  |
| --------- | --- |
| Common    | 40% |
| Uncommon  | 30% |
| Rare      | 20% |
| Epic      | 8%  |
| Legendary | 2%  |
| Mythic    | 0%  |

**使用方式**: 右键点击工具物品 → 进入选择模式 → 点击目标物品

#### 3. 星辉祝福 (Enhance) ✨

**使用方式**: 右键点击工具物品 → 直接激活效果

## 厄运系统

> **当前状态：新方向，待原型验证。** 此系统替代旧的金币/陷阱/撤离订单系统，作为核心威胁机制。

厄运系统是游戏的核心压力来源，通过逐步升级的威胁迫使玩家在"继续搜刮"与"及时撤离"之间做出抉择。

### 厄运网格（Doom Grid）

一个独立于物品网格的小型网格，代表累积的厄运威胁。

| 配置项 | 值 |
|--------|-----|
| 格子总数 | 10 |
| 初始状态 | 1个"危险" + 9个空格 |

厄运网格中的格子有两种状态：
- **有内容**：包含一种厄运效果（当前仅"危险"）
- **空白**：无效果

### 厄运事件（Doom Events）

厄运通过网格刷新阶段的**自动事件**产生，而非附加在物品上。玩家看到的物品网格始终是干净的。

每次网格补充新格子时，每个新格子可能触发：

| 事件 | 概率 | 效果 | 保护规则 |
|------|------|------|----------|
| **厄运标记（装弹）** | 5% 每个新格子 | 一个"危险"标记立刻加入厄运网格 | 初始网格和手动刷新后不触发 |
| **厄运触发（开枪）** | 10% 每次刷新 | 触发一次厄运结算 | 初始网格不触发；触发后冷却 |

> **关键设计**: 厄运标记在物品出现时就自动进入厄运网格，玩家无需抽到才触发。物品网格上没有任何需要回避的"雷"——所有厄运来自抽取行为导致的网格刷新，而非抽取结果。玩家面对的不是"这个格子安不安全"，而是"我还要不要继续抽（导致更多刷新、更多厄运）"。
>
> **扩展性**: 未来可能加入"危险"以外的厄运标记类型（不限于扣血效果）。

### 厄运结算

触发时，一个框在厄运网格上移动并依次停下。每次停下结算该格子的效果：

- 停在**有内容的格子** → 触发该厄运效果（如"危险" → -1 生命值），计为一次**命中**
- 停在**空白格子** → 无事发生

每次结算停下的次数 = **厄运等级**。

### 厄运等级（Doom Level）

| 配置项 | 值 |
|--------|-----|
| 初始等级 | 1（每次结算停1格） |
| 升级条件 | 每累计命中 **3次**，等级+1 |
| 递增规则 | 可配置 |

### 双重升级节奏

厄运系统有两层加速，确保威胁持续上升：

1. **厄运网格变脏（装弹加速）**：每次网格补充都有5%概率为每个新格子注入一个"危险" → 抽取越多，补充越多，厄运网格中有内容的格子越多 → 每次结算命中概率越高
2. **结算变狠（开枪加重）**：厄运等级随命中次数提升 → 每次结算抽取更多格子 → 单次触发造成多次命中的概率上升

厄运完全由**抽取行为的频率**驱动——抽得越多，刷新越多，装弹和开枪的机会越多。玩家无法通过"回避某些格子"来规避厄运，唯一能降低厄运的方式是减少抽取（或撤离）。

## 撤离

玩家**任何时候**都可以选择撤离，带走当前背包中的**全部物品**。

撤离无条件限制——核心张力来自厄运系统的逐步升级：留得越久能拿到越多物品，但厄运结算的危险性也在持续攀升。

### 游戏结束

| 条件 | 结果 |
|------|------|
| 主动撤离 | 带走背包全部物品 |
| 生命值归零 | 随机失去背包中一半物品，带着剩余撤离 |

## 积分与进度系统

### 积分计算

> **注意**: 订单系统计划移至局外，积分系统可能随之调整。以下为当前实现。

- `baseScoreReward` = Σ(每个需求物品品质的积分权重) + progressOffset
- `finalScoreReward` = ceil(baseScoreReward × multiplier)
  - `multiplier` = 1 + Σ(提交物品的品质加成)
  - 强迫症触发时：multiplier × 2

### 积分品质权重

| 品质 | 积分权重 |
|------|----------|
| Common | 2 |
| Uncommon | 2.5 |
| Rare | 4 |
| Epic | 8 |
| Legendary | 16 |
| Mythic | 32 |

### 积分进度

- **目标积分**: 无上限 (`targetProgress: null`)
- 积分累积推动游戏进度
- 积分进度可影响技能选择触发和难度调整

## 游戏流程

### 核心循环

```
┌─────────────────────────────────────┐
│           游戏开始                   │
│    生命值: 3, 背包: 10格            │
│    厄运网格: 1个危险 + 9个空格      │
│    厄运等级: 1                      │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│           核心循环                   │
│  1. 观察矩阵，选择一行或一列        │
│  2. 随机获取该行/列中的1个物品      │
│     → 物品放入背包                   │
│  3. 格子移除，重力掉落，顶部补充    │
│     - 每个新格子5%概率: 装弹        │
│       （危险加入厄运网格）           │
│     - 每次刷新10%概率: 开枪         │
│       （厄运结算，次数=厄运等级）    │
│  4. 管理背包（整理、合成）          │
│  5. 随时可选择撤离                  │
│  6. 重复                           │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│    游戏结束条件：                    │
│    - 主动撤离（带走全部物品）       │
│    - 生命值归零（失去一半物品）     │
└─────────────────────────────────────┘
```

### 订单提交流程

```
┌─────────────────────────────────────┐
│        进入提交模式                  │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│      选择背包中的物品                │
│  高亮显示可满足的订单                │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│        确认提交                      │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│    验证所有选中物品                  │
│  - 每个物品必须被某订单需要          │
└─────────────┬───────────────────────┘
              │ 验证通过
              ▼
┌─────────────────────────────────────┐
│    计算每个订单的奖励                │
│  - 积分: baseScoreReward × 乘数     │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│    发放积分、消耗物品                │
│    每个完成的订单：                  │
│    - 刷新次数 +1                    │
│    - 生成2个候选订单供选择           │
└─────────────────────────────────────┘
```
