## 游戏概述

**主题**：人如何与不确定性共处。主角的餐厅濒临倒闭——每天凌晨必须去菜市场抢食材，回家做菜挽救人气值。好食材稀缺、抢菜人成群,"抢"不是比喻。

**核心张力**：
- 局内（菜市场）：食材需求 vs 厄运风险，行列选择的策略博弈；摊位类型决定食材品类
- 局外（厨房）：做菜评分 → 人气涨跌 → 影响后续天数

**胜利条件**：当前原型阶段——3 场（3 天）累计 ≥ 30 分。终局"评审 Boss"机制规划中。

## 大局结构（Day 循环）

每"天"= 一次菜市场早市搜打撤 + 一次回家做菜结算。

```
[Day N 开始]
   │
   ▼
揭晓今天的菜品要求（菜名 + 槽位结构 + 五维目标）
   │
   ▼
自动填满订单货架（4 单）
   │
   ▼
进入菜市场（局内）
  - 选择摊位（奖品墙）
  - 抽食材 / 完成订单 / 遭遇抢菜人
  - 决定撤离时机
   │
   ▼
回家做菜（局外）
  - 把食材填入菜品槽位
  - 派遣判定五维评分
  - 人气值涨跌
   │
   ▼
[Day N+1] ── 直到达成胜利条件
```

代码中：`dayNumber` 即天数计数；`expeditionScores` 累积各天得分；`phase` 状态机驱动 `pre_game → setup → wall_choice → drawing → between_turns → restaurant → cook_result → pre_game`（下一天）。

## 开局组建（Setup）

每天 `startGame` 进入 `setup` phase：

1. **今日菜单揭晓**：全屏浮层展示今日菜品图标 + 名称，点击任意位置继续（`RoundTransition` 组件）
2. **自动填充货架**：玩家关闭揭晓浮层后，系统立即生成 4 单随机订单填满货架，无需手动选择

> **v2.5 → 本分支变化**：原本的"5 次二选一手动选单"已移除。现在由系统直接生成初始 4 单。

## 局内：节目（奖品墙）

### 奖品墙基本结构

- **大小**：4×4（`MATRIX_CONFIG.gridSize: 4`；调试模式可切 3×3）
- 每回合一面墙，回合内不补充
- 每次抽取选择**行**或**列**，从该行/列里随机抽中 1 个格子
- 抽中格子立即移除（仅移除该格，同组其他格保留）

### 格子类型与每格生成概率（Procedural 墙）

每个格子按以下概率序排：

| 类型 | 每格概率 | 抽中效果 |
|------|---------|----------|
| 🧑 抢菜人（厄运结算） | 15% | 触发厄运结算 |
| 🎫 抽数格 | 3% | 获得 1-2 抽次 |
| 📋 订单格 | 7% | 队列新增 1 个二选一事件 |
| 💣 炸弹格 | 5% | 爆炸摧毁周围 8 格 |
| 🥩/🐟/... 食材格 | 余下（~70%） | 获得 1 个食材（品质在抽中时随机分配） |

> **v2.5 → 本分支变化**：
> - ⬆️ 厄运升级格已移除
> - 💀 厄运结算格改用人物 emoji（🧑 等），称为"抢菜人"
> - 🎁 独立"局外食材格"已移除——所有食材格统一来自市场食材池
> - 概率分布调整：厄运结算 15%（原 5%），订单格 7%（原 4%），炸弹 5%（原 4%），金币/抽数 3%（原 6%）

### 格子多联形状（Polyomino）

食材格以**多联格形状**生成：

| 形状大小 | 权重 | 效果 |
|---------|------|------|
| 1 格（单体） | 60% | 单格独立 |
| 2 格（多米诺） | 30% | 两格共享同一食材类型和 groupId |
| 3 格（三联体） | 10% | 三格共享同一食材类型和 groupId |

- 同一多联格内所有格子拥有相同食材类型（id）和同一 `groupId`
- 每次抽取**只移除被抽中的那一格**，同组其他格保留在墙上
- **品质不存储在格中**——每次抽取时实时 `rollQuality()`

### 回合流程

每回合进入墙时：
1. 3 选 1 选市场（`wall_choice` phase）
2. 进入墙开始抽取（`drawing` phase）
3. 抽完所有次数或主动撤离 → `between_turns` 结算
4. 连续或撤离选择

### 抽数（原"金币"）

| 配置 | 值 |
|------|----|
| 每面墙初始抽数 | 3 |
| 每次抽取消耗 | 1 |
| 抽数格奖励 | 1-2 抽次 |

## 市场类型（奖品墙类型）

每面墙对应一种**市场类型**，决定墙上出现的食材品类：

| 类型 | 名称 | 可出现食材 |
|------|------|-----------|
| 🦐 seafood_market | 海鲜市场 | 仅海鲜类（鱼/虾/贝/蟹） |
| 🍖 butcher | 肉铺 | 仅肉类（鸡/牛/猪/羊） |
| 🍚 grain_store | 粮食店 | 仅主食类（米/面/豆/面包） |
| 🥬 vegetable_shop | 蔬菜店 | 仅蔬菜类（青菜/根茎/水果/菌菇） |
| 🧀 dairy_store | 乳品店 | 仅蛋奶制品（蛋/奶/豆腐/奶酪） |

**选取方式**：5 种等权重随机（每次从全部 5 种中加权选 3 种不重复候选）

**与 v2.5 的区别**：
- 原 9 种 modifier（shuffle bag）临时停用；`currentWallType` 现在存储市场类型
- 选墙时市场类型**完全可见**（图标、名称、描述、可用食材子类），不再隐藏
- 原 `wall_reveal` 揭晓浮层流程已移除，选墙直接进入 `drawing` phase

> 原 modifier 逻辑（镜花水月、爆裂愈合、传送带等）代码仍在 `useGameLogic.js` 中，但因市场类型 id 不匹配原 modifier id，实际不触发，属于暂时冻结状态。

## 食材系统（局内格子）

食材是本分支的**核心局内货币**，替代原贴纸系统。

### 食材总表

共 **80 种**，按大类和小类组织：

| 大类 | 小类 | 示例 |
|------|------|------|
| 肉类 | 鸡/牛/猪/羊 | 鸡胸肉、牛腩、五花肉、羊排 |
| 海鲜 | 鱼/虾/贝/蟹 | 三文鱼、明虾、扇贝、帝王蟹 |
| 蔬菜 | 青菜/根茎/水果/菌菇 | 菠菜、土豆、芒果、香菇 |
| 主食 | 米/面/豆/面包 | 茉莉香米、乌冬面、鹰嘴豆、法棍 |
| 蛋奶制品 | 蛋/奶/豆腐/奶酪 | 鹌鹑蛋、水牛奶、老豆腐、帕玛森 |

每个大类含 4 个小类，每个小类含 4 个具体食材（共 5 大类 × 4 小类 × 4 食材 = 80 种）。

### 食材属性

每种食材有：`id`、`icon`、`name`/`nameEn`、`tags: [大类, 小类]`、`shortLabel`（角标，同小类区分）

格中不存储品质——品质在被抽中时实时分配（见[品质系统](#品质系统)）。

### 与原贴纸的对比

| 维度 | 原贴纸 | 现食材 |
|------|--------|--------|
| 数量 | 20 种 | 80 种 |
| 分类 | 无层级 | 大类 + 小类两级 |
| 品质 | 无 | 5 级（随机分配） |
| 墙上形态 | 单格 | 多联格（1-3格形状） |
| 订单匹配 | 按 sticker id | 按小类 tag2 + 品质 ≥ 要求 |
| 撤离 | 全部丢弃 | 带到厨房做菜（局外物品） |

## 品质系统

每件食材（无论通过抽取还是订单奖励获得）都有品质等级：

| 品质 id | 名称 | 图标 | scoreValue | 抽取概率 |
|---------|------|------|-----------|---------|
| 1 | 普通 | ★ | 1 | **40%** |
| 2 | 精选 | ★★ | 2 | **30%** |
| 3 | 优质 | ★★★ | 3 | **18%** |
| 4 | 顶级 | ★★★★ | 5 | **8%** |
| 5 | 传说 | ★★★★★ | 8 | **4%** |

`scoreValue` 用于订单匹配（满足品质要求）和厨房做菜评分。

品质 5 档替代原 4 级稀有度（★/★★/★★★/★★★★）。

## 合成系统

背包内，**2 件相同食材（同 id）且同品质** 可合成为高一档品质：

- `synthesizeItems(index1, index2)` 或 `synthesizeWithPending(idx)`
- 合成后原两件消耗，得到 1 件同食材、品质 +1 的新物品
- 传说品质（5）不可继续合成

## 订单系统

### 货架（Bulletin Board）配置

| 字段 | 值 | 含义 |
|------|----|------|
| `bulletinCapacity` | 4 | 货架容量（始终满员） |
| `initialCount` | 4 | 每天开局自动生成 |
| `REFRESH_CONFIG.initialCharges` | 0 | 每天开局的刷新次数 |
| `REFRESH_CONFIG.maxCharges` | 5 | 刷新次数上限 |

### 订单模板与权重

| 模板 | 难度 | 要求格式 | 品质要求 | 食材种类数 | 奖励品质 | 权重 |
|------|------|---------|---------|---------|---------|------|
| easy | easy | reqBudget 2 | 平均 q1-2 | 2 | ★★（精选） | **30%** |
| medium | medium | reqBudget 3 | 平均 q2-3 | 2 | ★★★（优质） | **40%** |
| hard | hard | qualityDist [3,2,1] | 混合 q1-3 | 3 | ★★★★（顶级） | **20%** |
| extreme | extreme | qualityDist [3,3,2] | 混合 q2-3 | 3 | ★★★★★（传说） | **10%** |

> **v2.5 → 本分支变化**：权重从 40/30/20/10 调整为 30/40/20/10（medium 现为最常见）。

### 订单需求格式

每张订单包含 N 个需求槽（N = `ingredientTypes`）：
```
{ tag2: '虾', categoryTag: '海鲜', quality: 2, count: 1 }
```
匹配条件：背包中有 `tags[1] === req.tag2 && quality >= req.quality` 的食材即可满足。

### 订单奖励格式

每张订单含 1 个奖励槽：
```
{ tag2: '鸡', quality: 3, score: 3, isOutOfGame: true }
```
奖励食材在**提交时**通过弹出 `OrderSubmitModal` 由玩家从奖励品类（tag2）中选择具体种类。

### 订单刷新渠道

| 渠道 | 触发 | 行为 |
|------|------|------|
| **开局自动** | 每天菜品揭晓后 | 一次性生成 4 单，直接填满货架 |
| **完成订单自动补单** | 玩家提交订单后 | 入队 1 个二选一事件 |
| **抽中订单格** | 抽到 📋 格子时 | 入队 1 个二选一事件 |
| **主动刷新** | 点货架顶 🔄 按钮 | 消耗 1 次刷新次数 → 入队 1 个二选一事件 |

所有事件共享一个 **FIFO 队列**（`incomingQueue`）。货架满时进入替换模式。

**刷新次数来源**：（当前分支暂无格子直接 +刷新次数，刷新次数初始为 0）

### 订单提交

- 不限时机，不消耗抽数
- 背包中备齐所需食材（tag2 + 品质满足）才可提交
- 弹出选择界面：选择消耗哪件食材、选择具体奖励食材
- 提交后消耗对应食材 → 获得奖励食材（进入背包）→ 自动补单（二选一）

## 食材（局外物品）

食材在提交订单后作为奖励获得，撤离时**带回厨房**做菜。

- **获取方式**：完成订单（主要，奖励按 tag2 + 指定品质）；抽中墙上食材格（次要，品质随机）
- 食材进入背包时：`quality = 已知品质 || rollQuality()`
- 每件食材有完整属性：id / icon / name / tags / quality / score / isOutOfGame

## 厄运系统

### 厄运网格（Doom Grid）
- 总格子数 10，初始：1 个"危险" + 9 个空
- **每回合自动 +1 危险**

### 厄运结算
由奖品墙上的**🧑 抢菜人格**（`doom_resolution`）触发：
1. 光标在厄运网格上随机落 N 次（N = 当前厄运等级，初始 1）
2. 落在"危险"格 → -1 HP
3. 落在空格 → 无事

> **本分支变化**：
> - ⬆️ 厄运升级格已**完全移除**（代码层面删除，不再生成）
> - 厄运结算格（💀）改用人物 emoji（🧑👩 等），主题化为"抢菜人抢走了菜篮耐久"
> - 厄运等级只有初始等级 1，无升级路径（规划中）

### 生命值（HP）
- 初始 5（每天重置）
- 归零 → 丢失背包全部内容，强制撤离

## 局外：厨房与做菜结算

### 菜品（DISHES）

每天有指定菜品，结构：
```
{
  id, name, nameEn, icon,
  baseline: <基础分>,
  slots: [
    { name: '主料', required: true, rules: [...], defaultMultiplier },
    ...
  ]
}
```

当日菜品索引：`(dayNumber - 1) % DISHES.length`。

### 槽位匹配规则

每个槽位有 `rules[]`，每条规则形如：
```
{ match: { tag: '虾' }, multiplier: 1 }
{ match: { id: 'tiger_prawn' }, multiplier: 2 }
```

**匹配算法**（`getSlotMatch`）：
1. `slot.exclude` 命中 → multiplier 0，禁入
2. 评估所有规则，**取最高 multiplier**
3. 无匹配 → 用 `defaultMultiplier`（通常 0，代表"不能放"）
4. 无规则的槽（如"配料"）→ `defaultMultiplier`（通常 1）

**触发槽（`trigger`）**：某槽位可声明 `trigger.whenTag`——当该槽放入指定 tag 的食材时，额外生成一个新槽位（动态扩展菜品结构）。

**跨槽加成（`crossBonus`）**：
某槽位可声明 `crossBonus: { requireSlot, requireTag, multiplier }`——其它指定槽位放入指定 tag 的食材时，本槽乘数叠加。

### 评分流程（`scoreDish`）
1. 预扫描所有 `crossBonus` 是否激活
2. 对每个槽位：取食材 × 槽位 multiplier × crossBonus 加成
3. 汇总所有槽位得分 + 菜品 `baseline`
4. 输出最终分数

## 派遣判定（五维评分）

灵感源自 Dispatch（超英派遣中心）的多边形评分。

### 五个维度
**健康 / 香气 / 口感 / 味道 / 外观**

### 评分机制
- 每道菜的目标用 5 维数值表示，绘制为五边形
- 玩家做菜的实际表现也输出 5 维数值，绘制为另一个多边形（金色填充）
- 一颗小球在**玩家多边形**内随机弹跳，落停时检查是否落在重叠区

> 当前作为**独立工具页面**实装，未与厨房做菜流程完整接线。

## 人气值系统

- 人气值 = 玩家的"血量" + 经济引擎
- 每天做菜评价影响人气值涨跌（梯度，非二元）
- 人气值归零 = 游戏失败

代码中存在 `popularity` 状态字段，**具体涨跌公式与初始值仍待定型**。

- **阶段系统** `INITIAL_STAGE_CONFIG`（4 阶段多项配置）
- **技能系统** `SKILL_DEFINITIONS`（13 个技能）
- **词缀系统** `INITIAL_AFFIXES_CONFIG`（7 种词缀）
- **工具物品** `TOOL_ITEMS`（命运熔炉/万象棱镜/星辉祝福）
- **奖池数据** `INITIAL_POOLS_DATA`（5 池）
- **品质级别** `INITIAL_RARITY_CONFIG`（6 级品质）

### v2.5 modifier 系统（useGameLogic.js 冷冻）
原 9 种 modifier（镜花水月/爆裂愈合/传送带/转盘中心/神秘面纱/双倍惊喜/交叉问答/野蛮生长/祝福愈合）的代码逻辑仍在 `useGameLogic.js`（约 400 行），但由于 `currentWallType` 现在存储的是市场类型（id 不匹配），所有 modifier 分支不会触发。

### v2.5 簇系统（deprecated）
`matrixHelpers.js::getClusterMembers` 已标记为 `@deprecated`，`ResourceMatrix` 等组件可能仍引用但系统已不使用簇消除逻辑。当前食材的多联格（polyomino）是视觉层分组，非消除机制。
