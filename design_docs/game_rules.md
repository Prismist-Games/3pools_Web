## 游戏概述

> **当前状态：回合制原型 v2.5。** 相比 v2.4 主要新增：簇系统（相邻同类贴纸自动连成一片，整片消除）、开局菜品揭晓 + 5 次二选一组建初始订单、奖品墙三选一时隐藏 modifier 直至确认进入、厄运格重新出现在随机墙上、贴纸种类扩展到 20 种、局外物品改为带 tag 的食材并接入厨房菜品结算系统。移除了阴阳轮转 modifier。

**设定**：电视节目 / 厨房竞技。玩家面对奖品墙（Prize Wall）抽取贴纸与食材，组合食材完成今日菜品。

这是一款 push-your-luck 策略游戏。一次完整游戏包含 **3 场**（每场 = 一次进入 → 多回合抽取 → 撤离）。每场开局先揭晓"今日菜单"并通过 5 次"二选一"由玩家手动拼出初始订单货架，随后进入回合循环：每回合从 3 面候选奖品墙中盲选一面（modifier 隐藏，进入后揭晓），用金币选择行或列抽取。奖品墙上主要是**贴纸**（局内材料）；相邻同类贴纸自动结成一个**簇**，抽到任一格则整簇消失但仅产出 1 张（modifier/膨化加成可叠加）。玩家用贴纸完成**订单**获得**食材**（带稀有度与 tag 的局外物品），最终在厨房按"今日菜品"结算。**厄运格**散布在墙上，抽中触发结算或升级。每回合结束后厄运自动积累。回合间决定继续还是撤离。

**核心张力**：
- 回合内：贴纸需求 vs 厄运风险 vs 簇产出最大化（避免被簇"吞掉"贴纸）
- 回合间：继续收集 vs 带走得分
- 开局：菜品口味（slot 偏好）×订单挑选 → 影响后续抽墙取舍

**胜利条件**：3 场（3 次撤离）后累计至少 **30 分**。

## 核心资源

### 生命值 (HP)

- **初始生命值**: 5（每场重置）
- **用途**: 存活指标。厄运结算中命中"危险"格子会扣除生命值。
- **生命值归零**: 丢失背包全部内容，强制撤离

### 金币

- **每回合获得**: 5 金币
- **用途**: 支付抽取费用（每次抽取花费 1 金币）
- **剩余不累积**: 回合结束时未使用的金币清零
- **额外获取**: 奖品墙上可能出现金币格（1-2 金币）
- **modifier 覆盖**: 镜花水月墙进入金币 = 3（默认 5）

### 刷新次数

- **初始**: 0（开局通过 setup 手动构建订单，不再赠送免费刷新）
- **上限**: 5
- **获取**: 抽中📋 订单格 = +1 次（capped at 5）
- **消耗**: 主动点击货架顶部的 🔄 按钮，生成一个新二选一事件（可与系统自动补单事件叠加排队）

## 大局结构

一次完整游戏包含 **3 场**：

1. **游戏开始**：随机指定 3 种食材获得**额外加分**（分别 +1、+2、+3 分）
2. **每场开局**：进入 setup 阶段（菜品揭晓 + 5 次二选一组建订单），随后进入回合循环
3. **每场**：多回合抽取 → 主动撤离或强制撤离
4. **一场结束**：背包中的食材进入厨房按"今日菜品"结算分数；其他状态（HP、金币、贴纸、厄运、订单、刷新次数）重置
5. **3 场后**：累计分数 ≥ 30 分为胜利

## 开局组建（Setup）

每场开始时，先经过 setup 流程而非直接进入抽取。

### 流程

1. **今日菜单揭晓**：黑屏浮层展示今日菜品的图标 + 名称 + 副标题"今日菜单"。点击任意位置继续。
2. **5 次"二选一"**：依次弹出 5 个二选一事件（候选订单 A vs B），玩家从每对里选一个加入货架。不能跳过——选了就进入下一对。
3. **首面奖品墙**：5 次二选一全部完成后自动进入回合 1 的"奖品墙三选一"环节。

### 设计意图

- 让开局成为有意识的"今天我要打什么订单"决策，而不是看着系统随机塞 5 个订单进来
- "今日菜品"在 setup 期间常驻显示在中央，包含菜品的所有 slot 槽位预览（main/base/garnish 等及其匹配规则），让玩家看到 modifier-tag 偏好后再选订单
- 顺带修掉了"首墙生成时尚未有订单可参考"的 bug——首墙现在生成时已经有完整的 5 单货架

### 配置

| 项目 | 值 |
|------|------|
| 每对候选订单数 | 2 |
| Setup 二选一总次数 | 5 |
| 初始刷新次数 | 0 |
| 是否可跳过 | 否（所有 5 次必须做选择） |

## 回合结构

每回合的流程：

1. **奖品墙三选一**：从 3 张盲选卡（modifier 隐藏）中选一面墙
2. **奖品墙揭晓**：黑屏浮层展示 modifier/关卡的图标、名称、描述；点击任意位置确认进入。**没有"返回"** —— 选卡即承诺
3. **回合开始**：墙就绪，获得 5 金币
4. **抽取阶段**：花费金币选行或列抽取（可进行 0~5 次），可随时提交已完成的订单
5. **回合结束**：玩家点击"结束回合"，厄运自动积累（厄运网格 +1 危险格）
6. **决策**：继续下一回合（回到第 1 步）or 撤离

玩家不必用完所有金币——可以选择提前结束回合。

> **变化点**：回合内不再有"接受订单"环节。订单货架始终满 5 单，由 setup、订单完成自动补单、玩家主动刷新三种渠道维持。回合开始时也不再有自动刷新。

## 奖品墙系统

### 基本结构

- **大小**: 4×4（16 个格子位置）
- 每回合一面墙，回合内不补充
- 可选择**行**或**列**进行抽取
- 每个格子都是独立的 1×1 实体（无 polyomino 编组）。**贴纸格之间通过相邻关系动态结成簇** —— 详见 [簇（Cluster）系统](#簇cluster系统)

### 格子类型

| 格子类型 | 描述 | 抽中效果 |
|----------|------|----------|
| **贴纸格** | 20 种贴纸之一 | 整簇消失，按簇产出公式获得 N 张贴纸 |
| **食材格** 🎁 | 稀有出现，rarity 1-4 | 获得对应食材，放入背包 |
| **订单格** 📋 | 偶尔出现 | 刷新次数 +1（capped at 5）。不再直接生成订单 |
| **金币格** 💰 | 偶尔出现 | 获得 1-2 金币 |
| **💀 厄运结算格** | 红色底 | 触发厄运结算 |
| **⬆️ 厄运升级格** | 红色底 | 厄运等级 +1 |
| **💣 炸弹格** | 黑色格子 | 抽中时爆炸，摧毁周围 8 格 |
| **🌽 膨化格** | buff 锚点 | 抽中自身时消失无收益；相邻 4 格（上下左右）被抽中时收益 ×(N+1)，N 为相邻膨化格数量。**簇模式下：膨化格邻接簇任一成员都计入产出加成** |
| **❤️‍🩹 生命恢复格** | 效果格 | 恢复 HP（默认 +1，支持倍率） |
| **🎒 背包扩容格** | 效果格 | 增加背包容量（默认 +1，持续到本局结束） |
| **⬇️ 重力开关格** | 效果格 | 激活重力——所有格子向下坠落（持续生效直到本回合结束） |
| **🚪 子关卡入口格** | 关卡专属 | 进入子关卡（独立金币，共享背包和厄运） |
| **⬜ 空白格** | 结构格 | 不填充、不参与抽取，格子可通过（重力时视为空位） |

### 特殊格生成概率（Procedural 墙）

| 格子 | 每格生成概率 |
|------|--------------|
| 💰 金币 | 6% |
| 📋 订单 | 4% |
| 🎁 食材 | 2%（rarity 加权：★40% / ★★30% / ★★★20% / ★★★★10%） |
| 💣 炸弹 | 4% |
| 💀 厄运结算 | 5% |
| ⬆️ 厄运升级 | 5% |
| 🌽 膨化格 | 0%（仅由"祝福愈合"等 modifier 产生） |
| 贴纸 | 余下空位填充 |

> **变化点**：厄运格在 v2.4 阶段被移出随机墙；v2.5 重新加回，每格 5%/5% 概率。这意味着平均每面 16 格墙约有 1.6 个厄运格，总特殊格密度约 26%，剩余 ~12 格为贴纸。

### 贴纸分布

- 全集 **20 种贴纸**
- 每面奖品墙从全集中均匀随机挑选 **3-4 种** 出现
- 选墙时不受当前订单需求约束（v2.4 短暂尝试过"每格按订单需求 roll"，v2.5 已 revert）

### 奖品墙选择（回合间 3 选 1）

每回合开始前，从 3 面候选奖品墙中盲选一面。每个候选墙是以下二者之一（互斥）：
- **墙类型（Modifier）**：纯 procedural 生成 + 特殊规则
- **手作关卡（Level）**：半手作地形 + 无 modifier

### 三选一卡片预览（仅"基本信息"，modifier 隐藏）

每张候选卡只展示：
- **❓ 第 N 号墙** 标题（modifier/关卡名称都不显示）
- **贴纸种类列表**（带图标，hover 时高亮货架上对应需求）
- **厄运格统计**（💀 ×N、⬆️ ×N，红底 chip）
- **特殊格类型**（💣 / 💰 / 📋 / 🎁 / ❤️‍🩹 / 🎒 / ⬇️ / 🚪）

### 揭晓与确认（wall_reveal 阶段）

点击候选卡后**立即承诺**该墙，不可返回。系统进入 `wall_reveal` 阶段，弹出黑屏浮层显示该墙的：
- modifier/关卡的图标、名称、描述
- 副标题"奖品墙揭晓"

玩家点击任意位置确认进入抽取阶段。

> **设计意图**：让选墙变成"押宝格子组成"（哪些贴纸/特殊格/厄运），而不是"提前读规则后挑最舒服的"。modifier 是揭晓时的戏剧性惊喜。Commit-on-click 是为了防止玩家轮流点 3 张卡来 peek 所有 modifier 后再选——那样隐藏 modifier 就失去意义了。

### 奖品墙类型（Modifier）

每个 modifier 既决定墙的特殊规则，也可以覆盖墙级参数（如进入金币数）。

| 类型 | 规则 | 备注 |
|------|------|------|
| **🎭 神秘面纱** | 约 30% 贴纸格隐藏，抽到相邻格时揭示 | |
| **✨ 双倍惊喜** | 约 20% 格子带 ×2 标记。**簇模式下：簇内每个 ×2 格都为整簇产出 +1** | |
| **🔀 交叉问答** | 必须行列交替选择 | |
| **🎡 转盘中心** | 中间 2×2 区域每抽一次顺时针旋转一格；生成时若中心没有炸弹/膨化格则强制放入一个 | |
| **➡️ 传送带** | 随机一行或一列每抽一次整体前进一格，走到头从另一端绕回。**移动后簇自动重算** | |
| **🌱 野蛮生长** | 抽到任意格后，其 4 邻居（上下左右）变成和被抽中格子同类型 | 簇被消除后 4 邻居中的非簇格才会被覆盖 |
| **💣 爆裂愈合** | 每次抽取后，被抽中**那一格**生成一颗新炸弹（抽到炸弹本身不再生成）。**簇消除时其他成员位置不放炸弹** | |
| **🪞 镜花水月** | 左右两半互为镜像，抽一格则其镜像位置一并结算。**镜像格若与抽中格在同一簇，去重不重复产出**；若在另一个同类簇，则两个簇都被消除并各自产出 | 进入金币 3（默认 5） |
| **🙏 祝福愈合** | 每次抽取后，被抽中那一格生成一颗膨化格（抽到膨化格本身不再生成） | |

**Modifier 选择**：使用 shuffle bag——每个 modifier 在 9 元素的 bag 用完前不会重复出现。bag 跨回合、跨场次保留，等概率。

> **已移除**：阴阳轮转（v2.5 移除）。它依赖"墙上只有 2 种贴纸"的前提，与簇系统及订单 sticker 多样性配合差。

### 关卡系统（Level Editor）

奖品墙可以是纯随机生成，也可以基于**手作关卡**半生成。关卡定义了部分格子的固定内容和约束，空白格子由 procedural 逻辑填充。

**关卡角色：**
- **主关卡（main）**：出现在 3 选 1 中，和 modifier 互斥
- **子关卡（sub）**：不出现在 3 选 1 中，通过入口格子进入

**关卡格子状态：**
| 状态 | 含义 |
|------|------|
| 固定格子 | 指定具体类型（如 💣 炸弹、💀 厄运结算、⬇️ 重力开关等） |
| 约束格子 | 从可能性中随机选（如 `any_doom` = 💀或⬆️） |
| 贴纸格 | 随机贴纸类型，可设置倍率 |
| 空白格（procedural） | 交给随机生成器填充 |
| 空白格（真空） | 不填充、不参与抽取 |

> **已移除：Polyomino 编组系统**。之前的版本支持同类型格子通过 groupId 形成 polyomino，抽到任一格结算整组。v2.4 起全部改为独立 1×1 格子，关卡 JSON 中残留的 group 字段在读取时会被忽略。簇系统是动态的、基于运行时邻接关系的不同概念，不要混淆。

**墙级设置：**
- `stickerTypeRange: [min, max]` — 整面墙的贴纸种类数。所有贴纸（固定格 + procedural）共享同一个池
- `maxDoomInBlank` — 空白区域最多生成多少个厄运格（不设则无限制）
- `gold` — 进入关卡时的金币数（不设则使用默认值 5）

**子关卡系统：** 主关卡上可以放置子关卡入口格（🚪）。抽到入口格时：
1. 当前墙状态暂存（grid、金币）
2. 子关卡加载，使用子关卡自己的金币数
3. 背包和厄运系统与主关卡共享
4. 玩家点击"结束事件"退出，恢复主关卡状态继续
5. 退出时不触发厄运判定
6. 子关卡上不能放置入口格（防止递归）

**关卡数据存储：**
- 关卡文件：`src/data/levels/*.json`（自动导入，跟 Git）
- 调度配置：`src/data/levelSchedule.json`（权重、启用、最低探险，跟 Git）
- 本地化：关卡 JSON 内 `name_en` / `description_en` 字段

**关卡调度：** 每面候选墙独立决定使用关卡或纯随机，由权重控制（`proceduralWeight` vs 各关卡权重）。

**编辑器入口：** 游戏内 📐 按钮 → `/editor`；关卡管理 → `/levels`。

## 抽取机制

### 抽取流程

1. 花费 1 金币
2. 选择一行或一列
3. 从该行/列所有格子中随机选中 1 个
4. **若抽中贴纸格**：触发[簇消除](#簇cluster系统)（整簇移除，按公式产出 N 张贴纸）
5. **若抽中其他格**：仅消除被抽中的那一格，触发对应效果（金币/订单/厄运/炸弹爆炸/恢复/扩容/重力等）
6. 触发 modifier 副作用（爆裂愈合放炸弹、祝福愈合放膨化格、传送带/转盘移动、野蛮生长复制等）

### 抽取消耗

- 每次抽取花费 **1 金币**
- 每回合获得 **5 金币**，剩余不累积
- 玩家可自由选择抽取 0~5 次

### 核心决策

玩家选行/列时的考量：

- **贴纸需求**：哪一行/列含有当前订单需要的贴纸
- **簇结构**：行/列内贴纸成簇情况——是抽散单格保数量，还是抽大簇换 modifier 加成
- **命中概率**：行/列内目标格子占比（簇本身不影响命中——簇任意成员被抽中都消除整簇）
- **厄运风险**：行/列内 💀/⬆️ 格数量
- **炸弹风险**：行/列内是否有 💣，爆炸会摧毁周围 8 格
- **路径选择**：同一格可通过行或列两条路径触达，附带风险/收益不同
- **隐藏格**（神秘面纱）：是否值得抽取来揭示相邻隐藏格的内容

## 簇（Cluster）系统

> **v2.5 新增。** 是当前版本最重要的玩法变化之一。

### 簇的定义

**两个相邻贴纸格（4-连通：上下左右）若 sticker id 相同，自动属于同一个簇。** 沿连通关系传递闭包，所有相互可达的同 id 贴纸格构成一个簇。簇是动态计算的——matrix 是唯一事实来源，无需在格子上维护 cluster id。

- 不同 id 的贴纸不成簇
- 非贴纸格（金币/食材/厄运/炸弹/膨化格等）永远不属于任何簇
- 隐藏（hidden）贴纸格仍参与簇计算（等抽中或被揭晓后效果一样）

### 动态变化

- **传送带、转盘**：移动后簇按新邻接关系重新计算。两片本来分开的同类簇可能因移动相邻 → 合并成一个大簇
- **野蛮生长**：被消除的簇位置变空，再被野蛮生长复制的同 id 副本可能形成新簇（但生长副本通常在对角，不会立即互连）
- **爆裂愈合 / 祝福愈合**：在抽中位置放炸弹/膨化格，那一格不再属于簇

### 整簇消除

抽中簇内任一格时：

1. **整个簇全部消除**（所有成员位置变空）
2. 仅按以下公式产出对应数量的同 id 贴纸进入背包

### 产出公式（加性叠加）

```
yield = 1
      + Σ (cell.multiplier - 1)         对簇内每个成员
      + Σ buff_field 4-邻接计数         对簇内每个成员
```

- **multiplier**：来自双倍惊喜墙的 ×2 overlay（每个 ×2 成员 +1）
- **膨化邻接**：每条"簇成员 ↔ 膨化格"邻接关系 +1。同一膨化格若同时贴 2 个簇成员，**计 2 次**

### 例子

| 情况 | 产出 |
|------|------|
| 单格簇（邻居都不同 id） | 1 |
| 5 连簇，无 modifier | 1 |
| 5 连簇，1 个 ×2 双倍格 | 2 |
| 5 连簇，1 个膨化格贴 1 个簇成员 | 2 |
| 5 连簇，1 个膨化格贴 2 个簇成员 | 3 |
| 5 连簇，1 个膨化格 + 1 个 ×2 双倍格 | 3 |

### 镜花水月与簇

- 抽中格 + 镜像格在**同一簇**：簇被消除一次，仅产出一份。镜像不额外加 yield
- 抽中格 + 镜像格在**不同的同 id 簇**（或一个是贴纸一个不是）：两个簇分别按各自公式独立消除并产出

### 视觉表达

- **内边淡化 + 桥接矩形**：相邻簇成员之间的 6px gap 由 bg 色矩形填充，cell 共享边的 border 改为 bg 色 → 整簇看起来是一片连贯的形状，外轮廓连续
- **2×2 角落桥**：4 格簇相交处的 6×6 缝隙由角桥填充，避免中心出现小洞
- **Hover 高亮**：鼠标悬停簇任一成员时，整簇加金色描边，显示销毁范围
- **飞行 ×N 角标**：当 yield > 1 时，飞向背包的图标带金色 ×N badge

### 设计意图

- 簇是惩罚性的"密集成片"机制——大簇看似产量高，实际只产出 1 张（除非 modifier 加持）
- 玩家需要在"找散单格保 yield"和"利用 modifier 把大簇变成 windfall"之间做选择
- 横向移动机制（传送带/转盘）的策略价值因此放大——可以重排簇结构

## 订单系统

### 货架

货架是订单的唯一可见区，无"接受/未接受"区分——上面的订单都是可以直接提交的。

- **容量**: 始终 **5** 个订单（除非系统暂时少于 5，刷新会立刻补上）
- **显示信息**: 难度（容易/中等/困难/极难）、奖励食材（含 rarity）、所需贴纸（种类 + 数量）、当前持有进度
- **Hover 联动**: 鼠标 hover 行/列按钮、奖品墙格子或选墙候选卡时，订单上对应的贴纸需求会高亮

### 三种刷新渠道

| 渠道 | 触发 | 行为 |
|------|------|------|
| **开局 setup** | 每场开始 | 5 次二选一手动构建初始货架 |
| **完成订单后自动补单** | 玩家提交完成一个订单 | 系统立刻入队一个二选一事件，玩家选一张补回货架 |
| **主动刷新** | 货架顶 🔄 按钮 | 消耗 1 次刷新次数，入队一个二选一事件。可在 picker 打开时继续点 → 入队多个事件依次解析 |

### 二选一事件队列

- 同一时刻只显示一个二选一 picker（队列头）
- 多个事件来源（自动补单 + 主动刷新 + setup）共享同一个 FIFO 队列，永不互相覆盖
- 选定一张候选时：
  - 若货架未满 → 直接加入货架
  - 若货架已满 → 进入"替换"模式（点击货架某订单替换之，或取消放弃）

### 提交订单

- **随时可提交**：不限时机，不消耗金币
- 背包中持有足够指定贴纸时点击订单的"提交"按钮即可
- 提交后：消耗对应贴纸 → 获得订单奖励的食材（放入背包）→ 自动入队一个二选一事件填补释放出的位置

### 订单模板与权重

| 模板 | 难度 | 奖励 rarity | 所需贴纸总数 | 贴纸种类数 | 权重 |
|------|------|-------------|--------------|------------|------|
| a | easy | ★ | 2 | 1 | 40 |
| b | medium | ★★ | 3 | 2 | 30 |
| c | hard | ★★★ | 4 | 3 | 20 |
| d | extreme | ★★★★ | 6 | 4 | 10 |

每个订单奖励 1 个对应稀有度的食材（从 INGREDIENTS 表中按 rarity 随机抽取）。所需贴纸种类是从 20 种中随机选取，每种数量在 [1, 剩余]之间分配。

### 刷新次数（Refresh Charges）

| 项目 | 值 |
|------|------|
| 每场初始 | 0 |
| 上限 | 5 |
| 获取来源 | 抽中📋 订单格（每格 +1，超出上限提示"刷新次数已满"） |
| 消耗 | 主动点击 🔄 按钮（每次 1 点） |

> **变化点**：v2.4 短暂使用过"每场初始 3 次刷新"，v2.5 改为 0——开局玩家直接通过 setup 主动构建订单，不需要再用刷新去翻牌。

## 食材与菜品（厨房）

### 食材（INGREDIENTS）

食材取代了 v2.4 之前的"局外得分物品"，是带稀有度和 tag 的结构化数据，作为订单奖励或墙上 🎁 食材格的产出。

#### 稀有度

| Rarity | 标识 | 颜色定位 |
|--------|------|----------|
| ★ | rarity 1 | 普通（绿） |
| ★★ | rarity 2 | 优质（蓝） |
| ★★★ | rarity 3 | 稀有（紫） |
| ★★★★ | rarity 4 | 珍稀（金） |

#### 分类（hierarchical tags）

每个食材带 2 个 tag：`[大类, 小类]`。

| 大类 | 小类 |
|------|------|
| 肉类 | 鸡 / 牛 / 猪 / 羊 |
| 海鲜 | 鱼 / 虾 / 贝 / 蟹 |
| 蔬菜 | 青菜 / 根茎 / 水果 / 菌菇 |
| 主食 | 米 / 面 / 豆 / 面包 |

每个小类下 4 种食材，每个 rarity 一种。例如肉类 · 牛：牛肉碎(★) / 牛腱肉(★★) / 安格斯牛肉(★★★) / 和牛(★★★★)。

完整食材表见 `src/data/v2Config.js`。

#### 大局加分（Bonus Items）

每次完整游戏开始时，随机指定 3 种食材获得**额外加分**（分别 +1、+2、+3 分），模拟不同局对不同食材的需求差异。订单卡和菜品卡上的对应食材会带 ⭐ 角标。

### 今日菜品（DISHES）

每场开局随机抽取一道菜品作为"今日菜单"。当前 2 道菜：
- **海洋线条** (Lines of the Sea) 🍝 — 海鲜 + 主食 + 蔬菜组合
- **炉火慢歌** (Ballad of the Ember Hearth) 🍛 — 肉类 + 主食 + 蔬菜组合

每道菜定义：
- `baseline`: 评分基准分（默认 10）
- `slots`: 4 个槽位 + 可能的 trigger 触发槽位

### 菜品 Slot 结构

每个 slot 包含：
- `name`: 槽位名（如"主料"/"基底"/"汤汁"/"配料"）
- `required`: 是否必填
- `accept`: 主类标签（如"海鲜"）
- `prefer`: 偏好小类（如"虾"，可为字符串或数组）
- `exclude`: 禁止小类（可选）
- `trigger`: 当玩家放入带特定 tag 的食材时额外开启一个新槽位（可选）
- `crossBonus`: 与其他 slot 的联动加分（可选）

### Slot 匹配评分

把食材放入 slot 时按 tag 匹配判定：

| 匹配 | 倍率 |
|------|------|
| 食材带 prefer 中的小类 tag | ×2 |
| 食材带 accept 大类 tag（无 prefer 命中） | ×1 |
| 都不命中 | ×0.5 |
| 食材带 exclude tag | 0（不可放入） |
| slot 无 accept（任意 slot） | ×1 |

slot 单格基础分 = 食材 rarity（1/2/3/4），最终 slot 得分 = base × 倍率 + crossBonus（若触发）。

### 评级与人气变化

整道菜得分 = 所有 slot 得分总和。按基准分比例评级：

| 评级 | 阈值（相对 baseline） | 人气 Δ |
|------|------------------------|--------|
| 翻车 | < 0.5× | -2 |
| 勉强 | 0.5× ~ 1.0× | -1 |
| 合格 | 1.0× ~ 1.8× | 0 |
| 优秀 | 1.8× ~ 2.5× | +1 |
| 惊艳 | ≥ 2.5× | +2 |

### 撤离 → 厨房结算

当前原型中，厨房按钮（🍳）打开模态框由玩家手动放置食材到 slot 中预览评分。**正式撤离结算的自动化流程仍在迭代** —— 详见 [设计方向（未实现）](#设计方向未实现)。

## 厄运系统

> **v2.5 调整**：厄运格重新出现在随机墙上（每格 5%/5% 概率，详见特殊格生成概率表）。其他规则与 v2 相同。

厄运系统是游戏的核心压力来源，通过逐回合升级的威胁迫使玩家在"继续"与"撤离"之间做出抉择。

### 厄运网格（Doom Grid）

独立于奖品墙的小型网格，代表累积的厄运威胁。

| 配置项 | 值 |
|--------|-----|
| 格子总数 | 10 |
| 初始状态 | 1 个"危险" + 9 个空格 |

### 厄运积累

**每回合结束时**，自动往厄运网格加入危险格子：

- 每回合 +1 个危险格子（固定）

### 厄运结算

由**奖品墙上的 💀 厄运结算格**触发。触发时：

1. 光标在厄运网格上随机落下，共落 **N 次**（N = 当前厄运等级）
2. 每次落在**有危险的格子** → **命中**，-1 HP
3. 每次落在**空白格子** → 无事发生

抽中 💀 时墙面会有屏幕抖动 + CRT 视觉效果（持续 1 秒）。

### 厄运等级

| 配置项 | 值 |
|--------|-----|
| 初始等级 | 1（每次结算光标落 1 次） |
| 升级方式 | 奖品墙上的 ⬆️ **厄运升级格**被触发时 +1 |

### 威胁升级节奏

厄运系统有两层加速：

1. **厄运网格变脏**：每回合自动 +1 危险 → 回合越多，结算时命中概率越高
2. **结算变狠**：厄运等级通过 ⬆️ 厄运升级格提升 → 每次结算抽取更多格子

## 背包系统

### 背包容量

- **容量**: 15 格（基础）
- **存放物品**: 贴纸和食材共用同一背包
- **扩容**: 抽中 🎒 背包扩容格 +1，持续到本局结束

### 物品放置

获得物品后放入背包：
- 背包有空位 → 自动放入
- 背包已满 → 进入待处理队列，玩家逐个处理（替换或丢弃）

### 物品回收 / 合成

玩家可从背包侧栏切换到回收模式（多选丢弃）或合成模式（选择 2 个相同食材合成升 1 级稀有度）。

## 撤离

### 撤离时机

玩家只能在**回合间**（当前回合结束后、下一回合开始前）选择撤离。

### 撤离结果

| 条件 | 结果 |
|------|------|
| 主动撤离 | 背包中的食材进入厨房按今日菜品结算分数；贴纸丢失 |
| HP 归零 | 丢失背包**全部内容**（食材和贴纸），强制撤离，本场得 0 分，直接结束本场 |

## 设计方向（未实现）

以下是已讨论确定方向但尚未纳入当前原型的设计。

### 厨房结算自动化

撤离时按今日菜品自动给食材分配 slot 求最优解（或玩家手动 + 提示），目前仍是手动模态框。

### 贴纸兑换系统

贴纸除了完成订单，可能有其他兑换用途（如直接兑换食材）。

### 功能型奖品墙

奖品墙类型目前仅改变抽取规则。未来可能有功能型墙（如商店墙），改变整面墙的交互方式而不仅是抽取规则。

### 食材属性扩展

为食材增加食材-菜品联动以外的特殊能力（如保鲜期、风味、稀有买家偏好等）。

### 厄运系统扩展

- **多种危险类型**：厄运网格中不同类型的危险格子，命中后果不同
- **伤势/状态系统**：厄运命中后留下持续状态
- **生存维度**：从单一 HP 扩展为多维度

### 撤离系统扩展

撤离可能从"按按钮走人"变为有过程、有条件、有代价的系统。
