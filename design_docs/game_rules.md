## 游戏概述

这是一款资源管理策略游戏。玩家面对一个 4×4 的物品矩阵，通过选择一行或一列来随机获取其中的一个格子。矩阵中除了普通物品外，还有厄运相关的特殊物品。被取走的格子从矩阵中移除，上方物品因重力下落，空缺位置由随机新格子补充。玩家将获得的物品放入背包，最终带着背包中的物品撤离。厄运系统持续制造升级的威胁，玩家随时可以选择撤离——核心张力在于"再抽一次拿更多东西"还是"现在就跑"。

## 核心资源

### 生命值 (HP)

- **初始生命值**: 3
- **用途**: 生命值是存活指标。厄运系统的"危险"效果会扣除生命值。
- **生命值归零**: 游戏结束 → 随机失去背包中一半物品，带着剩余物品撤离

## 物品系统

### 物品池 (Item Pools)

游戏中有 **5个物品池**，每个池子包含 **4种物品**，共 **20种物品**：

| 池子 | 图标 | 物品 |
|------|------|------|
| 水果 (Fruit) | 🍎 | 西瓜🍉、柠檬🍋、芒果🥭、苹果🍎 |
| 药物 (Medicine) | 💊 | 冲剂🍵、滴眼液💧、注射器💉、胶囊💊 |
| 文具 (Stationery) | ✏️ | 铅笔✏️、橡皮🧼、订书机📎、笔记本📒 |
| 厨具 (Kitchenware) | 🍳 | 平底锅🍳、菜刀🔪、砧板🪵、汤勺🥄 |
| 电器 (Electronics) | ⚡️ | 手机📱、耳机🎧、空调❄️、电脑💻 |

> **总计**: 20 种不同的物品

### 物品品质 (Rarity)

物品有 **6个品质等级**（以下数值以 JSON 配置为准）：

| 品质 | ID | 回收金币 | 订单加成 | 颜色 |
|------|-----|----------|----------|------|
| 普通 (Common) | common | 0 | +0% | 灰色 |
| 优秀 (Uncommon) | uncommon | 0 | +10% | 绿色 |
| 稀有 (Rare) | rare | 1 | +25% | 蓝色 |
| 史诗 (Epic) | epic | 2 | +50% | 紫色 |
| 传说 (Legendary) | legendary | 4 | +100% | 橙色 |
| 神话 (Mythic) | mythic | 10 | +200% | 红色 |

### 物品属性

每个物品实例具有以下属性：

- **item_data**: 物品静态数据（名称、池子ID、图标）
- **rarity**: 品质等级对象（含 id、bonus、recycleValue 等）
- **sterile**: 绝育标记（无法参与合成）
- **uid**: 唯一标识符

### 物品合成

两个 **相同名称** 且 **相同品质** 的物品可以合成为一个 **品质+1** 的物品。

**合成规则**:
- 必须是相同名称的物品
- 必须是相同品质
- Mythic（神话）品质无法继续合成（已是最高级）
- 带有 `sterile` 标记的物品无法合成
- 合成后生成新的 uid

## 行列选取系统

> **当前状态：原型验证中。** 此系统替代矩阵框选系统 v2。

### 基本结构

- **矩阵大小**: 4×4（16个格子）
- 所有格子占 1 格
- 玩家选择一**行**或一**列**
- 从选中的行/列中**随机获取 1 个格子**
- 被取走的格子从矩阵中移除
- 上方格子因重力下落
- 顶部空位由随机新格子补充（三消式即时补充）
- **抽取本身无直接消耗**，但可能抽到厄运物品或触发厄运结算

### 格子类型

矩阵中的每个格子在生成时随机决定类型：

| 类型 | 效果 |
|------|------|
| 普通物品 | 获得该物品，放入背包 |
| 厄运物品：危险 (Danger) | 抽到时加入厄运网格（增加厄运网格中"危险"格子数量） |
| 炸弹 💣 | 消除周围 8 格（不获得任何物品），所有受影响列执行重力补充 |
| 厄运触发 (Doom Trigger) | 网格刷新时有 **10%** 概率出现，出现后**立刻消失**并触发一次厄运结算。初始不会出现；触发后进入冷却，不会立刻再次触发 |

> **已移除**: 金币陷阱已从当前原型中移除。炸弹保留。
>
> **生成概率**: 各类型的具体生成概率待测试后确定。

### 核心决策

玩家看到矩阵上所有格子的信息，选择一行或一列作为抽取范围。选择的依据包括：

- **目标物品**: 哪一行/列包含需要的物品
- **概率评估**: 行/列中有多少个想要的物品 vs 多少个厄运物品
- **厄运风险**: 选择含有厄运物品（危险）的行/列意味着有概率把危险加入厄运网格，增加未来威胁
- **重力预判**: 取走格子后的掉落会改变未来的行列组成
- **行列二重性**: 同一个目标物品可以通过它所在的行或列来接近，但附带的其他格子不同
- **撤离时机**: 厄运网格越来越危险，每次抽取都在"更多收获"与"更多风险"之间权衡

### 矩阵品质生成概率

普通物品格子的品质按以下权重随机决定（品质在矩阵上通过格子颜色可见）：

| 品质 | 权重 | 近似概率 |
|------|------|----------|
| Common | 0.37 | 37% |
| Uncommon | 0.30 | 30% |
| Rare | 0.20 | 20% |
| Epic | 0.10 | 10% |
| Legendary | 0.03 | 3% |
| Mythic | 0 | 0% |

## 背包系统

### 背包容量

- **默认容量**: 10格

### 操作模式

1. **整理模式**: 无待定物品时
   - 点击有物品的格子 → 选中该物品
   - 再次点击同一格子 → 取消选中
   - 点击另一个格子：
     - 空格 → 移动物品
     - 有物品且可合成 → 合成
     - 有物品但不可合成 → 交换位置

2. **放置模式**: 有待定物品时
   - 点击空格 → 放入物品
   - 点击有物品的格子：
     - 可合成 → 合成
     - 不可合成 → 回收原物品，放入新物品

### 待定队列

获得的物品会进入待定队列：
- 如果背包有空位且满足种类限制 → 自动飞入背包
- 如果背包满或违反种类限制 → 等待玩家手动选择替换

### 回收

> **待重新设计**: 回收系统原与金币经济绑定。金币系统已移除，回收机制需要重新设计。

### 订单槽位分配

玩家可以将背包中的物品预分配到订单的特定需求槽位：
- 选中背包物品后，点击订单需求槽位进行分配
- 已分配的物品会显示标记
- 幻影标记 (Phantom Marks) 会显示其他订单是否也需要同名物品

## 订单系统

> **设计方向调整**: 订单系统计划全部移至局外（meta-game 层）。抽取的物品需要被带出局内给局外使用。局内不再有订单。具体设计待定。以下内容为当前代码中的实现，仅供参考。

### 订单数量（当前实现）

- **普通订单**: 3个

### 普通订单生成

#### 需求数量

订单包含的物品需求数量：

| 需求数量 | 权重 | 近似概率 |
|----------|------|----------|
| 2物品 | 20 | 20% |
| 3物品 | 65 | 65% |
| 4物品 | 15 | 15% |

#### 需求品质

每个需求的品质通过 `orderRarityWeights` 随机决定：

| 品质 | 概率 |
|------|------|
| Common | 40% |
| Uncommon | 35% |
| Rare | 20% |
| Epic | 5% |
| Legendary | 0% |
| Mythic | 0% |

#### 订单奖励计算

**积分奖励**:
- `baseScoreReward` = 每个需求物品的品质积分权重之和 + progressOffset（默认为0）
- 积分品质权重:

| 品质 | 积分权重 |
|------|----------|
| Common | 2 |
| Uncommon | 2.5 |
| Rare | 4 |
| Epic | 8 |
| Legendary | 16 |
| Mythic | 32 |

- 例如：3物品订单要求 [Common, Uncommon, Rare]
  - baseScoreReward = floor(2 + 2.5 + 4 + 0) = 8，取 max(1, 8) = 8

**最终积分奖励** = ceil(baseScoreReward × multiplier)
- `multiplier` = 1 + 提交物品品质加成之和
- 如果技能"强迫症"触发（所有提交物品属于同一池子）：multiplier × 2

例如：提交 [Uncommon(+0.1), Rare(+0.25), Epic(+0.5)]
- multiplier = 1 + 0.1 + 0.25 + 0.5 = 1.85
- 最终积分 = ceil(3 × 1.85) = 6

### 订单刷新

- **初始刷新次数**: 3（JSON `global.initialRefreshCount` 值）
- **最大刷新次数**: 3（JSON `global.maxRefreshCount` 值）
- **刷新机制**: 消耗1次刷新机会，生成新订单替换被刷新的订单
- **完成订单恢复**: 每完成1个订单，刷新次数 +1

### 订单提交

1. 进入提交模式
2. 选择背包中的物品
3. 系统自动匹配所有可满足的订单
4. 提交成功 → 消耗物品，获得积分
5. 为每个完成的订单生成2个候选订单供选择
6. 触发相关技能效果

#### 关节技（物品共享规则）

同一次提交中，**普通订单之间**可以共享物品：一个物品如果同时满足多个普通订单的需求，则该物品会被计入所有这些订单的完成判定中。物品在提交结束后统一消耗，不会因被某个订单"占用"而对其他普通订单不可见。

### 订单候选选择

当订单完成后：
1. 系统为每个完成的订单槽位生成 **2个候选订单**
2. 玩家从2个候选中选择1个作为新订单
3. 多个订单同时完成时，候选选择按队列顺序依次进行

## 技能系统

> **当前状态：未启用。** 技能系统已在代码中完整实现，但当前版本尚未激活技能获取流程。部分技能效果与旧奖池/词缀系统绑定，需要重新设计。以下内容为设计规格参考。

### 技能获取

- 最多 **3个技能槽位**
- 技能通过积分进度触发选择事件获取
- 每次获取时从候选池中 **3选1**
- 技能一旦获得，持续整局游戏

### 技能列表

共有 **13个技能**：

---

#### 1. 贫困救济 (Poverty Relief)

**效果**: 金币 < 20 时，完成订单额外获得 **+5 金币**

**触发条件**: 订单完成时

---

#### 2. 幸运 7 (Lucky 7)

**效果**: 当前金币的尾数为 **7** ，或为 **7** 的倍数时，抽取传说物品的概率 **×2**

**示例**:
- 7 金币 → 触发
- 17 金币 → 触发（尾数7）
- 27 金币 → 触发（尾数7）
- 14 金币 → 触发

---

#### 3. 炼金术 (Alchemy)

**效果**: 回收 Rare 及以上品质物品时，**25%** 概率额外获得 **5 金币**

**触发条件**: 物品回收事件

---

#### 4. 贵宾折扣 (VIP Discount)

> **需重新设计**: 原效果与旧词缀系统绑定。

**原效果**: "精准"和"有的放矢"词缀的奖池金币消耗减少 **1**

---

#### 5. 谈判专家 (Negotiator)

**效果**: 抽到 **Epic** 或以上品质物品时，所有订单获得 **1次** 刷新次数

**触发条件**: 获得 Epic+ 物品

---

#### 6. 安慰奖 (Consolation Prize)

**效果**: 连续 **5次** 抽到 Common 品质物品后，下次必定 **Rare** 以上

**机制**:
1. 每抽到 Common → 计数+1
2. 抽到非 Common → 计数清零
3. 计数达到5 → 激活状态，下次保底 Rare+（从 Rare、Epic、Legendary、Mythic 中随机选择一个）

---

#### 7. 偷工减料 (Cut Corners)

**效果**: 刷新出新订单时，**20%** 概率使订单需求物品数量 **-1**（最低为1）

**触发条件**: 生成新普通订单时（不影响撤离订单）

---

#### 8. 时间冻结 (Time Freeze)

**效果**: 刷新单个订单时，**20%** 概率不消耗该订单的剩余刷新次数

**触发条件**: 单个订单刷新时

---

#### 9. 强迫症 (OCD)

**效果**: 提交的订单若所有物品属于 **同一种类（同一池子）**，积分奖励的乘数 **×2**

**示例**:
- 提交 [西瓜, 柠檬, 苹果]（均为水果池） → 触发 ×2
- 提交 [西瓜, 铅笔] → 不触发

---

#### 10. 自动补货 (Auto Restock)

**效果**: 完成任意订单后，下次抽取获得的物品会多获得 **1个**（复制第一个抽到的物品）

**机制**:
1. 完成订单 → 激活状态
2. 下次抽取时 → 额外获得1个物品
3. 获得物品后 → 消耗状态

---

#### 11. 时来运转 (Turn Fortune)

**效果**: 完成任意订单后，下次抽取获得的物品必定是 **Rare** 以上品质

**机制**:
1. 完成订单 → 激活状态
2. 下次抽取时 → 品质保底 Rare+（从允许的 Rare+ 品质中随机选择）
3. 获得物品后 → 消耗状态

---

#### 12. 大订单专家 (Big Order Expert)

**效果**: 完成需求物品数为 **4个** 的订单时，额外获得 **5 金币**

**触发条件**: 订单完成时，该订单有4个需求

---

#### 13. 困难订单专家 (Hard Order Expert)

**效果**: 完成需要 **Epic** 或以上品质物品的订单时，额外获得 **10 金币**

**触发条件**: 订单完成时，订单的需求中包含 Epic 或 Legendary 品质要求

## 厄运系统

> **当前状态：新方向，待原型验证。** 此系统替代旧的金币/陷阱/撤离订单系统，作为核心威胁机制。

厄运系统是游戏的核心压力来源，通过逐步升级的威胁迫使玩家在"继续搜刮"与"及时撤离"之间做出抉择。

### 厄运网格（Doom Grid）

一个独立于物品网格的小型网格，代表累积的厄运威胁。

| 配置项 | 值 |
|--------|-----|
| 格子总数 | 10 |
| 初始状态 | 1个"危险" + 9个空格 |

厄运网格中的格子有两种状态：
- **有内容**：包含一种厄运效果（当前仅"危险"）
- **空白**：无效果

### 厄运物品（Doom Items）

厄运物品作为特殊物品出现在物品网格上，与普通物品共存，对玩家可见。

当前唯一类型：

| 厄运物品 | 效果（在厄运网格中被命中时） |
|----------|-------------------------------|
| **危险 (Danger)** | 玩家 -1 生命值 |

玩家从物品网格抽到厄运物品时 → 该物品**加入厄运网格**（填入一个空格），使厄运网格变得更危险。

> **扩展性**: 未来可能加入具有不同效果的厄运物品类型（不限于扣血）。

### 厄运触发（Doom Trigger）

物品网格刷新时有概率出现"厄运触发"事件：

| 配置项 | 值 |
|--------|-----|
| 出现概率 | 10%（每次刷新） |
| 初始保护 | 游戏开始时不会触发 |
| 冷却 | 触发后不会立刻再次触发 |

厄运触发出现后**立刻消失**，并触发一次**厄运结算**。

### 厄运结算

触发时，一个框在厄运网格上移动并依次停下。每次停下结算该格子的效果：

- 停在**有内容的格子** → 触发该厄运效果（如"危险" → -1 生命值），计为一次**命中**
- 停在**空白格子** → 无事发生

每次结算停下的次数 = **厄运等级**。

### 厄运等级（Doom Level）

| 配置项 | 值 |
|--------|-----|
| 初始等级 | 1（每次结算停1格） |
| 升级条件 | 每累计命中 **3次**，等级+1 |
| 递增规则 | 可配置 |

### 双重升级节奏

厄运系统有两层加速，确保威胁持续上升：

1. **厄运网格变脏**：玩家抽到越多厄运物品 → 网格中有内容的格子越多 → 每次结算命中概率越高
2. **结算变狠**：厄运等级随命中次数提升 → 每次结算抽取更多格子 → 单次触发造成多次命中的概率上升

此外，如果玩家刻意回避厄运物品：厄运物品在物品网格上持续积累，导致网格中可抽取的普通物品占比下降，搜刮效率降低。

## 撤离

玩家**任何时候**都可以选择撤离，带走当前背包中的**全部物品**。

撤离无条件限制——核心张力来自厄运系统的逐步升级：留得越久能拿到越多物品，但厄运结算的危险性也在持续攀升。

### 游戏结束

| 条件 | 结果 |
|------|------|
| 主动撤离 | 带走背包全部物品 |
| 生命值归零 | 随机失去背包中一半物品，带着剩余撤离 |

## 积分与进度系统

### 积分计算

> **注意**: 订单系统计划移至局外，积分系统可能随之调整。以下为当前实现。

- `baseScoreReward` = Σ(每个需求物品品质的积分权重) + progressOffset
- `finalScoreReward` = ceil(baseScoreReward × multiplier)
  - `multiplier` = 1 + Σ(提交物品的品质加成)
  - 强迫症触发时：multiplier × 2

### 积分品质权重

| 品质 | 积分权重 |
|------|----------|
| Common | 2 |
| Uncommon | 2.5 |
| Rare | 4 |
| Epic | 8 |
| Legendary | 16 |
| Mythic | 32 |

### 积分进度

- **目标积分**: 无上限 (`targetProgress: null`)
- 积分累积推动游戏进度
- 积分进度可影响技能选择触发和难度调整

## 游戏流程

### 核心循环

```
┌─────────────────────────────────────┐
│           游戏开始                   │
│    生命值: 3, 背包: 10格            │
│    厄运网格: 1个危险 + 9个空格      │
│    厄运等级: 1                      │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│           核心循环                   │
│  1. 观察矩阵，选择一行或一列        │
│  2. 随机获取该行/列中的1个格子      │
│     - 普通物品 → 放入背包           │
│     - 厄运物品 → 加入厄运网格       │
│     - 炸弹 → 消除周围8格            │
│  3. 格子移除，重力掉落，顶部补充    │
│     - 刷新时10%概率触发厄运结算     │
│     - 厄运结算：在厄运网格抽取      │
│       （抽取次数=厄运等级）          │
│  4. 管理背包（整理、合成）          │
│  5. 随时可选择撤离                  │
│  6. 重复                           │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│    游戏结束条件：                    │
│    - 主动撤离（带走全部物品）       │
│    - 生命值归零（失去一半物品）     │
└─────────────────────────────────────┘
```

### 订单提交流程

```
┌─────────────────────────────────────┐
│        进入提交模式                  │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│      选择背包中的物品                │
│  高亮显示可满足的订单                │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│        确认提交                      │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│    验证所有选中物品                  │
│  - 每个物品必须被某订单需要          │
└─────────────┬───────────────────────┘
              │ 验证通过
              ▼
┌─────────────────────────────────────┐
│    计算每个订单的奖励                │
│  - 积分: baseScoreReward × 乘数     │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│    发放积分、消耗物品                │
│    每个完成的订单：                  │
│    - 刷新次数 +1                    │
│    - 生成2个候选订单供选择           │
└─────────────────────────────────────┘
```
