## 核心循环

```
[Day 1 开始]
   │
   ▼
随机刷 3 道菜（不可重刷），每道菜 3 槽。UI 在原货架区域长期展示
   │
   ▼
├─ 重复至多 12 次（= 12 小时） ────────────┐
│                                        │
│  从 5 店中随机刷 3 店 → 3 选 1 进入（-1h） │
│  店内 4×4 初始化，16 格全部刷新          │
│  ┌ 循环抽取 ───────────────────────┐    │
│  │ 系统摇 1 个词缀 → 显示           │    │
│  │ 玩家悬停选 2×2 → 按下抽取        │    │
│  │ 按词缀规则落一格 → 触发品质掷骰   │    │
│  │ 物品进临时篮 / 或抽到香蕉皮被踢   │    │
│  │ 被抽 2×2 整片重刷                │    │
│  │ 玩家可随时"离开店"按钮撤出       │    │
│  └─────────────────────────────────┘    │
│  安全撤离 → 临时篮并入冰箱               │
│  香蕉皮踢出 → 临时篮内容全损，冰箱安全    │
│                                        │
└────────────────────────────────────────┘
   │
   ▼
(12 小时耗尽后) 玩家仍可从冰箱往菜里放食材、调整、按"确定"做菜
   │
   ▼
玩家按"今日结束"按钮
   │
   ▼
未完成的菜每道 -2 满意度；已完成的菜按结算表 ±分
   │
   ▼
判定游戏是否结束（满意度 ≤ 0 → 失败）
```

## 食材系统（80 基础 × 4 品质）

### 分类结构

```
5 大类 × 4 小类/大类 × 4 品类/小类 = 80 个基础食材
```

每个基础食材有 **4 档品质** → 共 320 个食材实体（但 id 仍按 80 基础算，品质作为属性）。

### 5 大类（对应 5 家店）

| 大类 | 对应店 |
|------|------|
| 海鲜 | 海鲜市场 |
| 肉类 | 肉铺 |
| 蔬菜 | 蔬菜店 |
| 主食 | 粮食店 |
| 蛋奶 | 乳品店 |

### 小类/品类

每个大类下 4 个小类（与 `v2Config.js` 实际对齐）：

| 大类 | 小类 |
|------|------|
| 海鲜 | 鱼 / 虾 / 贝 / 蟹 |
| 肉类 | 鸡 / 牛 / 猪 / 羊 |
| 蔬菜 | 青菜 / 根茎 / 水果 / 菌菇 |
| 主食 | 米 / 面 / 豆 / 面包 |
| 蛋奶 | 蛋 / 奶 / 豆腐 / 奶酪 |

每个小类下 4 个品类（如"虾"小类下：河虾 / 基围虾 / 明虾 / 牡丹虾）。

### 食材数据结构

`INGREDIENTS` 在 `v2Config.js` 里已预生成 **320 条**（80 基础 × 4 品质），每条结构：

```
{
  id: "sea_bass_3",             // 品类_品质
  icon: "🐟",
  name: "优质鲈鱼",
  nameEn: "Premium Sea Bass",
  rarity: 3,                    // 1~4 已固化
  tags: ["海鲜", "鱼", "鲈鱼"], // [大类, 小类, 品类]
}
```

店内抽取时，格子上显示的是 **品类**（如"鲈鱼"，所有 4 种品质共享一个格位标识）；命中落点后按品质概率表 roll 1-4，查对应 id 的 INGREDIENTS 条目产出。

### 槽位匹配（基于 tags）

直接复用当前 `Kitchen.jsx:getSlotMatch` 的 `rules[]` 机制，槽位只需两条规则：

```js
rules: [
  { match: { tag: '鲈鱼' }, multiplier: 2 },   // 理想（品类名）→ ×2
  { match: { tag: '鱼' }, multiplier: 1 },     // 同小类     → ×1
],
defaultMultiplier: 0.5,                          // 其它       → ×0.5
```

### 品质概率（每次抽取默认）

| 品质 | 概率 |
|------|------|
| ★ 普通 | 45% |
| ★★ 优秀 | 30% |
| ★★★ 稀有 | 17.5% |
| ★★★★ 史诗 | 7.5% |

> 词缀可覆盖此表，见 [词缀系统](#词缀系统每抽必带)。

## 菜品系统（每日 3 菜随机生成）

### 每日生成

- Day 开始时随机生成 3 道菜（A / B / C），不起名字
- 3 道菜全天固定，**不可刷新、不可跳过**
- 玩家必须做这 3 道菜

### 菜品结构

每道菜：
```
{
  id,                  // Dish A / B / C
  baseline: 8,         // 初值 8（tentative）
  slots: [
    { idealIngredientId, subcategory, category },  // 槽 1
    { idealIngredientId, subcategory, category },  // 槽 2
    { idealIngredientId, subcategory, category },  // 槽 3
  ]
}
```

### 槽位生成算法

从 80 种基础食材中 **随机选 3 个彼此不同** 作为 3 槽的"理想食材"。每槽的中类 tag / 大类 tag 直接从该食材继承。

> 注：3 槽的理想食材可以来自同一大类（都是海鲜）也可以跨类，完全随机。

### 槽位匹配规则

| 放入食材 | 倍率 |
|---------|------|
| **就是该槽的理想食材**（baseId 匹配） | **×2** |
| 属于该槽的**同中类**（subcategory 匹配但 baseId 不同） | **×1** |
| 其它一切（不同中类，无论同大类或跨大类） | **×0.5** |

### 槽位 UI（展示在原货架区域）

每个槽位展示 **两个 tag**，**不展示倍率数字**：

```
┌─────────────────────┐
│   [食材图标 / 空]    │  ← 此处点击放入/取下
│                     │
│  #海鲜    #虾        │  ← 小标签：大类 + 中类(理想名)
└─────────────────────┘
```

> 示例："#海鲜 #基围虾"。玩家据此推导：放基围虾最好、放任何虾次之、放其它就是勉强。

## 店系统（5 店，3 选 1，1 小时/次）

### 每次进店流程

1. 系统从 5 家店中**随机选 3 家不重复**（每家店 20% 平权抽，取 3）
2. 玩家从 3 候选中选 1 进入
3. 消耗 1 小时（12 总小时 - 1）
4. 进入该店的 4×4 初始化界面

> **无旧 modifier 装饰**。店的唯一差别是食材大类不同。

### 店内 4×4 初始化

16 格独立 roll：

| 内容 | 概率 |
|------|------|
| 该店大类的某个随机基础食材（展示 baseId 名字，不展示品质） | 92.5% |
| 🍌 香蕉皮（可见图标，独占格位） | 7.5% |

食材从该大类的 16 个基础食材（4 小类 × 4 品类）中**均匀随机**抽取。

## 店内抽取（4×4，2×2 框选）

### 交互

1. 鼠标悬停在矩阵上 → 高亮显示即将抽取的 2×2 区域
2. 只能选完整落在 4×4 内的 2×2（九个可能位置：左上/中上/右上 × 上中下）
3. 按下鼠标 → 执行抽取

### 抽取基本规则

1. 先按**词缀规则**决定候选集合（见 [词缀系统](#词缀系统每抽必带)）
2. 选定"落点格" → 查看该格内容
   - 若是香蕉皮 → 触发**踢出事件**：弹出提示 / 动画 → 临时篮全部清空 → 返回店选择界面（仍扣刚才那 1 小时）
   - 若是食材 → 掷该食材的**品质**（按品质概率表）→ 包装为带品质的物品 → 进临时篮
3. **被抽的整个 2×2 刷新**（4 格独立重 roll，仍然每格 92.5%/7.5%）

### "离开店"按钮

- 店内界面**永远显示**"离开"按钮
- 点击 → 安全撤离 → 临时篮全部进冰箱 → 返回店选择界面

### 临时篮满处理

- 临时篮 10 格满时，继续抽取 → 弹出**替换/丢弃**决策（类似现在 pending item 流程，待 UI 细化）

## 词缀系统（每抽必带）

### 总则

- 每一抽**必有**一个词缀
- 词缀在玩家选 2×2 **之前**就已显示
- 抽完之后下一抽**重摇**一个新词缀
- 5 种词缀**等概率**（各 20%）

### 5 种词缀（精确规则）

| id | 名字 | 规则 | 品质处理 |
|----|------|------|---------|
| `precise` | 精准 | 系统从 2×2 的 4 格中随机选 2 作为候选，**向玩家展示两者的品质**，玩家从 2 选 1 | 候选 2 格品质**先摇好**再展示 |
| `targeted` | 有的放矢 | 玩家从 2×2 的 4 格中**自选 1 格**（点击指定） | 品质在抽取落定后才摇（不预览） |
| `fragmented` | 稀碎 | 从 2×2 中**独立随机 3 次**（有放回——可能撞同一格），得到 3 件物品 | 全部强制 ★ 普通 |
| `hardened` | 硬化 | 默认抽取（4 格均匀随机 1 格） | 品质权重改为：★:0 / ★★:60 / ★★★:30 / ★★★★:10 |
| `purified` | 提纯 | 默认抽取（4 格均匀随机 1 格） | 品质权重改为：★:0 / ★★:60 / ★★★:30 / ★★★★:10 （与硬化同效，保留两个名字作视觉差异） |

### 词缀与香蕉皮的交互

- **精准**：若候选 2 格中有香蕉皮，玩家看到了就可以避开（选另一格）。若 2 格都是香蕉皮，强制踢出
- **有的放矢**：玩家看得见香蕉皮在哪，可以指定食材格
- **稀碎**：3 次独立随机落点，任何一次落到香蕉皮 → 立即踢出（未发生的剩余抽取作废）
- **硬化 / 提纯**：默认随机落点，落到香蕉皮 → 踢出

### 词缀与品质覆盖

- **硬化 / 提纯**覆盖默认品质表
- **稀碎**覆盖为全 ★
- **精准 / 有的放矢**不覆盖品质表（用默认 45/30/17.5/7.5）

## 临时篮 & 冰箱

### 临时篮（店内）

- **容量**：10 格
- 本店内抽到的物品都进这里
- 安全撤离 → 全部并入冰箱
- 抽到香蕉皮 → **全部清空**（冰箱不受影响）

### 冰箱（全局，持续整天）

- **容量**：15 格
- 跨店持有，已进冰箱的物品不受后续店内香蕉皮影响
- 用来给菜品槽位填食材
- **不是**传统意义的"背包"——物品放进菜槽后仍在冰箱，直到玩家按"确定"结算菜品时才消耗
- 冰箱满时新物品进入 → 弹出替换/丢弃决策

## 做菜结算

### 槽位操作

- 玩家随时可以把冰箱里的食材放入任一菜的槽位
- 放入的食材**可以取下、可以替换**，直到玩家按菜旁的"确定"按钮
- 3 槽**必须全部填满**才能按"确定"（UI 上禁用按钮或提示）

### 确定 → 结算

按下"确定"那一刻：
1. 遍历 3 槽，每槽计分：`score = rarity × multiplier`（rarity ∈ [1,4]，multiplier ∈ {0.5, 1, 2}）
2. 3 槽求和 → `total`
3. 映射到评级：

| 条件 | 评级 | 满意度 Δ |
|------|------|---------|
| `total ≥ baseline × 2.5` | 惊艳 | **+2** |
| `total ≥ baseline × 1.8` | 优秀 | **+1** |
| `total ≥ baseline × 1.0` | 合格 | **0** |
| `total ≥ baseline × 0.5` | 勉强 | **-1** |
| `total < baseline × 0.5` | 翻车 | **-2** |

4. 3 槽食材从冰箱消耗
5. 该菜标记为"已完成"，无法再动

### 菜的 baseline 初值

- **baseline = 8**（tentative）
- 未来可在 `v2Config.js` 里调
- 数值理由：使"全理想 + 全 ★★★★ = 24"触达 2.5× baseline 的惊艳门槛

## 满意度与 Day 结束

### 满意度

| 项目 | 值 |
|------|------|
| 初始 | 5 |
| 上限 | 10 |
| 失败阈值 | ≤ 0 |

### 今日结束流程

玩家按"今日结束"按钮（任意时刻可按，但**12 小时用完后强制开启**）：

1. 扫描 3 道菜
   - 已完成：按之前确定时的评级应用 ±Δ
   - 未完成（不到 3 槽填满或未按确定）：**固定 -2**
2. 满意度 clamp 到 [0, 10]
3. 若满意度 ≤ 0 → 游戏失败
4. 否则 → 本草案范围结束（未来接入 Day 2 循环）

> 注：若玩家在 12 小时耗尽前就按"今日结束"，剩余小时作废、直接跳到结算。
