## 设计原则

1. **玩家长期目标 = 餐厅人气值**：每天做菜的评价 → 人气值涨跌；人气值归零 = 游戏失败。教程要把这个核心驱动在早期建立起来（见 `setting-current-state.md` 人气值系统），但不要在 Day 1 就让玩家真感受到人气值压力——先把机制讲明白。
2. **JIT 分层**：只把"不懂就卡死"的 P0 点塞进 Day 1 强制路径；其余 P1/P2 留到 Day 2+ 首次遇到时 tooltip 式解锁。
3. **叙事包裹机制**：每个教学点尽量用主角独白或 NPC 对白引出，避免纯系统提示堆叠。
4. **脚本化 ≠ 欺骗**：凡是需要"强制不抽到 X"的地方，要么让 X 根本不在墙上，要么让 X 显示在墙上但玩家抽取的行/列中的随机落点被预埋结果覆盖。后者用于营造"想抢但没抢到"的叙事张力。
5. **失败能重来**：教程阶段的失败都给软重置，不扣资源、不扣人气、不进 game_over。
6. **跟主游戏机制一致**：凡是能复用现有机制的（"挤出店铺"按钮、"回到餐厅"按钮、订单提交浮层）就直接复用，不做教程专属 UI。

## 第一部分 · 开场设定

### 1. 角色创建

- **玩家操作**：选角色 + 输入名字
- **约束**：立绘/性别不影响后续剧情，纯风味选择。母亲称呼统一为"**老妈**"

### 2. 背景叙事（静态演出 · 2~3 张卡片或文字渐显）

- 老妈是某家餐厅的主厨
- 在老妈的坚持和对料理的追求下，餐厅经营得蒸蒸日上，在美食界小有名气
- 玩家从小展现出对料理的天赋和兴趣，帮老妈打下手、跟她学烹饪

## 第三部分 · 新手教程

### 台词原则（适用于本章所有独白 / 对白）

主角人设：年轻的接班人，从小跟老妈学菜，有点底子但经验不足；努力装镇定，偶尔会慌。台词按以下原则写：

1. **口语优于书面**："放入到正确的位置" → "摆进去"、"按位置下"——不要用 UI 文案的句子
2. **一句一意**：每句台词只讲一件事；情绪长一点可以用省略号或破折号断开，不要挤到一句里
3. **自嘲胜于抱怨**：失败时说"哪儿不对味"，不说"系统错误"；收尾自嘲 > 叹气
4. **老妈要具体**：提到老妈尽量用动作场景（"做了多少遍"、"常念叨"），不要抽象（"教过我"）
5. **避免旁白主角**：主角不是系统；"请选择一行" 交给 UI coachmark，主角只在情绪节点说话
6. **NPC 生活感但不粗鲁**：老板/市场人群语气像真的忙得不耐烦，但不要脏话或戏剧化

下面各场景的台词均已按此原则首轮润色过；实装后可能再调。

### 场景 1 · 第一次厨房（教程专属菜 → 惊艳）


| 项        | 内容                                                                                                                                                                                                                                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **场景**   | 画面切到厨房                                                                                                                                                                                                                                                                                                                  |
| **主角独白** | "这道菜老妈做了多少遍，我闭着眼都记得料该怎么摆。——先开冰箱。"                                                                                                                                                                                                                                                                                       |
| **菜谱**   | **妈妈的家常汤面** 🍜（`moms_noodle_soup` · baseline 10 · 3 个 required 槽 · 无 trigger / crossBonus / exclude） ·槽位 1 · **面条**（default 0）：主食 ×0.5 / 面 ×1 / **挂面** ×2 ·槽位 2 · **主料**（default 0）：肉类 ×0.5 / 鸡 ×1 / **鸡胸肉** ×2 ·槽位 3 · **青菜**（default 0）：蔬菜 ×0.5 / 青菜 ×1 / **白菜** ×2 ·食材全部在 Day 2 正常市场中可再次获取（挂面→粮食店 / 鸡胸肉→肉铺 / 白菜→蔬菜店） |
| **冰箱预发** | 3 件全部 **Q4 顶级（紫色）**：挂面 Q4 / 鸡胸肉 Q4 / 白菜 Q4。每件都精确 id 命中对应槽位（×2 倍率）。叙事寓意："老妈教我做菜时用的都是最好的食材"                                                                                                                                                                                                                               |
| **玩家操作** | 将 3 件食材拖入对应槽位                                                                                                                                                                                                                                                                                                           |
| **目标**   | **必达"惊艳"**。精确命中计算：每槽 scoreValue 5 × ×2 倍率 = 10 分，3 槽共 **30 分**；baseline 10 × 2.5 = 25 → 30 ≥ 25 → **惊艳 ✓** ·任意一槽放错 → 该槽 0 分 → 总 ≤ 20 → 最高"优秀" → **fail**                                                                                                                                                                |
| **失败**   | 主角："嗯？……好像哪儿放错了。" → **全重置**（选项 A）：所有已放入槽位的食材回到冰箱原位，菜谱清空，玩家重试。不扣资源、不扣人气、不计失败次数                                                                                                                                                                                                                                           |
| **成功**   | 主角："……看吧，也没多难嘛。这家餐厅交给我，没问题。"                                                                                                                                                                                                                                                                                            |
| **教学点**  | **#7** 菜品结算基础（槽位匹配即得分）· 暂不讲大类/小类/id 倍率档，只让玩家感性体会"放对位置 = 好评价" · Q4 紫色也是玩家首次见到的"顶级"品质                                                                                                                                                                                                                                     |

### 场景 2 · 粮食店（核心抽取教学）


| 项                 | 内容                                                                                                                                                          |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **进店台词**          | 主角："这就是老妈常念叨的菜市场？——人怎么这么多。" 主角（冲店主喊）："老板！鸡蛋面有没有？今晚的海洋线条等着下锅呢！" 老板："自己找去！这边都忙不过来！"                                                                           |
| **墙面配置**          | 4×4 粮食店墙，手作 layout（见"脚本化资源清单 · 墙面 layout"）。**只开放 row 1 / col 1 抽取按钮**。鸡蛋面固定在 (1, 1)；该行与该列各 3 个挂面 + 相交点鸡蛋面                                                   |
| **玩家操作 A · 抽取**   | 系统引导玩家选"鸡蛋面所在的那一行或那一列"并抽取                                                                                                                                   |
| **脚本约束 A**        | 玩家在该行/列的 3 次抽取命中全部预埋： ·抽 1：挂面 Q1 ·抽 2：挂面 Q1 ·抽 3：挂面 Q2 **保证不抽到鸡蛋面**（即使行/列中有鸡蛋面的格子，随机落点跳过它）                                                                  |
| **设计意图**          | Q3 而不是 Q4 是**刻意的**：给玩家"将就感 / 妥协感"——想要鸡蛋面却抢到挂面；品质只到 Q3，离顶级紫还差一档。这份"够用但不够好"的情绪会在场景 7 用 Q3 食材做出"合格"海洋线条时再次回响。粮食店不让玩家尝到"合到 Q4 的爽感"，也是为了让 Day 2+ 真正合成到 Q4 时仍然有惊喜 |
| **教学点 A**         | **#3** 行/列抽取（选行或列 · 随机落点 · 3 抽/店 · 品质随机）                                                                                                                    |
| **玩家操作 B · 合成**   | 菜篮里首次出现 2 个 Q1 挂面 → 系统 JIT 指引："同 id 同品质可合成，点其中一格再点另一格" 玩家合成 → Q2 挂面。抽完 3 次后菜篮有 2 个 Q2 挂面，再合成 → **Q3 挂面**                                                    |
| **教学点 B**         | **#10** 合成机制（同 id 同品质 → 品质 +1）· **#8** 品质 5 档与 scoreValue 非线性跳档（1/2/3/5/8）                                                                                  |
| **玩家操作 C · 挤出店铺** | 3 抽用完后，系统引导玩家点右下"**挤出店铺**"按钮（`endTurn`）                                                                                                                     |
| **脚本约束 C**        | 进入 `resolveDoom('end_turn')` 人挤人结算： ·10 格 doom 网格**预埋只有 1 格 danger**（正常第 1 回合也是 1 格，此处只是强调） ·动画落点强制**命中 empty 格 → 闪避成功 → 扣 0 HP** ·目的：让玩家完整看到人挤人的结算形态，但不真扣血 |
| **教学点 C**         | **#4** 抢菜人 + 耐久度（只讲机制；耐久归零后果留到场景 6）                                                                                                                         |
| **离店**            | 主角："……抢个菜也这么费劲。"                                                                                                                                            |

### 场景 4 · 海鲜店（道具解锁 + 使用）


| 项                 | 内容                                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **进店即事件**         | 道具系统在此刻**首次解锁**：补发 **1 个道具——透视** + 弹 `ToolGrantPopup`（不是 3 个，见下方"为什么只发 1 个"）                                                               |
| **为什么只发 1 个**     | 避免玩家用驱散/换位"试图增加抽中明虾的概率"的心智陷阱。驱散和换位在教程脚本下都不会让明虾变得可抽——如果玩家试了却失败，会打破对工具的信任。透视不改变抽取结果、只揭示信息，叙事动机也最贴合（"看看明虾品质咋样"）。其它 4 种道具留给 Day 2+ 正常发放时遇到 JIT |
| **教学点 A**         | **#11** 道具基础用法（3 格栏 · 点击激活 · 激活后 ToolHintBar 指引 · 可取消）                                                                                     |
| **墙面配置**          | 4×4 海鲜店墙，手作 layout（见"脚本化资源清单 · 墙面 layout"）。**只开放 row 1 / col 1 抽取按钮**。明虾固定在 (1, 1)，其 row/col 序列为 `[基围虾, 明虾, 扇贝, 梭子蟹]`                      |
| **玩家操作 A · 使用透视** | 系统引导（软提示）玩家点透视 → 选 row 1 或 col 1 → 揭示该行/列所有食材品质。**明虾品质预 roll 锁定 Q5 传说橙色** → 最大化"看得到摸不到"的引诱感。若玩家跳过透视直接抽取，教程允许（透视概念已由 ToolGrantPopup 讲解覆盖）   |
| **玩家操作 B · 抽取**   | 3 抽结果全部预埋： ·抽 1：基围虾 Q3（= 教学里的"另一种虾"） ·抽 2：**订单消耗料 A**（暂定：扇贝 Q2） ·抽 3：**订单消耗料 B**（暂定：梭子蟹 Q2） **保证不抽到明虾**（同粮食店的处理逻辑）                         |
| **教学点 B**         | **#12** 道具 5 种效果——教程只覆盖 1/5（透视）；换位/驱散/炸墙/清库换抽留给 Day 2+ 首次获得时 JIT                                                                           |
| **挤出店铺**          | 同场景 2，脚本确保闪避成功（0 HP 扣除）                                                                                                                    |
| **离店**            | 主角："……一样都没抢到。这可怎么办啊。"                                                                                                                      |

### 场景 7 · 第二次厨房（海洋线条 → 合格）


| 项        | 内容                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **台词**   | 主角："……菜谱上要的料，一样都没买着。" 主角："手上这几样……就凑合着来一顿吧。"                                                                                                              |
| **菜谱**   | **海洋线条**（正式菜品 · 4 槽位：主料/基底/汤汁/配料）                                                                                                                        |
| **玩家手中** | Q3 挂面 + Q3 基围虾 + Q3 香菇（共 3 件）                                                                                                                            |
| **玩家操作** | 系统引导放入海洋线条槽位                                                                                                                                             |

- 屏幕底部，固定高度（约 `h-24`~`h-32`），`fixed bottom-4 inset-x-4` 左右留边

## 实装架构

### 状态机：线性 Step Controller

教程是严格线性序列（无分支、无并行），最简结构就够——索引驱动的 step 列表。

**新增 state（在 `useGameLogic` 里）**：

- `tutorialMode: boolean` — 整体开关；新游戏默认 `true`，跳过或自然走完后置 `false`
- `tutorialStepIndex: number` — 当前步索引（0 起）

**步骤序列（存于 `src/data/tutorialScript.js`）**：

```js
export const TUTORIAL_STEPS = [

  { id: 'scene_1_5_dishcard',    ... },  // Kitchen 切到海洋线条
  { id: 'scene_2_grainstore',    ... },  // 粮食店
  { id: 'scene_3_market_picker', ... },  // 3 选 1（精简版）
  { id: 'scene_4_seafood',       ... },  // 海鲜店 + 透视解锁
  { id: 'scene_5_bulletin',      ... },  // 交换区 + 固定订单
  { id: 'scene_6_evacuate',      ... },  // 撤离 + 耐久归零说明
  { id: 'scene_7_cooking',       ... },  // 海洋线条（任何评级通过）
  { id: 'day2_handoff',          ... },  // 人气值目标卡 + Day 2 启动
];
```

每步定义包含：`id` / `onEnter` / `onExit` / `completion`（判定完成的事件或 guard）/ `overrides`（见集成段）/ `narrative`（独白 / 对白 / 过场）。

**推进 API**：

- `advanceTutorial()` — `tutorialStepIndex++`；到末尾则 `tutorialMode = false`
- `skipTutorial()` — 见下方
- `isInStep(id)` — 便捷查询，供 UI 与 useGameLogic 内部分支用

### 跳过与重启语义

**跳过按钮**：右上角常驻"跳过教程"按钮，仅在 `tutorialMode = true` 时显示。

**点击流**：

1. 弹确认 modal："将跳过开场与新手教程，直接从第二天开始"
2. 确认后：`tutorialMode = false`（关所有脚本覆盖）
3. 拉 game state 到 Day 2 开局：`dayNumber = 2` · `dish = 海洋线条` · `popularity = 10` · `inventory = []` · 按正常 `TOOL_CONFIG.dayStartCount: 3` 发 3 道具
4. 进入正常 `pre_game / setup` 流程

**中途退出**：`tutorialMode` 与 `tutorialStepIndex` 均为 React state，不持久化。刷新页面自然回到初始值。**新游戏默认 `tutorialMode = true`**。

**后续若加"已玩过则默认跳过"**：用 `localStorage` 记录完成状态，启动时判断；本轮不实装。

### 集成：`tutorialOverrides` 派生对象

把所有脚本化覆盖集中到一个派生对象，现有 useGameLogic 内部函数在关键点加一行 guard：

```js
const tutorialOverrides = tutorialMode
  ? TUTORIAL_STEPS[tutorialStepIndex]?.overrides ?? null
  : null;
```

覆盖点：


| overrides 字段             | 影响函数                                   | 作用                                           |
| ------------------------ | -------------------------------------- | -------------------------------------------- |
| `wallLayout`             | `generateWall()`                       | 完整 4×4 格子定义，替代随机（详见墙面 layout 节）              |
| `selectableAxes[]`       | `ResourceMatrix` 的行/列按钮                | 只启用指定轴（如 `['row_1', 'col_1']`），其余按钮 disabled |
| `drawResults[]`          | `selectRow()` / `selectColumn()`       | 预埋命中序列，替代随机落点；命中时跳过受保护 cell（如鸡蛋面/明虾位）        |
| `peekQualityMap`         | 透视 apply 逻辑                            | 强制特定 cell 的预 roll 品质（如明虾锁 Q5）                |
| `safeDoomLanding`        | `resolveDoom()`                        | 强制 empty 格落点，HP 扣 0                          |
| `fixedOrder`             | `generateOrder()` / `incomingQueue` 触发 | 固定订单替代随机生成                                   |
| `toolsGranted`           | 道具发放时机                                 | 覆盖 `dayStartCount` / `perWallExitCount`      |
| `dish` / `fridgePreload` | `startGame()` / `startNextDay()`       | 锁定今日菜谱 + 预发食材                                |
| `hideBulletin`           | `BulletinBoard` render                 | 场景 3 首次市场界面屏蔽交换区                             |
| `disableUI[]`            | GameCore header                        | 教程期间隐藏 ⚙ / 🍳 / 📐 等 debug 入口                |


### 各场景完成条件总表

| ----------------------- | ----------------------------------------- | ---------------------------------------------------------------------- |
| `opening_narrative`     | 玩家点完 2~3 张叙事卡                             | 可快进单卡，不可跳过整段（整段跳过走 skipTutorial）                                       |

| `scene_6_evacuate`      | 耐久归零说明 modal 已展示过 + 玩家点"回到餐厅"按钮           | modal 必须先看完才允许点回到餐厅                                                    |
| `scene_7_cooking`       | Kitchen 完成做菜（**任何评级都通过**）                 | 玩家随意放置；评级按实际结算显示；教学重点是"看到分数"而非"做对"                                     |
| `day2_handoff`          | 玩家点完人气值目标卡 → 进入 Day 2 `pre_game`          | 目标卡必看完；之后正常 Day 循环接管，`tutorialMode` 自动设为 `false`                       |


### UI 层组件职责拆分

- `**TutorialStepController`**（GameCore 顶层，挂在 `useGameLogic` 之上）：订阅 `tutorialStepIndex` 变化，在 `onEnter` / `onExit` 时触发对应场景的独白、coachmark、过场动画
- `**TutorialSkipButton**`（header 右上常驻）：仅 `tutorialMode = true` 显示
- `**TutorialDialogBox**`（主角独白 / NPC 对白）：复用或扩展 Toast；长独白手动关闭
- `**TutorialCoachmark**`（指引箭头 + 高亮框）：通过 DOM ref 或 portal 定位到目标元素
- `**TutorialIntermission**`（过场卡 · 黑屏 + 字幕）：用于开场叙事、"【半小时后】"、人气值目标卡
