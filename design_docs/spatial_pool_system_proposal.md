# 空间奖池系统设计方案

> **状态**: 原型已实现，正在测试
> **日期**: 2026-03-21（基于 2026-03-20 分析对话）
> **来源**: 分析对话 — 从当前词缀/奖池系统的扩展性瓶颈出发，探索空间化方向

---

## 问题诊断

当前奖池系统的扩展瓶颈不在于词缀数量，而在于物品只有名字和品质两个属性，所有词缀本质上都在操纵同样的两个维度。第8个词缀和第7个在本质上没有区别。

## 核心变化

用 **物品地图 + 框选工具** 取代当前的 **物品类别 + 词缀奖池**。

**扩展性来源：**
- 地图布局成为独立于名字和品质的第三个设计旋钮
- 固定类别（水果/药物/文具/厨具/电器）被空间邻近关系取代，打包关系从静态变为动态
- 覆盖取舍（精度 vs 效率 vs 噪音）提供当前系统不存在的策略维度
- 框的属性继承词缀功能，品质操纵能力不丢失

## 当前实现规则

### 1. 物品地图

- 每次抽奖从 20 个物品中随机选取 **12 个**，排列在 **3×4 网格** 上
- 每抽重新生成（物品内容和位置都变化）
- 每个物品跨抽取有 **12/20 = 60%** 的等概率出场率
- 里程碑网格上高亮显示当前需要的物品及其品质要求

### 2. 框（抽取工具）

每次抽奖，系统随机生成 **3个框**，每个框包含：

| 属性 | 说明 |
|------|------|
| 形状 | 从形状库随机（含随机旋转） |
| 品质效果 | 从效果库随机，3框互不重复 |
| 费用 | 形状基础费 + 品质效果附加费 |

### 3. 形状库

| 形状 | 覆盖格数 | 基础费 |
|------|---------|--------|
| 单格 | 1 | 4 |
| 双格（横/竖） | 2 | 3 |
| 三连（横/竖） | 3 | 2 |
| L形（4旋转） | 3 | 2 |
| 方块 2×2 | 4 | 1 |
| T形（4旋转） | 4 | 1 |

基础费逻辑：覆盖格数越少 = 名字索引精度越高 = 越贵。

形状锚点始终在形状自身的一个格子上（非包围盒角落），确保鼠标位置一定在形状内部。

### 4. 品质效果与附加费

| 效果 | 品质规则 | 附加规则 | 附加费 |
|------|---------|---------|--------|
| 波动 | 90% Common / 10% Legendary | — | +0 |
| 稀碎 | 100% Common | 获得3个物品（可重复名称） | +0 |
| 以旧换新 | 同牺牲品(5%升1级) | 牺牲物品换不同名物品，绝育传递 | +0 |
| 硬化 | Rare+(67/30/3) | 物品绝育 | +1 |
| 精准 | 标准概率 | 抽2个不同名，选1个 | +1 |
| 提纯 | Rare+(67/30/3) | — | +2 |

**费用 = 形状基础费 + 品质效果附加费**

### 5. 生成约束

- **以旧换新** 仅出现在覆盖 ≥2 格的形状上
- **精准** 仅出现在覆盖 ≥2 格的形状上
- 1格形状仅可搭配：波动、稀碎、硬化、提纯

### 6. 抽奖流程

1. 玩家看到 3×4 物品地图 + 3 个可选框
2. 选择一个框
3. 在地图上移动放置（悬停预览高亮覆盖范围）
4. 点击确认 → 扣除金币
5. 按品质效果从覆盖物品中抽取
6. 物品进入待定队列/背包
7. 地图重新生成（新的12个物品）+ 3个框全部刷新

### 7. 被移除的元素

- **物品类别**（水果/药物/文具/厨具/电器）作为机制不再存在
- **"有的放矢"词缀**：被小形状的空间精确性取代

## 实现架构

采用 **虚拟池子** 方案：`handleMapPlace` 从空间覆盖构建一个池子形状的对象，传入现有 `handleDraw` 管线。所有技能逻辑、熵值处理、以旧换新/精准选择模式自动继承，无需并行逻辑。

### 关键文件

| 文件 | 职责 |
|------|------|
| `src/data/spatialConstants.js` | 形状定义、品质效果配置、费用计算 |
| `src/utils/spatialPoolHelpers.js` | 地图生成、框生成、形状旋转、覆盖计算 |
| `src/components/game/ItemMap.jsx` | 3×4 物品网格 + 放置交互 + 需求高亮 |
| `src/components/game/FrameSelector.jsx` | 3 个框选择卡片 + 形状预览 |

## 迭代历程

本系统经过多轮迭代才达到当前形态：

1. **5×4 全展示**：20 个物品全部可见，自由放置 → 信息过载，选择过多
2. **固定封闭模板**：关闭 2 行或边缘列 → 出场概率不均（25%–100%）
3. **随机封闭**：随机关 8 格 + 形状合法性验证 → 合法性难以保证
4. **3×4 每抽重生**（当前）：每抽从 20 中随机选 12 个排在 3×4 上 → 等概率、简洁、所有形状合法

核心学习：空间记忆（记住物品位置）在实际测试中不起作用，因此放弃固定布局、拥抱每抽变化是正确的简化。
