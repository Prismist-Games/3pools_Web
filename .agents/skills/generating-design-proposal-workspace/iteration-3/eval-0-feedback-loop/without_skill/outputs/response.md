# 反馈循环机制：具体设计方案

## 问题诊断

当前信息流是单向的：随机池 → 玩家抽取 → 库存管理 → 提交订单 → 积分。玩家的操作结果（完成了什么订单、回收了什么物品、选择了什么）不回流到世界状态。订单完成后唯一的后果是数字变化（积分+、金币+），世界本身没有任何改变。这意味着叙事层无处附着——没有"因为你做了X，世界发生了Y"的因果链。

以下方案都遵循一个约束：**叠加在现有核心循环（抽取→库存→提交）之上，不新增行动类型，不移除已有步骤。**

---

## 方案一：世界状态池（World State Pool）

### 核心思路

引入一个持久的"世界状态"层，由玩家的订单完成和物品处理行为持续塑造。世界状态反过来影响奖池的生成规则。

### 具体规则变更

1. **新增：世界状态变量**——维护一组隐性或显性的"世界参数"，例如按物品池分类的"供给指数"（水果供给、药物供给、文具供给、厨具供给、电器供给），初始值均为0。

2. **订单完成时更新世界状态**——每完成一个订单，该订单所涉及的物品池的供给指数 +1。例如完成一个需要[西瓜、铅笔、注射器]的订单，水果+1、文具+1、药物+1。

3. **回收物品时更新世界状态**——回收物品时，对应物品池的供给指数 -1（代表资源被浪费/从系统中流失）。

4. **世界状态影响奖池生成**——刷新奖池时，供给指数高的物品池出现概率降低，供给指数低的物品池出现概率升高。直觉：你大量供给了水果，市场上水果饱和，新的水果池子出现得更少了。

5. **世界状态影响订单生成**——供给指数高的物品池，对应的订单需求品质会提高（市场标准提高了）；供给指数低的物品池，可能出现高奖励的"稀缺订单"。

### 反馈循环

玩家专注某类物品 → 该类供给指数上升 → 该类奖池变少+订单要求变高 → 玩家被迫调整策略或接受更高难度 → 新的选择改变世界状态 → ...

### 叙事附着点

世界状态变化可以用叙事事件呈现："由于大量水果涌入市场，水果品质标准提高了"——玩家的行为产生了可感知的世界后果。

### 优点

- 实现简单，主要是在已有的订单完成和回收事件上挂钩子
- 自然产生长期策略维度（专精 vs 分散）
- 世界状态是渐变的，不会产生突变的负面体验

### 风险

- 如果参数调得太温和，玩家感知不到变化；太激进，会觉得被惩罚
- "供给指数"这个抽象概念需要设定层面的包装才能不显得机械

## 方案二：后果订单链（Consequence Order Chain）

### 核心思路

订单完成不是终点，而是起点——每个完成的订单有概率触发"后果订单"，后果订单的内容由之前完成的订单决定。形成"行为→后果→新行为"的链条。

### 具体规则变更

1. **新增：后果订单**——完成普通订单后，有一定概率（例如40%）在下一轮生成一个"后果订单"，替代某个普通订单槽位中的候选选项之一。

2. **后果订单的生成逻辑**——后果订单的需求与刚完成的订单相关但不同：
   - **同池扩展**：需求物品来自刚完成订单涉及的物品池，但品质要求更高。（"客户满意，追加了更高规格的订单"）
   - **跨池连锁**：需求物品来自刚完成订单未涉及的物品池，但奖励更高。（"你的交付引起了其他部门的关注"）
   - **修正订单**：需求与刚完成的订单部分重叠，但有一个需求被替换。（"上次的交付有点问题，需要补一批不同的"）

3. **后果订单的特殊性**——后果订单有视觉标记，奖励比普通订单高20-50%，但如果不完成（被刷新掉），会对世界产生轻微负面效果（例如下次后果订单出现的概率+10%，或者下次后果订单的品质要求+1级）。

4. **后果链深度**——后果订单本身被完成后，也可以触发新的后果订单，形成链条。连续完成后果链，每一环的奖励递增。链条断裂（刷新或超时）则重置。

### 反馈循环

完成订单 → 触发后果订单 → 选择接受或刷新 → 接受并完成 → 触发更深层后果 → ...
完成订单 → 触发后果订单 → 刷新掉 → 未来后果订单压力增加 → ...

### 叙事附着点

后果订单是玩家行为在世界中产生涟漪的直接体现。每个后果订单都可以携带一句叙事文本解释因果关系。

### 优点

- 直接在已有的订单系统上扩展，不需要新系统
- 每个后果订单都是一个微型叙事事件
- 后果链创造了"一个决定引出一连串后果"的体验，与不可逆主题高度契合

### 风险

- 后果订单的生成逻辑需要仔细平衡，避免雪球效应
- 如果后果订单太频繁，会压缩玩家的自由选择空间

## 方案三：剩余物品分配系统（Surplus Allocation）

### 核心思路

利用设定中已有的"部门"概念，让玩家在撤离/阶段结束时将剩余物品分配给不同部门。分配结果改变下一阶段的游戏条件。

### 具体规则变更

1. **新增：阶段结束分配环节**——每次撤离（或阶段转换）时，背包中的剩余物品不是简单消失，而是进入"分配界面"。玩家将物品分配给2-3个部门。

2. **部门需求与偏好**——每个部门偏好特定的物品池和品质等级。分配匹配度高的物品获得更多"关系点数"。

3. **关系点数的持久后果**——关系点数累积，影响下一阶段（或下一次撤离后的新局）的游戏条件：
   - **部门A（假设偏好高品质）**：关系好 → 订单奖励积分倍率+、但订单品质要求也+
   - **部门B（假设偏好大量普通物品）**：关系好 → 奖池刷新时多一个词缀选择、但急单难度+
   - **部门C（假设偏好特定物品池）**：关系好 → 特定物品池出现概率+、但其他池子-

4. **部门之间的张力**——给A的多了，B就觉得被忽视，关系自动下降。零和设计确保玩家必须做取舍。

5. **部门反馈**——分配后，每个部门给出简短反馈（1-2句），反馈内容基于累积关系和本次分配。这是叙事附着的主要位置。

### 反馈循环

游戏中的物品获取和使用 → 剩余物品的组成 → 分配选择 → 部门关系变化 → 下一阶段条件变化 → 影响游戏中的策略 → ...

### 叙事附着点

部门是"面对不确定性的不同心理姿态"的具象化（设定中已确认），分配行为让玩家直接与这些姿态互动。

### 优点

- 与设定文档中已确认的"部门"概念直接对接
- 剩余物品从"被忽视的废料"变成"有意义的选择"
- 创造了跨局/跨阶段的持久后果

### 风险

- 只在阶段结束时触发，反馈循环的频率太低，可能在游戏过程中感知不到
- 需要设计好部门的具体身份和偏好，工作量不小

## 方案四：奖池记忆系统（Pool Memory）

### 核心思路

奖池不再是无状态的随机源——它们"记住"玩家的行为，并据此改变自身属性。玩家从某个池子抽取越多，池子本身发生变化。

### 具体规则变更

1. **新增：池子抽取计数器**——每个物品池（水果、药物、文具、厨具、电器）维护一个全局抽取计数。

2. **抽取计数影响池子行为**——当某个物品池的抽取计数达到阈值时，触发池子变异：
   - **5次抽取**：该池子下次出现时，品质权重向两极偏移（Common和Legendary概率各+5%，中间品质-）。"这个池子被抽得多了，产出开始不稳定。"
   - **10次抽取**：该池子下次出现时，必定携带特定词缀（而非随机）。"池子的特性固化了。"
   - **15次抽取**：该池子产出一个"变异物品"——外观和名字略有不同，可以用于多个物品池的订单需求（跨池通用）。

3. **回收重置计数**——回收该池子的物品时，抽取计数-2。玩家可以通过主动回收来"冷却"过热的池子。

4. **订单完成影响所有池子**——完成订单时，订单中涉及的物品池计数-1（代表"需求被满足，压力释放"），未涉及的池子计数+1（代表"被忽视的领域积压了"）。

### 反馈循环

从某池大量抽取 → 池子变异 → 产出特性改变 → 玩家适应新特性或转向其他池子 → 其他池子也开始积累变化 → ...

### 叙事附着点

池子不是机器，是有反应的系统。大量抽取导致不稳定——这与"不确定性被放大"的设定直接呼应。

### 优点

- 反馈循环嵌入核心操作（每次抽取都在改变世界状态），感知频率最高
- 不需要新的UI界面，变化体现在已有的奖池展示中
- 池子变异创造了"你的选择塑造了你面对的世界"的体验

### 风险

- 计数阈值和变异效果需要大量平衡测试
- 如果变异效果太强，可能破坏游戏经济平衡

## 方案五：订单完成改变世界事件表（World Event Table）

### 核心思路

维护一张"世界事件表"，订单完成和关键物品操作往表中添加条目。事件表中的条目在特定时机触发，改变游戏规则的某些参数。事件是不可逆的。

### 具体规则变更

1. **新增：世界事件表**——一个可见的列表，最多容纳5-8个待触发事件。

2. **事件的产生**——以下行为向事件表中添加事件：
   - 完成订单：根据订单的物品池组合，添加对应事件。例如完成全水果订单 → 添加"丰收季"事件。
   - 回收Epic+物品：添加"资源浪费"事件。
   - 连续3次从同一池子抽取：添加"过度开采"事件。
   - 刷新订单：添加"市场波动"事件。

3. **事件的触发**——事件不立即生效。每个事件有一个"倒计时"（3-8回合），倒计时归零时触发。玩家能看到事件即将到来，但无法阻止。

4. **事件的效果**（不可逆，持续到游戏结束）：
   - **"丰收季"**：对应物品池的订单基础奖励-20%，但该池子出现概率+15%
   - **"资源浪费"**：所有回收价值永久-1（最低0）
   - **"过度开采"**：对应池子的Legendary概率归零，Common概率+对应量
   - **"市场波动"**：订单刷新次数上限-1，但每次刷新给出3个候选而非2个

5. **事件的叠加**——同类事件可以叠加，效果累积。这创造了螺旋：如果你一直做同样的事，世界朝同一个方向持续偏移。

### 反馈循环

玩家行为 → 事件进入事件表 → 倒计时中玩家能看到但不能阻止 → 事件触发改变规则 → 规则变化影响最优策略 → 新策略产生新事件 → ...

### 叙事附着点

事件表本身就是"世界因为你的行为正在改变"的直接可视化。倒计时创造了设定文档中提到的"延迟和不确定性带来的不安"——你知道后果要来了，但还得继续工作。

### 优点

- 延迟触发 + 不可逆 + 可见倒计时 = 完美匹配设定中"不安 = 不知道 + 影响大 + 可能负面"的公式
- 事件效果不可逆，与设定中"不可逆让不确定性有重量"直接对应
- 事件表是天然的叙事容器，每个事件都是一个微型世界变化
- 不修改核心操作流程，只在已有行为上挂钩子

### 风险

- 事件效果如果设计不当，可能累积成不可玩的状态（需要设计安全阀）
- 事件数量和种类需要足够多才能避免重复感

## 方案对比

| 维度 | 方案一：世界状态池 | 方案二：后果订单链 | 方案三：剩余物品分配 | 方案四：奖池记忆 | 方案五：世界事件表 |
|------|----------|----------|----------|----------|----------|
| 反馈频率 | 中（每次订单完成/回收） | 高（每次订单完成） | 低（仅阶段结束） | 高（每次抽取） | 中（行为产生事件，延迟触发） |
| 实现复杂度 | 低 | 中 | 中 | 中 | 高 |
| 叙事附着力 | 中（需要包装） | 高（每个后果订单即叙事） | 高（部门互动） | 中（池子变化需要解释） | 高（事件即叙事） |
| 与设定契合度 | 中 | 中 | 高（已有部门概念） | 中 | 高（不可逆+延迟+不安） |
| 不可逆程度 | 低（世界状态是渐变可回调的） | 中（链条断裂有后果） | 中（关系点数持久） | 中（池子变异可通过回收缓解） | 高（事件效果永久） |
| 改动现有系统程度 | 小（挂钩子+调生成权重） | 小（扩展订单生成逻辑） | 中（新增分配界面和部门系统） | 小（奖池生成逻辑扩展） | 中（新增事件表系统） |

## 建议

这些方案不互斥。如果要选一个先做原型验证，**方案二（后果订单链）**的实现成本最低、反馈最直接——只需要在现有订单完成逻辑上加一层后果订单生成规则，就能让玩家立刻感受到"我的行为产生了后果"。

如果要追求与设定文档中"不安"主题的最深契合，**方案五（世界事件表）**最值得投入——它的"延迟+不可逆+可预见但不可阻止"的结构，几乎就是设定文档中描述的不安感的机制化表达。

方案三（剩余物品分配）适合作为第二步——在反馈循环的基础机制验证后，引入部门系统来承载叙事和主题表达。
