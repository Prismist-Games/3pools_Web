# 池子个性化：问题分析与设计方向

## 问题诊断

你说得对，目前三个池子之间的差异化不够。看当前机制，三个池子的区分来自两个维度：

1. **物品池**（水果/药物/文具/厨具/电器）——决定你能抽到什么名字的东西
2. **词缀**（以旧换新/硬化/提纯/波动/稀碎/精准/有的放矢）——决定抽取的方式和品质分布

问题出在哪？物品池之间**功能完全等价**——水果和药物没有任何机制上的区别，只是名字和图标不同。玩家选池子时真正在看的只有词缀。而词缀虽然有7种，但它们的差异主要在"品质概率"和"交互方式"上，缺少与当前游戏状态的关联——无论你背包里有什么、订单要什么，词缀的价值评估方式基本不变。

所以玩家的决策退化成了：**看哪个词缀性价比高就抽哪个**，而不是"这个池子此刻对我最有价值"。

## 核心问题：选择缺少上下文依赖

好的选择感需要"此刻选A而非B的理由"。当前的理由太单薄——基本只有"我需要哪个池子的物品来完成订单"加上"哪个词缀更好"。

让选择有意义，需要让每个池子的价值**随游戏状态变化**。这意味着池子的个性不应该是静态的标签（"这个池子总是怎样怎样"），而是来自池子与当前局面的动态关系。

## 三个可能的方向

### 方向A：物品池本身有机制差异

最直接的思路。让不同物品池的物品具有不同的内在属性，而不只是名字不同。

**具体做法举例**：
- 某些物品池的物品合成成功率更高（或有额外效果）
- 不同池子的物品回收价值有差异——比如电器回收值高但合成难，水果回收值低但合成容易
- 某些池子的物品在特定订单类型中有加成

**优点**：直觉清晰，玩家很快能建立"水果=X策略，电器=Y策略"的心智模型。

**风险**：如果差异是固定的，玩家会快速算出最优池，反而减少选择空间。而且5个物品池都有独特机制，认知负担不小。另外，这个方向本质上是把差异硬编码在物品类别上——一旦玩家学会了，选择就变成查表而不是思考。

### 方向B：让池子的状态可变、有记忆

让每个池子不是每次刷新都从零开始，而是带有某种"状态"或"历史"，使得同一个池子在不同时刻的价值不同。

**具体做法举例**：
- **蓄能机制**：池子每次未被选中时积累一个buff（比如下次抽取品质提升、费用降低、或额外出一个物品）。被抽取后buff清零。这样玩家要权衡：现在抽这个我需要的池子，还是等它蓄满再抽？
- **耗尽/冷却**：连续从同一个池子抽取时，该池子的品质逐渐降低或费用逐渐升高。鼓励轮换。
- **连锁/combo**：连续从同一池子抽取有额外奖励（比如第二次抽同池时有小概率额外出物品），形成"专注一个池子"vs"均匀分配"的策略分歧。

**优点**：选择和时机紧密绑定。同一个池子在第1回合和第5回合的价值完全不同，每次决策都是新的。不增加物品层面的复杂度。

**风险**：如果蓄能太强，玩家会倾向于永远等最大蓄能，节奏变慢。需要仔细调参让"现在抽"和"等一等"都是合理选择。

### 方向C：池子之间产生关联

让三个池子不是独立的选项，而是存在某种互动关系——选了A会影响B和C。

**具体做法举例**：
- **跷跷板**：三个池子共享某种资源池。从一个池子抽取会让另外两个池子的某个属性变化（比如品质概率微调、费用变化）。
- **共振**：如果你这轮抽了水果池，下轮包含水果的池子有某种加成或减损。

**优点**：每次选择都有连锁后果，决策深度最高。

**风险**：太隐晦的关联玩家感知不到，太明显的关联计算量太大。对于轻中度策略游戏来说，这可能过于复杂。

## 我的判断

**方向B（池子状态可变）最值得优先尝试**，理由：

1. **和现有机制兼容**。词缀系统不需要改，物品系统不需要改。只是在池子层面加一层状态。
2. **选择感来自时机而非知识**。不是"学会了就知道该选什么"，而是每个瞬间都要根据当前三个池子的状态、自己的需求和金币来权衡。这正是"不确定性中的策略选择"。
3. **实现成本低**。蓄能值只是一个计数器，UI上在池子旁边显示一个指示就够了。原型验证很快。
4. **和主题契合**。池子的状态变化本身就是一种"无法完全控制的动态"——你可以选择等，但不确定等的过程中订单和急单会怎么变。

**具体建议的最小可验证版本**：

每个池子有一个"蓄能"值（0-3）。每回合刷新时，**未被抽取的池子**蓄能+1。蓄能效果：
- 0：正常
- 1：品质权重整体向上偏移一档（common权重减少，uncommon增加，依此类推）
- 2：品质偏移两档 + 费用-1（最低1）
- 3：品质偏移三档 + 费用-1 + 额外获得1个物品

抽取后该池子的蓄能归零。

这个版本足够简单，可以快速在Web原型里试玩，看"要不要等池子充能"这个决策点是否真的有趣。

---

方向A可以作为后续叠加的层——如果蓄能机制验证成功，再给不同物品池加轻量的机制差异（比如不同的蓄能速度或上限），可以进一步增加个性。但不建议一开始就同时做两层复杂度。
