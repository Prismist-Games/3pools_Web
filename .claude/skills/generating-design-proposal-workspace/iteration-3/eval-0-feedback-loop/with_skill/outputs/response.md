# 反馈循环机制方案

问题：玩家的订单完成和物品处理不产生世界层面的后果，信息流是单向的（随机->玩家->分数），叙事和机制脱节。

方向：让订单完成和物品处理改变世界状态，世界状态再影响玩家后续的游戏条件。

---

## 方案 A：订单完成改变池子状态

**想法**

玩家的时刻：你面前有一个水果池和一个文具池，水果池因为上回合你提交了大量水果订单而变得"疲惫"——它的高品质概率下降了。而文具池因为很久没被使用过，物品在"堆积"，高品质概率上升。你手里有一个需要水果的订单和一个需要文具的订单，两个都能做，但你选择先做文具订单，趁文具池还"丰满"的时候多抽几个好东西。

这解决反馈循环问题的方式很直接：订单完成消耗了某类物品 -> 这类物品对应的池子状态变化 -> 玩家后续从该池子抽取时条件不同。玩家的行为回流到了世界状态（池子），而不是只产出一个数字（分数）。

**规则变更**

每个物品池有一个隐藏的"存量"数值（初始值 100，范围 0-200）：

1. **[玩家提交订单时]** -> **[订单中每个物品的来源池存量 -15]** -> **[影响奖池系统的品质概率]**
2. **[每回合开始时]** -> **[所有物品池存量自动 +5（自然恢复）]** -> **[影响奖池系统]**
3. **[存量影响品质]** -> **[存量每低于100一个单位，Rare及以上品质概率按比例下降（最多降50%）；每高于100一个单位，按比例上升（最多升30%）]** -> **[影响抽奖结果]**

示例流程：
- 回合1：你连续提交了2个包含水果的订单（共消耗4个水果类物品），水果池存量从100降到40。
- 回合2：水果池出现时，Rare概率从20%降到约12%。你发现从水果池抽好东西变难了。
- 回合3-5：你转向其他池子，水果池每回合恢复+5，3回合后回到55，概率逐步回升。

**分析**

*核心假设*：玩家会注意到不同池子的"丰盈/枯竭"状态差异，并据此调整抽取和订单完成的优先级。如果玩家完全不关注池子状态就无脑抽，这个机制就是白加的数值噪音。

*风险*：如果数值调整太小，玩家感知不到差异，等于没有反馈；如果太大，玩家会觉得"我完成订单反而被惩罚了"，产生挫败感而非策略深度。窗口可能很窄。

*对已有乐趣的影响*：增加了一层需要关注的信息（池子状态），对当前"看订单需求->选池子抽"的决策增加了一个考量维度。不改变任何现有操作，但增加了认知负担。对于喜欢轻松抽卡的玩家，可能觉得多了个要操心的事。这个代价是否值得取决于"池子状态变化"能否产生真正有趣的决策——如果只是"等它恢复再抽"，那就不值得。

*最小实验*：给每个物品池加一个数字，提交订单时减、每回合加，让这个数字直接乘以 Rare+ 的概率。不需要UI，用 console.log 打印池子状态，玩5局看是否出现"我要避开这个池子"或"趁这个池子好的时候多抽"的决策。预计2-3小时。

## 方案 B：剩余物品分配产生部门关系变化

**想法**

玩家的时刻：你背包里有3个用不上的物品。回收它们能拿到2金币，但你也可以把它们"上交"给不同的部门。上交给研发部可以让下次出现"提纯的"词缀时费用-1，上交给仓储部可以让下次背包溢出时自动保留最高品质的物品而不是强制手动选择。你权衡：当前金币紧张，但下一轮可能刷出提纯词缀...

这解决反馈循环的方式是：物品不止有"提交订单"和"回收换金币"两个去处，第三个去处（分配给部门）产生持续性的世界后果。玩家的每次物品处理决策都在塑造后续的游戏环境。

**规则变更**

1. **[玩家在背包中选择不需要的物品时，除"回收"外新增"分配"选项]** -> **[物品被送往选定的部门，该部门的好感度+1（按品质加权：Common=1, Uncommon=2, Rare=3, Epic=5）]** -> **[影响部门提供的被动效果]**

2. **[部门好感度达到阈值时（如10/25/50）]** -> **[解锁或升级该部门的被动效果]** -> **[影响奖池词缀费用/背包管理/订单生成等具体系统]**

3. **[每次撤离重置时]** -> **[部门好感度保留一部分（如50%），不完全清零]** -> **[影响长期策略选择]**

示例流程：
- 你有2个多余的Rare文具物品，回收值共2金币。
- 你选择把它们分配给"质检部"（好感度+6），质检部好感达到10，解锁效果："精准的"词缀展示3个候选而非2个。
- 下次遇到精准词缀时，你有3选1而非2选1，选择空间明显变大。

**分析**

*核心假设*：玩家愿意放弃回收金币的即时收益，去换取部门效果的长期收益。如果金币太紧张导致玩家永远选回收，部门系统就是摆设。

*风险*：部门效果如果太强，变成"正确答案"（永远该给某个部门），失去选择意义；如果太弱，不值得放弃金币。另外，这实质上是新增了一个资源系统（部门好感度），增加了不少设计和平衡工作量。

*对已有乐趣的影响*：给"多余物品"增加了一个有意义的去处，这本身是正面的——当前多余物品只能回收换0-2金币，决策空间很小。但新增了一整套部门系统（部门身份、效果、阈值），这是显著的复杂度增加。对3人团队来说，这不是一个小改动。值得做的前提是：部门系统本身就是游戏想要的设定元素（从 setting 文档看，部门确实是计划中的设定方向），这个方案只是把它提前落地到机制里。

*最小实验*：先不做完整部门系统。只加一个按钮"分配物品"，物品消失，累计一个计数器，每累计5个物品，下一次抽奖Rare+概率翻倍（一次性）。测试的核心问题是：玩家是否会在"回收换金币"和"分配换未来好处"之间做出有意义的权衡。预计3-4小时。

## 方案 C：订单完成产生连锁订单变化

**想法**

玩家的时刻：你刚完成了一个全是水果的订单，结果新刷出的候选订单中，有一个明显更侧重水果类需求，而且给的分数更高。你意识到：如果你持续深耕水果路线，后续订单会越来越"认可"你的专精，给更好的回报。但另一方面，你的水果库存快用完了，而池子里不一定有水果池...

这解决反馈循环的方式是：订单完成的类型影响后续订单生成的分布。玩家的选择不只是"完成眼前的订单"，而是在塑造未来会出现什么样的订单。行为产生路径依赖。

**规则变更**

1. **[玩家完成订单时]** -> **[记录该订单中使用的物品池类型，对应池的"需求倾向"值+1]** -> **[影响后续订单生成]**
2. **[生成新订单的需求物品时]** -> **[物品的池来源不再均匀随机，而是按"需求倾向"加权：倾向值越高的池，越可能出现在新订单需求中]** -> **[影响订单系统]**
3. **[需求倾向值每3回合自然衰减-1（最低为0）]** -> **[防止极端集中，保持流动性]** -> **[影响订单系统]**

示例流程：
- 回合1-3：你完成了2个包含药物类物品的订单，药物池的"需求倾向"从0升到3。
- 回合4：新生成的候选订单中，有一个要求2个药物+1个文具。你发现药物相关的订单变多了。
- 回合7：你已经3回合没提交药物了，倾向值衰减到0，订单分布回到均匀。

**分析**

*核心假设*：玩家会感知到"我完成什么类型的订单，后续就倾向出现什么类型"这个规律，并主动利用它来规划路线。如果倾向变化太微妙，玩家根本注意不到。

*风险*：路径依赖可能导致"正反馈陷阱"——玩家专精某类物品，订单也越来越偏向该类，导致游戏体验变窄，失去三池选择的多样性。这和游戏核心乐趣（在3个不同池子间做策略选择）可能冲突。衰减机制能缓解但不能完全解决。

*对已有乐趣的影响*：这个方案的好处是几乎不增加新的操作或界面元素——玩家做的事和以前一样，但行为有了延伸后果。坏处是它可能削弱"三池之间的选择张力"——如果订单越来越集中在一个方向，其他两个池子就变得不重要了。游戏的核心身份是"3个池子之间的策略选择"，任何让选择空间变窄的机制都需要特别警惕。

*最小实验*：在订单生成逻辑中加一个加权数组（5个池子各一个数值，初始都是1），完成订单时对应池+0.5，每回合全部-0.1。生成新订单需求时用这个加权数组决定物品来源。不需要UI，只需要在生成订单时 console.log 输出当前倾向值，玩10局观察是否产生"路径"感。预计1-2小时。

## 方案 D：物品回收/提交改变词缀出现概率

**想法**

玩家的时刻：你注意到最近几回合你回收了很多低品质物品（因为背包满了），导致"稀碎的"词缀出现概率上升了——游戏好像在"回应"你大量处理廉价物品的行为。而你的队友（或另一局游戏里的你）如果一直提交高品质订单，"提纯的"和"有的放矢的"词缀会更频繁出现。你的操作风格在塑造你面对的词缀环境。

这解决反馈循环的方式是：玩家处理物品的方式（回收vs提交、低品质vs高品质）直接影响池子刷新时的词缀分布。世界在回应玩家的行为模式。

**规则变更**

1. **[玩家回收物品时]** -> **[记录回收物品的总品质值（Common=1, Uncommon=2...），累计到"回收计数器"]** -> **[影响词缀出现概率]**
2. **[玩家完成订单时]** -> **[记录提交物品的总品质值，累计到"完成计数器"]** -> **[影响词缀出现概率]**
3. **[刷新奖池词缀时]** -> **[根据两个计数器的比值调整词缀权重：回收多于提交时，低费词缀（稀碎、波动、以旧换新）概率上升；提交多于回收时，高费词缀（提纯、有的放矢、精准）概率上升]** -> **[影响奖池系统]**
4. **[每次撤离后]** -> **[计数器重置]** -> **[不影响跨局]**

示例流程：
- 你前5回合回收了8个物品（大部分Common），回收计数器=10，完成计数器=6（完成了1个订单）。
- 回收/完成比值 > 1.5，低费词缀权重 x1.3，高费词缀权重 x0.8。
- 你发现池子上出现"稀碎的"和"波动的"的频率变高了。如果你想看到"提纯的"，需要多完成订单、少回收。

**分析**

*核心假设*：玩家会把词缀变化和自己的行为关联起来（"我回收太多导致词缀变差了"），而不是归因于随机波动。这个关联必须足够明显，否则反馈循环不存在于玩家的感知中。

*风险*：如果玩家感知不到词缀概率的变化（因为词缀本身就是随机的，样本量太小），这个系统等于透明的——花了开发时间但玩家不知道。另一个风险是"惩罚回收"的感觉：回收是当前玩家管理背包的重要手段，如果回收导致负面后果（词缀变差），玩家会觉得背包管理变得窒息。

*对已有乐趣的影响*：当前回收是一个轻松的操作——背包满了就回收低品质的，没有心理负担。这个方案给回收加了后果，可能让背包管理变得更焦虑。好处是让"保留还是回收"的决策有了更深的含义；坏处是增加了日常操作的心理成本。需要确保"回收多→低费词缀多"不是纯粹的惩罚——低费词缀本身也有用（稀碎给3个物品、波动有10%传说概率），所以这更像是"行为塑造环境的风格"而非"做错了被惩罚"。

*最小实验*：加两个全局计数器（回收品质总和、提交品质总和），每次刷新词缀时用比值乘以词缀权重。不需要UI，console.log 当前比值和调整后的权重。重点观察：玩家是否能感知到词缀分布的变化，以及回收时是否产生新的犹豫。预计1-2小时。

## 方案 E：订单完成触发世界事件

**想法**

玩家的时刻：你刚完成了一个高分订单（需要Epic品质物品），完成后弹出一个简短的事件："质检部注意到你最近提交的物品品质异常高，下达了新规定：未来2回合内，所有订单额外要求至少1个Uncommon以上品质的物品。"你的出色表现改变了游戏条件——不是奖励，也不完全是惩罚，而是世界对你行为的回应。

这解决反馈循环的方式最直接：完成订单->触发事件->事件改变游戏规则/条件->玩家在新条件下继续做决策。它不是数值层面的隐性调整，而是明确的、可感知的世界变化。

**规则变更**

1. **[玩家完成订单时]** -> **[根据订单类型（高分/低分、品质构成、物品池来源）从事件池中抽取一个事件]** -> **[影响全局游戏状态]**
2. **[事件生效]** -> **[持续N回合（每个事件独立设定），到期后自动解除]** -> **[临时影响具体系统（订单需求、词缀费用、品质概率、背包容量等）]**
3. **[同时最多存在2个活跃事件]** -> **[新事件触发时，如已满则替换最早的事件]** -> **[控制复杂度上限]**

事件示例（不是完整列表，只是说明"事件"具体意味着什么）：
- "仓库腾空"：完成3物品以上的订单后触发，背包容量临时+2，持续3回合。
- "价格波动"：完成包含稀有物品的订单后触发，所有词缀费用-1，持续2回合。
- "高标准期"：完成高分订单后触发，新生成的订单品质要求+1级，但积分奖励x1.5，持续3回合。

示例流程：
- 你完成了一个包含2个Rare物品的订单，触发"价格波动"事件，所有词缀费用-1持续2回合。
- 你趁费用降低的窗口，连续从"提纯的"池子抽取（费用从3降到2），获得了几个Rare+物品。
- 2回合后事件结束，费用恢复正常。

**分析**

*核心假设*：玩家会把事件和自己的行为关联起来（"我完成了高品质订单所以触发了这个"），并且觉得事件让游戏更有趣而非更烦。事件需要足够简单，一句话能说清楚效果。

*风险*：事件系统的平衡难度很高——每个事件都是一个独立的规则修改，事件之间的组合可能产生意外效果。对3人团队来说，设计、实现、测试一个事件池是不小的工作量。如果事件太频繁，玩家会觉得游戏规则一直在变，无法制定策略；如果太稀少，反馈循环太弱。

*对已有乐趣的影响*：这是所有方案中复杂度最高的。它新增了一整套系统（事件池、事件触发条件、事件效果、持续时间、同时存在上限）。好处是反馈最明确——玩家100%能感知到"我做了什么导致了什么变化"。坏处是游戏节奏可能变得不可预测（本来就有池子随机+订单随机，再加上事件随机），以及维护成本高（每个事件都需要单独平衡）。适合作为中长期目标而非快速验证。

*最小实验*：只实现2-3个最简单的事件（如"下2回合词缀费用-1"、"下2回合背包+2格"），完成任意订单时50%概率触发其中一个。用一个简单的文字提示显示当前活跃事件。预计3-4小时。重点观察：事件是让游戏更有趣（"哦这回合费用便宜了我要多抽"）还是更混乱（"又变了，我搞不清规则了"）。

## 方案比较

| 维度 | A（池子存量） | B（部门分配） | C（订单倾向） | D（词缀概率） | E（世界事件） |
|------|:---:|:---:|:---:|:---:|:---:|
| 能多快验证核心假设 | 2-3小时 | 3-4小时 | 1-2小时 | 1-2小时 | 3-4小时 |
| 做错了代价多大（可逆性） | 小，删一个数值即可 | 中，部门系统有连锁设计 | 小，改回均匀随机即可 | 小，删两个计数器即可 | 中，事件池需要整体移除 |
| 后续维护/平衡负担 | 低，一个数值曲线 | 高，部门+效果+阈值 | 低，一个衰减参数 | 低，一个比值公式 | 高，事件池持续扩展 |
| 能否与其他方案组合 | 可与C/D组合 | 独立系统，可与任何方案并存 | 可与A/D组合 | 可与A/C组合 | 可吸收A/C/D作为事件效果 |

**互斥关系**：没有方案是严格互斥的，但 A 和 D 都在调整"抽取结果的概率"，同时存在可能让系统变得不透明。E 可以把 A、C、D 的效果包装为具体事件，所以如果选 E，不需要单独做 A/C/D。

**组合建议**：
- **最小起步**：C（订单倾向）最快验证、改动最小、风险最低，适合第一个实验。
- **有野心的组合**：C + A（订单影响后续订单分布 + 提交消耗池子存量），两者影响不同系统（订单生成 vs 抽奖品质），不冲突。
- **长期方向**：B（部门系统）如果团队确认部门是核心设定元素，它不只是反馈循环，还是叙事载体。但它是最大的投入。
- **E 适合的时机**：等确认反馈循环确实能提升体验之后，E 可以作为"把多种小反馈统一成一个系统"的框架，不适合第一步。
