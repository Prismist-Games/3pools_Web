# 紧急订单系统改造方案

## 问题理解

当前紧急订单和普通订单在核心交互上几乎一致：都是"凑物品 → 提交"。紧急订单唯一的区别是15回合时限和不给积分。这导致它在体验上只是"有倒计时的普通订单"，缺乏独立的玩法身份。

以下方案从不同方向让紧急订单在玩法层面真正区别于普通订单。

---

## 方案 A：急单指定池子来源

**想法**

急单的每个需求不仅要求特定品质，还要求物品必须来自特定的奖池（比如"需要一个来自水果池的 Rare 物品"）。

玩家时刻：你手上有一个 Rare 铅笔（文具池），但急单要的是 Rare 水果池物品。你的普通订单刚好也要文具。你是把铅笔交给普通订单拿积分，然后抽水果池碰运气赶急单？还是先保住急单不超时，把铅笔用万象棱镜转成水果池不行——棱镜只能同池内转换。你必须真的去抽水果池。

这解决什么问题：当前急单只检查"物品名+品质"，玩家可以用手头任何满足条件的物品交差，和完成普通订单没有区别。加上池子来源限制后，急单会直接影响你"选哪个奖池抽"的决策——这正是这个游戏最核心的选择。急单从"背包里翻翻有没有"变成了"我必须主动去特定池子里找"。

**规则变更**

1. **[急单生成时]** → **[每个需求额外标注一个来源池子ID，需求显示为"XX池的YY品质物品"]** → **[影响急单生成逻辑和UI显示]**
2. **[玩家提交急单物品时]** → **[验证物品的pool_id是否匹配需求指定的池子]** → **[影响订单提交验证逻辑]**
3. 现有规则"急单需求物品必须来自不同池子"保持不变，进一步强化为：每个需求明确指定是哪个池子。

**示例**：
- 急单生成：需求1 = 水果池 Rare 物品，需求2 = 电器池 Uncommon 物品
- 当前3个奖池是：水果池（波动的）、药物池（精准的）、文具池（以旧换新的）
- 玩家看到水果池有波动词缀（90% Common / 10% Legendary），风险很大。但急单要水果池物品，不抽这个池子就没办法。玩家必须决定：花金币赌波动池，还是等下一轮刷新希望水果池换个词缀（但时限在倒计时）。

**分析**

- *核心假设*：这个方案成立的前提是——玩家在选择奖池时会注意急单的池子要求并据此调整抽取策略，而不是继续无视急单按自己节奏玩。鉴于急单超时 = 游戏结束（1点生命），这个压力应该足以驱动行为。
- *风险*：如果当前3个奖池恰好没有急单要求的池子，玩家会感觉"被卡住了"——只能等刷新，没有主动权。这种无力感可能令人沮丧。缓解方式：允许急单指定的池子在下次奖池刷新时有更高概率出现（比如保底至少1个急单需要的池子）。
- *对已有乐趣的影响*：不增加新系统，只在已有属性上加一层约束。核心的"3池选择"乐趣不会受损，反而多了一个考量维度。复杂度增加很小——玩家只需要多看一个信息（池子图标）。
- *最小实验*：在急单UI上hardcode显示"需要XX池物品"的文字标签，提交时加一行pool_id校验。不需要改生成逻辑（先手动指定测试）。预计1-2小时，验证的是"池子来源限制是否让急单决策变得不同"。

## 方案 B：急单完成奖励临时词缀加成

**想法**

完成急单后，玩家获得一个持续若干回合的奖池增益效果（比如"接下来3回合，所有池子抽取费用-1"或"接下来2回合，所有池子品质权重向上偏移一档"）。

玩家时刻：急单还剩4回合，你手上差一个 Rare 物品就能交。你可以现在花2回合去凑，完成后拿到3回合的费用减免，然后趁减免期间疯狂抽取为普通订单囤货。或者你可以先忽略急单、专注普通订单拿积分，但你就失去了这个增益窗口。急单从"不得不做的负担"变成了"值得主动追求的机会"。

这解决什么问题：当前急单不给积分，完成它纯粹是为了"不死"。玩家对急单的态度是被动防守。加上完成奖励后，急单成为"投入资源 → 获得临时优势 → 利用优势期加速"的主动策略选项。急单有了"存在感"是因为它在正向激励层面有了意义。

**规则变更**

1. **[玩家完成急单时]** → **[获得一个临时增益，持续N回合（N可配置，建议3回合）]** → **[影响奖池系统的费用或品质计算]**
2. **[增益生效期间每次抽奖时]** → **[应用增益效果（如费用-1或品质权重上移）]** → **[影响抽奖经济和品质分布]**
3. **[增益持续回合数耗尽时]** → **[自动移除增益]** → **[回归正常状态]**

**示例**：
- 回合7，玩家完成急单，获得"3回合内所有池子抽取费用-1"的增益
- 回合8：原本费用3的提纯池变成费用2，玩家可以更频繁地抽高品质物品
- 回合9：继续享受减免，集中抽取填充普通订单
- 回合10：增益结束，回到正常费用
- 玩家在3回合内多抽了2-3次，相当于额外获得了4-6金币的价值

**分析**

- *核心假设*：这个方案成立的前提是——玩家能感知到"完成急单→获得增益→利用增益"这条因果链，并且主动规划何时完成急单以最大化增益收益。如果玩家不会提前规划，增益就只是一个事后奖励，不会改变决策过程。
- *风险*：增益数值如果太强，玩家会把急单当作"必须尽快完成的buff触发器"，急单反而失去了时间压力的紧张感。如果太弱，感知不到差别。需要通过测试找到平衡点。另外，临时增益状态需要UI明确展示剩余回合数，否则玩家可能忘了自己有增益。
- *对已有乐趣的影响*：增加了一个临时状态变量和对应UI。对现有系统的改动集中在抽奖费用/品质计算处加一个条件判断。不会让任何现有操作变慢或变复杂。风险点在于：如果增益太好用，玩家可能会觉得没有增益的"正常状态"很无聊，产生依赖感。
- *最小实验*：最简版本——完成急单后，设一个flag + 剩余回合计数器，在计算抽奖费用时if flag则费用-1。UI上在奖池区域显示一个"优惠剩余X回合"的文字。预计2-3小时实现，验证的是"完成急单获得增益是否改变玩家对急单的态度——从被动应付变为主动追求"。

## 方案 C：急单物品锁定（提交前物品被占用）

**想法**

当玩家把物品分配给急单的某个需求槽位时，该物品立刻从背包中"锁定"——它仍然可见，但不能用于普通订单提交、不能合成、不能回收。只有取消分配或提交急单后才解锁。

玩家时刻：你有一个 Rare 芒果，急单需要它，普通订单也需要它。如果你把它分配给急单，它就被锁住了，你的普通订单就少了一个可用物品，而且背包等于少了一格。你必须决定：先锁给急单确保不超时，还是先用它交普通订单拿积分、再另想办法凑急单？

这解决什么问题：当前物品分配给订单只是一个"预标记"，不会真正限制物品的使用。急单和普通订单共享同一个物品池，没有资源竞争的紧张感。锁定机制制造了真实的资源冲突——分配给急单的物品确实不能挪作他用，迫使玩家在急单和普通订单之间做出真正的取舍。

**规则变更**

1. **[玩家将物品分配到急单需求槽位时]** → **[该物品获得"锁定"状态，不可用于合成/回收/普通订单提交]** → **[影响背包系统、合成逻辑、订单提交逻辑]**
2. **[玩家取消急单物品分配时]** → **[物品解除锁定，恢复正常状态]** → **[影响背包系统]**
3. **[急单提交成功时]** → **[锁定的物品正常消耗]** → **[无额外影响]**

**示例**：
- 背包10格，已有8个物品，其中2个分配给急单并被锁定
- 实际可自由使用的物品只有6个，可用于合成和普通订单
- 玩家想合成两个 Common 芒果，但其中一个被锁给了急单
- 选择：取消急单分配来合成（但急单进度倒退），还是再抽一个芒果来合成（花金币和时间）

**分析**

- *核心假设*：这个方案成立的前提是——背包空间和物品在急单与普通订单之间的争夺足够频繁，让锁定机制真正产生决策压力。如果玩家的背包通常很宽裕、急单物品和普通订单物品很少重叠，锁定就没有实际影响。考虑到10格背包 + 3普通订单 + 2急单，空间确实紧张，重叠概率也不低。
- *风险*：锁定可能让玩家觉得急单"惩罚性太强"——不仅有时间压力，还要牺牲背包灵活性。如果玩家频繁需要反复分配/取消分配来调度物品，操作会变得繁琐。需要确保取消分配的操作足够顺畅（一键取消）。
- *对已有乐趣的影响*：这个方案直接限制了背包管理的灵活性，而背包管理（整理、合成、调度）是现有的核心乐趣之一。代价是明确的：玩家会因为锁定而失去一些自由度。收益是急单真正参与了资源博弈，不再是独立于核心循环之外的东西。这个取舍是否值得需要测试验证。
- *最小实验*：在物品对象上加一个 `lockedForEmergency` 布尔值。分配急单时设为 true，在合成/回收/普通订单提交的校验逻辑中检查这个值。UI上给锁定物品加一个小锁图标。预计2小时，验证的是"物品锁定是否让急单和普通订单之间产生有意义的资源竞争"。

## 方案 D：急单提供独占的物品需求类型

**想法**

急单的需求不再是"某品质的任意物品"，而是要求特定的物品名称（比如"需要一个 Rare 西瓜"和"需要一个 Uncommon 铅笔"）。普通订单保持现在的"任意物品+品质"需求不变。

玩家时刻：急单要一个 Rare 西瓜。你手上有 Rare 芒果（同为水果池），但不行，急单要的就是西瓜。你需要想办法弄到西瓜——直接抽水果池碰运气、用万象棱镜把芒果转成西瓜、还是用有的放矢词缀的池子直接选？每种方式成本不同。

这解决什么问题：当前急单和普通订单的需求结构一样（品质+任意物品），体验自然趋同。指定具体物品名后，急单需要玩家动用完全不同的策略——精确获取特定物品，而不是凑齐同品质的任意物品。工具物品（万象棱镜）和交互型词缀（有的放矢、精准）突然对急单有了特殊价值，这些系统获得了新的使用场景。

**规则变更**

1. **[急单生成时]** → **[每个需求指定具体的物品名称（如"西瓜"）+ 品质，而非只有品质]** → **[影响急单生成逻辑]**
2. **[急单提交验证时]** → **[检查物品名称是否完全匹配需求指定的名称，同时检查品质是否达标]** → **[影响订单提交验证逻辑]**
3. 物品名称从对应池子的4种物品中随机选取。已有规则"需求来自不同池子"保持不变。

**示例**：
- 急单生成：需求1 = Rare 西瓜（水果池），需求2 = Uncommon 铅笔（文具池）
- 玩家背包里有 Rare 芒果和 Uncommon 橡皮
- 芒果和西瓜同池但不同名，不满足。橡皮和铅笔同池但不同名，不满足
- 玩家选项：(1) 用万象棱镜把芒果变西瓜（消耗工具）；(2) 抽水果池碰运气抽到西瓜；(3) 等有的放矢词缀的水果池出现，直接选西瓜

**分析**

- *核心假设*：这个方案成立的前提是——"需要特定物品"和"需要任意同品质物品"在玩家体验中有显著不同。每个池子有4种物品，直接抽中特定物品的概率是25%，这已经是一个有意义的约束，但不至于太苛刻。万象棱镜的存在提供了确定性解法。
- *风险*：如果玩家频繁需要特定物品但抽不到，同时手上没有万象棱镜，会感觉急单"不可控"。这与急单的时限压力叠加可能导致挫败感。缓解方式：保证万象棱镜的掉落率在急单活跃时足够（或者考虑急单完成后必定掉落一个万象棱镜）。
- *对已有乐趣的影响*：不增加新的系统概念，只是把需求从模糊变精确。工具物品和交互型词缀获得新用途，这是正面影响。核心的抽取-合成-提交循环不受影响。唯一的复杂度增加是：玩家需要记住急单要的具体物品名，但这只有2个需求，信息量很小。
- *最小实验*：修改急单生成函数，在选定池子后额外随机选一个具体物品名写入需求。提交验证加一行name匹配。急单UI的需求槽位显示具体物品图标+名称而非只显示品质。预计1-2小时，验证的是"指定具体物品是否让急单的备货策略区别于普通订单"。

## 方案 E：急单互斥提交（一次只能完成一个急单）

**想法**

当前2个急单可以在同一次提交中同时完成。改为：每次撤离提交只能完成其中1个急单，另一个急单的倒计时继续。完成的急单立刻生成新急单（难度+1）。

玩家时刻：两个急单都快到期了。急单A剩3回合，急单B剩5回合。你手上刚好两个都能交。但你只能交一个——你交A（更紧急），然后A的位置刷出一个新的更难的急单。现在你要应对B（剩4回合）和新急单（15回合）。你交的顺序、时机都有策略含义。

这解决什么问题：当前2个急单可以同时解决，玩家倾向于攒够物品一次性提交两个，急单系统变成了"集中爆发"而非"持续管理"。限制每次只能交一个后，玩家必须持续关注两个急单的时间差，安排提交节奏。急单从一个可以批量处理的任务变成了需要持续调度的压力源。

**规则变更**

1. **[玩家在撤离模式中提交急单时]** → **[每次提交操作只能选择1个急单完成，即使多个急单都满足条件]** → **[影响撤离模式的提交逻辑和UI]**
2. **[急单完成后]** → **[该槽位立刻生成新急单（难度+1），另一个急单倒计时继续不重置]** → **[影响急单刷新逻辑]**
3. 其他规则不变：完成后金币重置、生命值规则不变。

**示例**：
- 回合10：急单A（剩5回合）要 Rare+Uncommon，急单B（剩8回合）要 Rare+Rare
- 玩家两个都能交，但只能选一个
- 选择交A：A消失，新急单C生成（难度+1，15回合倒计时）。B倒计时继续（现在剩7回合）
- 回合11-17：玩家需要在B到期前完成B，同时为C做准备

**分析**

- *核心假设*：这个方案成立的前提是——限制提交频率会让玩家对两个急单的管理产生有意义的先后顺序决策。如果玩家总是简单地"先交快到期的那个"，决策就退化成了机械执行。需要验证是否存在"交这个还是那个"的真正纠结时刻。
- *风险*：如果两个急单的到期时间经常非常接近，玩家可能陷入"无论怎么选都有一个要超时"的困境，体验很差。需要确保急单生成的时间错开足够多，或者给每次完成后一个短暂的"喘息期"。
- *对已有乐趣的影响*：这是最保守的方案——不增加任何新概念、新状态、新UI元素。只改变一个行为限制。对现有系统零侵入。唯一的代价是玩家失去了"一次搞定两个急单"的爽快感，但换来的是更持续的策略深度。
- *最小实验*：在撤离提交逻辑中加一个计数器，限制每次撤离最多完成1个急单。不需要改UI（多个可提交急单都高亮，但点击一个后立刻结算并退出提交模式）。预计30分钟-1小时，验证的是"限制每次交一个急单是否让急单管理的节奏感变得更独特"。

## 方案对比

| 维度 | A（指定池子来源） | B（完成奖励增益） | C（物品锁定） | D（指定物品名称） | E（互斥提交） |
|------|---|---|---|---|---|
| 能多快验证核心假设 | 1-2小时 | 2-3小时 | 2小时 | 1-2小时 | 30分钟-1小时 |
| 做错了代价多大（可逆性） | 很小，删掉pool_id校验即可 | 小，移除临时状态即可 | 中等，锁定逻辑涉及多处校验 | 很小，删掉name校验即可 | 很小，移除计数器限制即可 |
| 后续维护/平衡负担 | 低，只是一个过滤条件 | 中，需要持续调整增益数值 | 中，锁定状态需要与未来新系统兼容 | 低，只是需求多了一个字段 | 极低，纯逻辑限制 |
| 能否与其他方案组合 | 可与B/C/E组合 | 可与A/C/D/E组合 | 可与A/B/D/E组合 | 可与B/C/E组合，与A部分重叠 | 可与所有方案组合 |

**互斥关系**：A 和 D 有部分重叠——A要求来自特定池子，D要求特定物品名（隐含了池子）。同时用两者约束会过强，建议二选一，或合并为"指定具体物品名"（D已包含池子信息）。

**组合建议**：
- E + A 或 E + D：互斥提交提供节奏层面的独特感，加上需求约束提供策略层面的独特感，两者互补。
- B + E：完成奖励让急单有正向驱动力，互斥提交让完成时机成为策略选择，两者叠加让急单同时有"想做"和"怎么做"的深度。
- C 与任何方案组合都可以，但要注意叠加后的总体限制强度——锁定 + 指定物品 + 互斥提交三者全上可能让急单压力过大。
