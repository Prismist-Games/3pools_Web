## 分解：反馈循环需要满足什么条件？

洞察和方向都清楚了——当前信息流是单向的（随机 → 玩家 → 分数），需要让订单完成和物品处理产生世界层面的后果，后果再回流影响玩家面对的条件。

要让这个方向真正解决"叙事和机制脱节"的问题，以下条件需要同时成立：

### 条件

**1. 后果可见（visibility）**
玩家的行为（完成订单、回收物品、分配剩余物品）产生的世界变化，必须在后续游戏中以玩家能感知的方式呈现。如果后果只是后台数值变化，等于没有反馈。

**2. 后果改变决策空间（consequence）**
世界变化必须实际改变玩家接下来面对的条件——池子里出什么、订单要什么、词缀如何、经济参数如何，至少影响其中一个。如果后果只是装饰性的（比如换个背景图），机制和叙事仍然脱节。

**3. 行为和后果之间有可读的因果关系（legibility）**
玩家能大致理解"我做了X，所以世界变成了Y"。不需要精确预测，但因果方向要可读。否则后果和随机噪声无法区分，"我的行为影响了世界"的感受不成立。

**4. 后果不可逆（irreversibility）**
世界变化一旦发生就回不去。这是已确认的设计原则——可逆的后果没有重量。如果玩家可以撤销世界变化，反馈循环退化为又一个可优化的系统。

**5. 后果叠加在现有循环之上，不改变核心行动（compatibility）**
抽取 → 库存 → 提交 的核心循环保持不变。反馈循环通过改变这些行动的上下文（池子内容、订单条件、经济参数）来产生影响，而不是新增行动类型或移除已有步骤。这是死胡同"玩法改动太大"的边界。

### 依赖关系

- **consequence** 依赖 **visibility**：如果变化不可见，即使决策空间变了，玩家也感知不到。
- **legibility** 依赖 **consequence**：只有后果实际改变了什么，因果关系才有东西可读。
- **irreversibility** 独立于其他条件，但强化了所有条件的效果——不可逆让后果更可见、更有重量、因果关系更值得关注。
- **compatibility** 是硬约束，限制了其他条件的实现方式。

### 潜在冲突

**legibility vs. 主题中随机性的性质**：已确认随机性是"毫无道理地发生"的。但反馈循环要求因果可读。这意味着：反馈循环本身（玩家行为 → 世界后果）应该因果清晰，但世界后果叠加上池子本身的随机性后，最终结果仍然不完全可控。玩家能看到自己的行为塑造了世界的走向，但走向之上仍有不可预测的随机层。两者不矛盾，但设计时要注意不让因果可读性完全消解随机性的重量。
