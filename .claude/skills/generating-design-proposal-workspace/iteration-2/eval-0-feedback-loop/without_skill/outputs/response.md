# 反馈循环机制：具体方案

## 问题总结

当前信息流是单向的：随机池 → 玩家操作 → 积分。玩家的订单完成和物品处理不回流到世界状态，导致叙事和机制脱节。需要一个机制让玩家行为产生世界层面的后果，而世界变化再反过来影响玩家的池子、订单或环境条件。

以下方案都遵守设定文档中的约束：叠加在现有核心循环（抽取→库存→提交）之上，不新增行动类型也不移除已有步骤；惩罚对体验不负面；不可逆改变处境而非人。

---

## 方案一：世界状态轨道 (World State Tracks)

### 核心概念

引入2-3条可见的"世界状态轨道"，每条轨道代表世界的一个维度（具体名称取决于最终选定的设定方向，这里用抽象名暂代：比如"秩序度""紧张度""某种资源的丰裕度"）。轨道是一根数值条，有正负两个方向。

### 运作方式

1. **订单完成时**：根据提交的物品组合，推动某条轨道向某个方向移动。规则是确定性的、可预测的——比如"提交水果类订单 → 轨道A +1"，"提交电器类订单 → 轨道B +1"。玩家在提交前就能看到后果。
2. **世界状态改变池子条件**：轨道到达某些阈值时，改变奖池的生成规则。例如：轨道A高时，水果池出现概率上升但词缀偏向高成本；轨道B低时，新的词缀类型解锁。
3. **世界状态改变订单生成**：轨道位置影响新订单的生成权重。某条轨道偏高时，相关类型的订单变多且要求更高（世界"需要"更多这类东西）。
4. **不可逆性**：轨道的移动是不可逆的（或有衰减但极慢）。你早期的选择塑造了后期的游戏环境。

### 为什么解决问题

- 闭合了循环：玩家行为 → 世界状态变化 → 池子/订单条件变化 → 影响下一轮玩家行为
- 物品处理有了"世界后果"——提交什么不只是拿分，还在塑造游戏环境
- 产生了新的策略维度：我要不要为了短期分数提交这个订单，即使它会把轨道推向对我不利的方向？

### 与设定的契合

轨道可以直接映射到部门/群体的状态。不同部门关心不同的轨道，玩家的行为实际上在影响这些群体的处境。这为"不同人面对不确定性的态度"提供了具体的、可观察的后果。

### 风险

- 需要仔细平衡，避免出现"一条轨道永远最优"的情况
- 轨道的因果关系需要对玩家透明，否则感觉像隐藏惩罚

## 方案二：涟漪事件系统 (Ripple Events)

### 核心概念

每次订单完成或物品回收时，有一定概率（或确定性地）触发一个"涟漪事件"——世界对你行为的响应。涟漪事件是短暂但具体的世界变化，持续若干回合。

### 运作方式

1. **触发条件**：订单完成时，根据提交的物品类型+品质组合，从事件池中抽取一个涟漪事件。事件类型和触发物品之间有逻辑关系（不是纯随机）。
2. **涟漪效果举例**：
   - "市场短缺"：你提交了大量某类物品 → 接下来3回合该类物品的池子不会出现（世界"消化"了这批货）
   - "需求涌入"：完成了某个高品质订单 → 接下来出现的订单中该类物品需求增多（"做得好"反而意味着更多同类工作涌来）
   - "价格波动"：回收了大量物品 → 回收价值暂时提升或下降
   - "词缀偏移"：某种操作模式后 → 特定词缀出现概率变化
3. **可见性**：涟漪事件在触发时明确展示给玩家，包括持续时间和效果。当前活跃的涟漪在界面上有专门位置。
4. **累积效应**：多个涟漪可以叠加，产生非线性后果。

### 为什么解决问题

- 让每次订单完成变成"发生了一件事"——不只是加分，世界对此有反应
- 自然产生叙事：涟漪事件本身就是微型故事（"你做的事导致了什么"）
- 反馈循环是间接的和有延迟的——符合"不安来自等待"的设计原则

### 与设定的契合

涟漪事件可以被叙述为世界各方（部门/群体）对玩家行为的反应。不同"姿态"的群体对同一行为产生不同类型的涟漪，让玩家看到自己的行为在不同价值观中被如何解读。

### 风险

- 事件池需要足够大才不会重复
- 如果效果太弱，玩家感觉不到"世界在变化"；太强则感觉像随机惩罚

## 方案三：物品去向系统 (Item Destination System)

### 核心概念

扩展现有的"订单完成"和"物品回收"两个物品出口，加入第三个出口："分配给部门"。物品的最终去向直接塑造世界状态。

### 运作方式

1. **三个物品出口**：
   - **提交订单**：完成公司指标，获得积分（现有机制不变）
   - **回收**：换金币（现有机制不变）
   - **分配给部门**（新增）：将物品给某个部门，不获得即时奖励，但改变该部门的状态
2. **部门状态**：每个部门有一个可见的状态条。接受物品会推动其状态变化。
3. **部门状态的后果**：
   - 部门状态影响该部门提供的"被动条件"。例如：某部门状态高时，特定词缀出现更频繁；另一部门状态高时，订单品质要求整体下降。
   - 部门之间可能有互斥关系——给A部门物品可能削弱B部门的条件。
4. **不可逆**：给出去的物品回不来，部门状态的变化是永久的。这创造了一个持续的张力：物品是用来完成当前订单拿分，还是投资给部门换取长期环境优势？
5. **部门请求**（可选）：部门偶尔主动发出"请求"（类似订单但不是订单），提供它们想要的物品类型和承诺的条件改变。玩家选择是否响应。

### 为什么解决问题

- 直接利用了设定中已确认的"部门"概念，不需要引入新实体
- 每个物品都有了三重身份：订单素材 / 金币来源 / 世界塑造工具
- 反馈循环：玩家分配物品 → 部门状态变化 → 池子/订单/词缀条件变化 → 影响玩家获得什么物品
- 背包管理的张力大幅增加：10格背包里的每个物品都面对"给谁"的决策

### 与设定的契合

这是三个方案中与现有设定最直接契合的。部门已经被定义为"面对随机命运的不同心理姿态"的具象化，设定中也已经提到"剩余物品分配给不同部门获得perk"。这个方案把这条线从设定概念落地为核心机制。

### 风险

- 部门数量和互动关系需要控制复杂度
- 需要避免"最优分配策略"让部门选择变成数学优化题

## 方案四：环境衰变与修复 (Environment Drift)

### 核心概念

游戏世界有一个持续衰变的"环境状态"——某种条件在不断恶化（具体表现取决于设定方向）。玩家的订单完成和物品处理方式决定了衰变的速度和方向，以及能否修复。

### 运作方式

1. **环境基线**：游戏开始时环境处于中性状态。每过N回合，环境沿某个维度自然衰变。
2. **行为影响衰变方向**：
   - 完成高品质订单 → 减缓或逆转衰变
   - 大量回收物品（浪费） → 加速衰变
   - 特定物品类型的处理方式影响不同维度的衰变
3. **环境状态的具体效果**：
   - 环境好：词缀池更丰富，出现稀有词缀的概率高，订单奖励有加成
   - 环境差：某些物品池暂时不可用，词缀选项减少，急单频率上升
   - 环境极差：触发特殊事件（新的词缀类型出现、异常订单出现）
4. **关键设计**：衰变不是线性的。玩家可以在某些维度修复环境，但可能因此忽视其他维度。不存在"全部修好"的理想状态——这反映了"不确定性是被迫的基本条件"。

### 为什么解决问题

- 世界状态有了自己的生命——不只是玩家行为的结果，还有自身的趋势
- 玩家同时面对两个压力源：眼前的订单/急单 + 长期的环境管理
- 不可逆体现在：你无法回到游戏开始时的环境状态，只能在当前状态下做出最好的应对

### 与设定的契合

衰变本身就是"不确定性的后果持续累积"的具象化。环境不断变化、无法完全控制——这正是设定想表达的"被迫与不确定性共处"。

### 风险

- 衰变如果感觉太像惩罚（"环境在变差因为你不够好"），会落入"产生厌烦而非不安"的死胡同
- 需要确保衰变带来的是新决策空间，不是减少操作空间

## 方案比较

| 维度 | 方案一：世界轨道 | 方案二：涟漪事件 | 方案三：物品去向 | 方案四：环境衰变 |
|------|:---:|:---:|:---:|:---:|
| 与现有设定的契合度 | 中 | 中 | **高** | 中 |
| 实现复杂度 | 中 | 中低 | 中 | 中高 |
| 玩家可理解性 | 高（轨道可视） | 高（事件明确） | 高（去向明确） | 中（衰变间接） |
| 叙事空间 | 中 | **高** | **高** | 中 |
| 新决策深度 | 高 | 中（主要是后果） | **高** | 高 |
| 对核心循环的侵入性 | 低 | 低 | 中（新增出口） | 低 |
| 碰死胡同风险 | 低 | 低 | 低 | 中（"厌烦非不安"） |

## 建议

**方案三（物品去向系统）是最值得优先探索的**，原因：

1. 它直接利用了设定中已确认但尚未落地的"部门"和"剩余物品分配"概念，不需要引入完全新的设定实体
2. 它让每个物品多了一重身份（世界塑造工具），直接解决了"物品应该是情境的种子"这个设计目标
3. 反馈循环最清晰：物品→部门→条件变化→影响下轮物品
4. 它同时为叙事提供了着力点——部门对物品的反应、部门之间的张力、玩家在部门之间的立场——这些都是叙事可以自然生长的空间

**方案二（涟漪事件）可以作为补充层**叠加在方案三之上——部门对玩家行为的反应以涟漪事件的形式呈现，既提供反馈循环的具体手感，又增加叙事密度。

方案一和方案四的核心思路可以被吸收进方案三：轨道就是部门状态条，衰变可以是某些部门状态的自然趋势。不需要作为独立系统存在。
