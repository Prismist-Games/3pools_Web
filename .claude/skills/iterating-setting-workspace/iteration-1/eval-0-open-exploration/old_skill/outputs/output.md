# 订单代表什么？完成后有什么后果？

## 出发点

放松了"答案形状"的第一条约束后（不可逆不需要在获得物品时触发，可以通过游戏流程体现），游戏里已有的不可逆步骤浮出来了：订单提交。物品交出去就回不来。这个不可逆是现成的，问题是它在设定层面没有重量——目前订单只是"交东西换分数"，没有可见的、持久的后果。

所以问题是：订单在世界里代表什么，使得完成它会产生可见的、不可逆的处境变化？

## 方向

**订单来自不同的部门。完成订单 = 把资源交给那个部门。资源到手的部门会壮大，影响力增加。公司的权力格局、日常氛围、工作环境因此不可逆地改变。**

具体来说：

- 每个部门代表一种面对不确定性的哲学（已确认）。它们需要资源来运转——不是抽象的"影响力点数"，是具体的"我们部门需要这些东西来做事"。
- 玩家操作机器，产出物品，而可用的订单来自不同部门。完成谁的订单，谁就拿到资源。
- 拿到资源的部门壮大：人更多、占的空间更大、他们那套做事方式渗透到公司日常中。没拿到资源的部门萎缩或停滞。
- 这是不可逆的——你不能把已经交出的资源要回来，部门拿到资源后已经用了、已经长了。处境回不去。

## 为什么这能成立

逐条对照答案形状（调整后的版本，不可逆不要求在获得时触发）：

**不可逆通过游戏流程体现，不依赖获得瞬间。** 不可逆发生在提交订单时。机器产出 → 库存 → 提交给某个部门 → 那个部门壮大。整个流程是：不确定性（机器产出什么）→ 受限选择（手头物品能满足哪些订单）→ 不可逆后果（部门格局变了）。不确定性的重量是通过这条链传递的，不是在某一个瞬间附上的。

**变化对象是处境，不是人。** 变的是公司里哪个部门占主导、工作环境是什么样的。玩家自己没被改变。

**不需要额外解释"为什么"。** 给一个组织提供资源，它就会壮大——这是现实中任何组织都遵循的逻辑。不需要魔法，不需要新世界规则。

**影响显著到玩家能感知。** 部门格局的变化可以视觉化：空间占比、人员密度、环境氛围（更有序/更混乱/更紧张）。这是"视觉和机制表现，不靠文字"（设计原则3）的自然载体。

**不大改现有玩法。** 订单已经存在。唯一的区别是订单现在有来源（哪个部门发的），完成后有可见后果（那个部门变了）。核心循环不变：抽取 → 库存 → 提交。

**接地气。** 一家公司里不同部门争夺资源——完全日常。

## 这个方向里真正有意思的东西

有一个张力值得注意：

**玩家没有选择支持谁，但结果看起来像是选择了。**

机器产出什么是不确定的。手头的物品能满足哪些订单是受限的。在大多数情况下，玩家并不是"决定支持A部门"，而是"手头只有这些东西，能交的订单就这几个"。但一段时间后，看着公司的样子——某个部门占据了大半个办公区，他们那套理念渗透到每个角落——这看起来就像是玩家的选择。

这和主题直接相关。你在不确定性中做了一系列受限的决策，事后看起来像是你选了一条路。但你真的选了吗？如果机器当初产出了不同的东西，你现在会在一个完全不同的公司里工作。这个"what-if"不是来自"我当初应该换个分配方式"，而是来自"如果产出不同，一切都会不同"——正好对应已确认的设计原则7。

## 这个方向打开的后续问题

这些不是需要现在回答的，只是标记出来：

1. **部门壮大具体什么样？** "氛围变了"太抽象。需要具体的视觉和机制表现——是工位变多了？是背景音变了？是NPC的行为模式变了？这需要和"视觉表现优先"的原则一起想。

2. **负面可能在哪里？** 不安需要"可能负面"。如果某个部门过度壮大，会发生什么不好的事？不是灾难，但是让日子变得不太好过。比如：过度控制型的部门占主导 → 规矩越来越多，灵活性消失；过度放任型的部门占主导 → 混乱加剧，效率下降。这里需要和部门的具体哲学一起设计。

3. **和部门perk机制的关系。** 已确认"剩余物品分配给不同部门获得perk"。现在订单也来自部门。这两个系统是同一个系统（订单完成 = perk来源）还是两个不同的接口？需要理清。

4. **紧急订单在这个框架里是什么？** 普通订单是部门的日常需求。紧急订单呢？某个部门的紧急请求？外部压力？这可能和"不安"的另一层有关。

5. **和mystery的关系。** 搁置中有"mystery和主题之间的关系"。如果公司格局是玩家行为的累积后果，而玩家行为是被不确定性塑造的——那mystery可能和"看见这个过程"有关。但这是后面的问题。

## 需要检验的假设

这个方向建立在一个隐含假设上：**玩家在大多数时候没有足够的选择余地来"选择"支持哪个部门。** 如果玩家总是有多个可满足的订单可选，那"看起来像选择但不是"这个张力就不成立——它真的变成选择了。这需要对照实际的游戏机制验证：库存大小、订单数量、物品匹配的灵活度，这些参数决定了玩家的实际选择空间有多大。
